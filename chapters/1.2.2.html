1.2.2  
Tree Recursion
ツリー再帰

Another common pattern of computation is called tree recursion. As an example, consider computing the sequence of Fibonacci numbers, in which each number is the sum of the preceding two:
もう1つの一般的な計算パターンはツリー再帰と呼ばれます。例として、 フィボナッチ数列の計算を考えましょう。この数列では、各数はその前の2つの数の和です。
\[\begin{array}{l} 0, 1, 1, 2, 3, 5, 8, 13, 21, \ldots \end{array}\]
In general, the Fibonacci numbers can be defined by the rule
一般に、フィボナッチ数は次のルールで定義できます。
\[\begin{array}{lll} \textrm{Fib}(n) & = & \left\{ \begin{array}{ll} 0 & \mbox{if $n=0$}\\ 1 & \mbox{if $n=1$}\\ \textrm{Fib}(n-1)+\textrm{Fib}(n-2) & \mbox{otherwise} \end{array} \right. \end{array}\]
We can immediately translate this definition into a recursive function for computing Fibonacci numbers:
この定義は、フィボナッチ数を計算する再帰的な関数に直接変換できます。 
function fib(n) {
    return n === 0
           ? 0
           : n === 1
           ? 1
           : fib(n - 1) + fib(n - 2);
}

Consider the pattern of this computation. To compute fib(5), we compute fib(4) and fib(3). To compute fib(4), we compute fib(3) and fib(2). In general, the evolved process looks like a tree, as shown in figure 1.10. Notice that the branches split into two at each level (except at the bottom); this reflects the fact that the fib function calls itself twice each time it is invoked.
この計算のパターンを考えましょう。fib(5) を計算するには、fib(4) と fib(3) を計算します。fib(4) を計算するには、fib(3) と fib(2) を計算します。一般に、発展したプロセスは figure 1.10 に示すようにツリーのような形になります。（最下層を除いて）各レベルで枝が2つに分かれることに注目してください。これは fib 関数が呼び出されるたびに自身を2回呼び出すという事実を反映しています。

This function is instructive as a prototypical tree recursion, but it is a terrible way to compute Fibonacci numbers because it does so much redundant computation. Notice in figure 1.10 that the entire computation of fib(3)—almost half the work—is duplicated. In fact, it is not hard to show that the number of times the function will compute fib(1) or fib(0) (the number of leaves in the above tree, in general) is precisely $\textrm{Fib}(n+1)$. To get an idea of how bad this is, one can show that the value of $\textrm{Fib}(n)$ grows exponentially with $n$. More precisely (see exercise 1.13), $\textrm{Fib}(n)$ is the closest integer to $\phi^{n} /\sqrt{5}$, where
この関数はツリー再帰の典型例として教訓的ですが、冗長な計算が非常に多いため、フィボナッチ数を計算する方法としてはひどいものです。figure 1.10 を見ると、fib(3) の計算全体—ほぼ半分の作業—が重複していることがわかります。実際、この関数が fib(1) や fib(0) を計算する回数（一般に上のツリーの葉の数）がちょうど $\textrm{Fib}(n+1)$ であることを示すのは難しくありません。これがどれほどひどいかを把握するために、$\textrm{Fib}(n)$ の値は $n$ に対して指数的に増加することを示すことができます。より正確には（exercise 1.13を参照）、$\textrm{Fib}(n)$ は $\phi^{n} /\sqrt{5}$ に最も近い整数です。ここで
\[\begin{array}{lllll} \phi&=&(1+\sqrt{5})/2 & \approx & 1.6180 \end{array}\]
is the golden ratio, which satisfies the equation
は 黄金比であり、次の等式を満たします。
\[\begin{array}{lll} \phi^{2} &=&\phi + 1 \end{array}\]
Thus, the process uses a number of steps that grows exponentially with the input. On the other hand, the space required grows only linearly with the input, because we need keep track only of which nodes are above us in the tree at any point in the computation. In general, the number of steps required by a tree-recursive process will be proportional to the number of nodes in the tree, while the space required will be proportional to the maximum depth of the tree.
したがって、このプロセスは入力に対して指数的に増加するステップ数を使用します。一方、必要な空間は入力に対して線形にしか増加しません。なぜなら、計算のどの時点でも、ツリーの中で自分より上にあるノードだけを追跡すればよいからです。一般に、ツリー再帰的プロセスに必要なステップ数はツリーのノード数に比例し、必要な空間はツリーの最大深さに比例します。

We can also formulate an iterative process for computing the Fibonacci numbers. The idea is to use a pair of integers $a$ and $b$, initialized to $\textrm{Fib}(1)=1$ and $\textrm{Fib}(0)=0$, and to repeatedly apply the simultaneous transformations
フィボナッチ数を計算する反復的プロセスも定式化できます。アイデアは、$\textrm{Fib}(1)=1$ と $\textrm{Fib}(0)=0$ で初期化された整数のペア $a$ と $b$ を使い、次の同時変換を繰り返し適用することです。
\[\begin{array}{lll} a & \leftarrow & a+b \\ b & \leftarrow & a \end{array}\]
It is not hard to show that, after applying this transformation $n$ times, $a$ and $b$ will be equal, respectively, to $\textrm{Fib}(n+1)$ and $\textrm{Fib}(n)$. Thus, we can compute Fibonacci numbers iteratively using the function
この変換を $n$ 回適用した後、$a$ と $b$ がそれぞれ $\textrm{Fib}(n+1)$ と $\textrm{Fib}(n)$ に等しくなることを示すのは難しくありません。したがって、次の関数を使ってフィボナッチ数を反復的に計算できます。 
function fib(n) {
    return fib_iter(1, 0, n);
}
function fib_iter(a, b, count) {
    return count === 0
           ? b
           : fib_iter(a + b, a, count - 1);
}
This second method for computing $\textrm{Fib}(n)$ is a linear iteration. The difference in number of steps required by the two methods—one linear in $n$, one growing as fast as $\textrm{Fib}(n)$ itself—is enormous, even for small inputs.
$\textrm{Fib}(n)$ を計算するこの2番目の方法は線形反復です。2つの方法に必要なステップ数の違い—一方は $n$ に対して線形、もう一方は $\textrm{Fib}(n)$ 自体と同じ速さで増加—は、小さな入力に対してさえ膨大です。

One should not conclude from this that tree-recursive processes are useless. When we consider processes that operate on hierarchically structured data rather than numbers, we will find that tree recursion is a natural and powerful tool.
このことからツリー再帰的プロセスが無用だと結論づけるべきではありません。数値ではなく階層的に構造化されたデータを操作するプロセスを考えるとき、ツリー再帰は自然で強力なツールであることがわかります。
[1]
But even in numerical operations, tree-recursive processes can be useful in helping us to understand and design programs. For instance, although the first fib function is much less efficient than the second one, it is more straightforward, being little more than a translation into JavaScript of the definition of the Fibonacci sequence. To formulate the iterative algorithm required noticing that the computation could be recast as an iteration with three state variables.
数値演算においてさえ、ツリー再帰的プロセスはプログラムの理解と設計に役立ちます。たとえば、最初の fib 関数は2番目のものよりはるかに効率が悪いですが、フィボナッチ数列の定義を JavaScript に変換しただけのもので、よりわかりやすいものです。反復的アルゴリズムを定式化するには、計算を3つの状態変数による反復として書き換えられることに気づく必要がありました。

Example: Counting change

It takes only a bit of cleverness to come up with the iterative Fibonacci algorithm. In contrast, consider the following problem: How many different ways can we make change of $1.00 (100 cents), given half-dollars, quarters, dimes, nickels, and pennies (50 cents, 25 cents, 10 cents, 5 cents, and 1 cent, respectively)? More generally, can we write a function to compute the number of ways to change any given amount of money?
反復的なフィボナッチアルゴリズムを思いつくには、ちょっとした工夫が必要なだけです。それとは対照的に、次の問題を考えてみましょう。50セント硬貨、25セント硬貨、10セント硬貨、5セント硬貨、1セント硬貨を使って、$1.00（100セント）の両替をする方法は何通りあるでしょうか。より一般的に、任意の金額の両替方法の数を計算する関数を書くことはできるでしょうか。

This problem has a simple solution as a recursive function. Suppose we think of the types of coins available as arranged in some order. Then the following relation holds:
The number of ways to change amount $a$ using $n$ kinds of coins equals
  • the number of ways to change amount $a$ using all but the first kind of coin, plus
  • the number of ways to change amount $a-d$ using all $n$ kinds of coins, where $d$ is the denomination of the first kind of coin.
この問題は再帰的な関数として単純な解を持ちます。利用可能な硬貨の種類がある順序で並べられていると考えましょう。すると、次の関係が成り立ちます。
$n$ 種類の硬貨を使って金額 $a$ を両替する方法の数は、次の2つの和に等しい。
  • 最初の種類の硬貨を除くすべての硬貨を使って金額 $a$ を両替する方法の数
  • $n$ 種類すべての硬貨を使って金額 $a-d$ を両替する方法の数（ここで $d$ は最初の種類の硬貨の額面）

To see why this is true, observe that the ways to make change can be divided into two groups: those that do not use any of the first kind of coin, and those that do. Therefore, the total number of ways to make change for some amount is equal to the number of ways to make change for the amount without using any of the first kind of coin, plus the number of ways to make change assuming that we do use the first kind of coin. But the latter number is equal to the number of ways to make change for the amount that remains after using a coin of the first kind.
なぜこれが正しいかを理解するために、両替の方法は2つのグループに分けられることに注目してください。最初の種類の硬貨を1枚も使わないものと、使うものです。したがって、ある金額の両替方法の総数は、最初の種類の硬貨を使わずにその金額を両替する方法の数と、最初の種類の硬貨を使うと仮定した場合の両替方法の数の和に等しくなります。後者の数は、最初の種類の硬貨を1枚使った後に残る金額の両替方法の数に等しくなります。

Thus, we can recursively reduce the problem of changing a given amount to problems of changing smaller amounts or using fewer kinds of coins. Consider this reduction rule carefully, and convince yourself that we can use it to describe an algorithm if we specify the following degenerate cases:
このようにして、与えられた金額の両替問題を、より小さい金額の両替やより少ない種類の硬貨を使う問題に再帰的に帰着できます。この帰着規則をよく考え、次の退化した場合を指定すればアルゴリズムを記述できることを確かめてください。
[2]
  • If $a$ is exactly 0, we should count that as 1 way to make change.
  • If $a$ is less than 0, we should count that as 0 ways to make change.
  • If $n$ is 0, we should count that as 0 ways to make change.
We can easily translate this description into a recursive function:
  • $a$ がちょうど 0 なら、両替方法は 1 通りと数えます。
  • $a$ が 0 未満なら、両替方法は 0 通りと数えます。
  • $n$ が 0 なら、両替方法は 0 通りと数えます。
この記述は容易に再帰的な関数に変換できます。 
function count_change(amount) {
    return cc(amount, 5);
}

function cc(amount, kinds_of_coins) {
    return amount === 0
           ? 1
           : amount < 0 || kinds_of_coins === 0
           ? 0
           : cc(amount, kinds_of_coins - 1)
             +
             cc(amount - first_denomination(kinds_of_coins),
                kinds_of_coins);
}

function first_denomination(kinds_of_coins) {
    return kinds_of_coins === 1 ? 1
         : kinds_of_coins === 2 ? 5
         : kinds_of_coins === 3 ? 10
         : kinds_of_coins === 4 ? 25
         : kinds_of_coins === 5 ? 50
         : 0;   
}
(The first_denomination function takes as input the number of kinds of coins available and returns the denomination of the first kind. Here we are thinking of the coins as arranged in order from largest to smallest, but any order would do as well.) We can now answer our original question about changing a dollar:
（first_denomination 関数は、利用可能な硬貨の種類数を入力として受け取り、最初の種類の額面を返します。ここでは硬貨を大きい順に並べていますが、どの順序でも同様に機能します。） これで元の問い、1ドルの両替の方法の数に答えることができます。 
count_change(100);

The function count_change generates a tree-recursive process with redundancies similar to those in our first implementation of fib. On the other hand, it is not obvious how to design a better algorithm for computing the result, and we leave this problem as a challenge. The observation that a tree-recursive process may be highly inefficient but often easy to specify and understand has led people to propose that one could get the best of both worlds by designing a smart compiler that could transform tree-recursive functions into more efficient functions that compute the same result.

function pascal_triangle(row, index) {
    return index > row
           ? false
           : index === 1 || index===row
             ? 1
             : pascal_triangle(row - 1, index - 1)

Prove that $\textrm{Fib}(n)$ is the closest integer to $\phi^n/\sqrt{5}$, where $\phi= (1+\sqrt{5})/2$.

Hint: Use induction and the definition of the Fibonacci numbers to prove that $\textrm{Fib}(n)=(\phi^n-\psi^n)/\sqrt{5}$, where $\psi= (1-\sqrt{5})/2$.
ヒント: 帰納法とフィボナッチ数の定義を使って、$\textrm{Fib}(n)=(\phi^n-\psi^n)/\sqrt{5}$ を証明してください。ここで $\psi= (1-\sqrt{5})/2$ です。
First, we show that $\textrm{Fib}(n) = \dfrac{\phi^n-\psi^n}{\sqrt{5}}$, where $\psi = \dfrac{1-\sqrt{5}}{2}$ using strong induction.
$\textrm{Fib}(0) = 0$ and $\dfrac{\phi^0-\psi^0}{\sqrt{5}} = 0$
$\textrm{Fib}(1) = 1$ and $\dfrac{\phi^1-\psi^1}{\sqrt{5}} = \dfrac{\dfrac{1}{2}\left(1+\sqrt{5} - 1 + \sqrt{5}\right)}{\sqrt{5}} = 1$
So the statement is true for $n=0,1$. Given $n \geq 1$, assume the proposition to be true for $0, 1, \dots , n$.
$\textrm{Fib}(n+1) = \textrm{Fib}(n) + \textrm{Fib}(n-1) = \dfrac{\phi^n-\psi^n + \phi^{n-1} - \psi^{n-1}}{\sqrt{5}}$
$= \dfrac{\phi^{n-1}(\phi + 1) - \psi^{n-1}(\psi + 1)}{\sqrt{5}}$
$=\dfrac{\phi^{n-1}(\phi^2) - \psi^{n-1}(\psi^2)}{\sqrt{5}} = \dfrac{\phi^{n+1} - \psi^{n+1}}{\sqrt{5}}$, so the statement is true.
Notice that since $|\psi| < 1$ and $\sqrt{5} > 2$, one has $\left|\dfrac{\psi^n}{\sqrt{5}}\right| < \dfrac{1}{2}$
Then the integer closest to $\textrm{Fib}(n) + \dfrac{\psi^n}{\sqrt{5}} = \dfrac{\phi^n}{\sqrt{5}}$ is $\textrm{Fib}(n)$.
まず、強帰納法を使って $\textrm{Fib}(n) = \dfrac{\phi^n-\psi^n}{\sqrt{5}}$（ここで $\psi = \dfrac{1-\sqrt{5}}{2}$）を示します。
$\textrm{Fib}(0) = 0$ であり、$\dfrac{\phi^0-\psi^0}{\sqrt{5}} = 0$
$\textrm{Fib}(1) = 1$ であり、$\dfrac{\phi^1-\psi^1}{\sqrt{5}} = \dfrac{\dfrac{1}{2}\left(1+\sqrt{5} - 1 + \sqrt{5}\right)}{\sqrt{5}} = 1$
よって命題は $n=0,1$ で成り立ちます。$n \geq 1$ が与えられたとき、命題が $0, 1, \dots , n$ で成り立つと仮定します。
$\textrm{Fib}(n+1) = \textrm{Fib}(n) + \textrm{Fib}(n-1) = \dfrac{\phi^n-\psi^n + \phi^{n-1} - \psi^{n-1}}{\sqrt{5}}$
$= \dfrac{\phi^{n-1}(\phi + 1) - \psi^{n-1}(\psi + 1)}{\sqrt{5}}$
$=\dfrac{\phi^{n-1}(\phi^2) - \psi^{n-1}(\psi^2)}{\sqrt{5}} = \dfrac{\phi^{n+1} - \psi^{n+1}}{\sqrt{5}}$ なので、命題は成り立ちます。
$|\psi| < 1$ かつ $\sqrt{5} > 2$ なので、$\left|\dfrac{\psi^n}{\sqrt{5}}\right| < \dfrac{1}{2}$ となることに注目してください。
すると、$\textrm{Fib}(n) + \dfrac{\psi^n}{\sqrt{5}} = \dfrac{\phi^n}{\sqrt{5}}$ に最も近い整数は $\textrm{Fib}(n)$ です。

One approach to coping with redundant computations is to arrange matters so that we automatically construct a table of values as they are computed. Each time we are asked to apply the function to some argument, we first look to see if the value is already stored in the table, in which case we avoid performing the redundant computation. This strategy, known as tabulation or memoization, can be implemented in a straightforward way. Tabulation can sometimes be used to transform processes that require an exponential number of steps (such as count_change) into processes whose space and time requirements grow linearly with the input. See exercise 3.27.
