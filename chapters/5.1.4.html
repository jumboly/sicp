5.1.4  
Using a Stack to Implement Recursion
スタックを使った再帰の実装

With the ideas illustrated so far, we can implement any iterative process by specifying a register machine that has a register corresponding to each state variable of the process. The machine repeatedly executes a controller loop, changing the contents of the registers, until some termination condition is satisfied. At each point in the controller sequence, the state of the machine (representing the state of the iterative process) is completely determined by the contents of the registers (the values of the state variables).
これまでに示した考え方を使えば、あらゆる 反復的プロセスを、プロセスの各状態変数に対応するレジスタを持つレジスタマシンとして実装できます。マシンはコントローラのループを繰り返し実行し、何らかの終了条件が満たされるまでレジスタの内容を変更し続けます。コントローラ列の各時点で、マシンの状態（反復的プロセスの状態を表す）はレジスタの内容（状態変数の値）によって完全に決定されます。

Implementing recursive processes, however, requires an additional mechanism. Consider the following recursive method for computing factorials, which we first examined in section 1.2.1:
しかし、 再帰的プロセスの実装には追加のメカニズムが必要です。 1.2.1節で最初に見た、階乗を計算する次の再帰的な方法を考えてみましょう： 
function factorial(n) {
    return n === 1
           ? 1
           : n * factorial(n - 1);
}
As we see from the function, computing $n!$ requires computing $(n-1)!$. Our GCD machine, modeled on the function
この 関数 から分かるように、$n!$ の計算には $(n-1)!$ の計算が必要です。次の 関数 をモデルとした GCD マシンも、 
function gcd(a, b) {
    return b === 0 ? a : gcd(b, a % b);
}
similarly had to compute another GCD. But there is an important difference between the gcd function, which reduces the original computation to a new GCD computation, and factorial, which requires computing another factorial as a subproblem. In GCD, the answer to the new GCD computation is the answer to the original problem. To compute the next GCD, we simply place the new arguments in the input registers of the GCD machine and reuse the machine's data paths by executing the same controller sequence. When the machine is finished solving the final GCD problem, it has completed the entire computation.
同様に別の GCD を計算する必要がありました。しかし、gcd 関数 と factorial の間には重要な違いがあります。gcd は元の計算を新しい GCD の計算に帰着させますが、factorial は別の階乗計算をサブ問題として必要とします。GCD の場合、新しい GCD 計算の答えがそのまま元の問題の答えになります。次の GCD を計算するには、新しい引数を GCD マシンの入力レジスタに置き、同じコントローラ列を実行してマシンのデータパスを再利用するだけです。マシンが最後の GCD 問題を解き終えた時点で、計算全体が完了しています。

In the case of factorial (or any recursive process) the answer to the new factorial subproblem is not the answer to the original problem. The value obtained for $(n-1)!$ must be multiplied by $n$ to get the final answer. If we try to imitate the GCD design, and solve the factorial subproblem by decrementing the n register and rerunning the factorial machine, we will no longer have available the old value of n by which to multiply the result. We thus need a second factorial machine to work on the subproblem. This second factorial computation itself has a factorial subproblem, which requires a third factorial machine, and so on. Since each factorial machine contains another factorial machine within it, the total machine contains an infinite nest of similar machines and hence cannot be constructed from a fixed, finite number of parts.
階乗（または任意の再帰的プロセス）の場合、新しい階乗のサブ問題の答えは元の問題の答えではありません。$(n-1)!$ で得られた値に $n$ を掛けて最終的な答えを得る必要があります。GCD の設計を模倣して、n レジスタをデクリメントして階乗マシンを再実行することで階乗のサブ問題を解こうとすると、結果に掛けるべき n の古い値が使えなくなってしまいます。したがって、サブ問題を処理する2台目の階乗マシンが必要になります。この2回目の階乗計算にもまた階乗のサブ問題があり、3台目の階乗マシンが必要になり、以下同様に続きます。各階乗マシンの中に別の階乗マシンが含まれるため、マシン全体は同様のマシンの無限の入れ子になり、固定された有限個の部品からは構成できません。

Nevertheless, we can implement the factorial process as a register machine if we can arrange to use the same components for each nested instance of the machine. Specifically, the machine that computes $n!$ should use the same components to work on the subproblem of computing $(n-1)!$, on the subproblem for $(n-2)!$, and so on. This is plausible because, although the factorial process dictates that an unbounded number of copies of the same machine are needed to perform a computation, only one of these copies needs to be active at any given time. When the machine encounters a recursive subproblem, it can suspend work on the main problem, reuse the same physical parts to work on the subproblem, then continue the suspended computation.
それでも、マシンの入れ子の各インスタンスに同じコンポーネントを使う手配ができれば、階乗プロセスをレジスタマシンとして実装できます。具体的には、$n!$ を計算するマシンは、$(n-1)!$ の計算のサブ問題にも、$(n-2)!$ のサブ問題にも、同じコンポーネントを使うべきです。これが実現可能なのは、階乗プロセスでは計算を実行するのに同じマシンの無限個のコピーが必要だとしても、任意の時点でアクティブである必要があるのはそのうちの1つだけだからです。マシンが再帰的なサブ問題に遭遇した場合、メインの問題の作業を中断し、同じ物理的な部品を再利用してサブ問題に取り組み、その後中断していた計算を続行できます。

In the subproblem, the contents of the registers will be different than they were in the main problem. (In this case the n register is decremented.) In order to be able to continue the suspended computation, the machine must save the contents of any registers that will be needed after the subproblem is solved so that these can be restored to continue the suspended computation. In the case of factorial, we will save the old value of n, to be restored when we are finished computing the factorial of the decremented n register.
サブ問題では、レジスタの内容はメインの問題とは異なります（この場合、n レジスタがデクリメントされます）。中断した計算を続行できるようにするには、サブ問題が解かれた後に必要となるすべてのレジスタの内容を保存し、中断した計算の続行時に復元できるようにしなければなりません。階乗の場合、n の古い値を保存し、デクリメントした n レジスタの階乗の計算が終わったら復元します。
[1]

Since there is no a priori limit on the depth of nested recursive calls, we may need to save an arbitrary number of register values. These values must be restored in the reverse of the order in which they were saved, since in a nest of recursions the last subproblem to be entered is the first to be finished. This dictates the use of a stack, or last in, first out data structure, to save register values. We can extend the register-machine language to include a stack by adding two kinds of instructions: Values are placed on the stack using a save instruction and restored from the stack using a restore instruction. After a sequence of values has been saved on the stack, a sequence of restores will retrieve these values in reverse order.
入れ子の再帰呼び出しの深さにはアプリオリな制限がないため、任意の数のレジスタ値を保存する必要が生じる場合があります。これらの値は保存した順序の逆順で復元しなければなりません。再帰の入れ子では、最後に入ったサブ問題が最初に終了するからです。これは、レジスタ値を保存するためにスタック、すなわち後入れ先出し（last in, first out）データ構造を使うことを示唆しています。レジスタマシン言語を拡張してスタックを含めるには、2種類の命令を追加します。値をスタックに置く save 命令と、スタックから値を復元する restore 命令です。一連の値がスタックに save された後、一連の restore はこれらの値を逆順に取得します。
[2]

With the aid of the stack, we can reuse a single copy of the factorial machine's data paths for each factorial subproblem. There is a similar design issue in reusing the controller sequence that operates the data paths. To reexecute the factorial computation, the controller cannot simply loop back to the beginning, as with an iterative process, because after solving the $(n-1)!$ subproblem the machine must still multiply the result by $n$. The controller must suspend its computation of $n!$, solve the $(n-1)!$ subproblem, then continue its computation of $n!$. This view of the factorial computation suggests the use of the subroutine mechanism described in section 5.1.3, which has the controller use a continue register to transfer to the part of the sequence that solves a subproblem and then continue where it left off on the main problem. We can thus make a factorial subroutine that returns to the entry point stored in the continue register. Around each subroutine call, we save and restore continue just as we do the n register, since each level of the factorial computation will use the same continue register. That is, the factorial subroutine must put a new value in continue when it calls itself for a subproblem, but it will need the old value in order to return to the place that called it to solve a subproblem.
スタックの助けを借りて、階乗マシンのデータパスの単一のコピーを各階乗サブ問題に再利用できます。データパスを操作するコントローラ列の再利用にも同様の設計上の問題があります。階乗計算を再実行するために、コントローラは反復的プロセスのように単に先頭に戻ることはできません。$(n-1)!$ のサブ問題を解いた後、マシンはまだ結果に $n$ を掛ける必要があるからです。コントローラは $n!$ の計算を中断し、$(n-1)!$ のサブ問題を解き、そして $n!$ の計算を続行しなければなりません。この階乗計算の見方は、 5.1.3節で説明したサブルーチンメカニズムの使用を示唆しています。このメカニズムでは、コントローラは continue レジスタを使って、サブ問題を解く列の部分に移動し、その後メインの問題の中断箇所から続行します。こうして、continue レジスタに格納されたエントリポイントに戻る階乗サブルーチンを作ることができます。各サブルーチン呼び出しの前後で、n レジスタと同様に continue も save と restore します。階乗計算の各レベルが同じ continue レジスタを使うからです。つまり、階乗サブルーチンはサブ問題のために自身を呼び出すとき continue に新しい値を入れる必要がありますが、サブ問題を解くために自身を呼び出した場所に戻るには古い値が必要です。

Figure 5.13 shows the data paths and controller for a machine that implements the recursive factorial function. The machine has a stack and three registers, called n, val, and continue. To simplify the data-path diagram, we have not named the register-assignment buttons, only the stack-operation buttons (sc and sn to save registers, rc and rn to restore registers). To operate the machine, we put in register n the number whose factorial we wish to compute and start the machine. When the machine reaches fact_done, the computation is finished and the answer will be found in the val register. In the controller sequence, n and continue are saved before each recursive call and restored upon return from the call. Returning from a call is accomplished by branching to the location stored in continue. The register continue is initialized when the machine starts so that the last return will go to fact_done. The val register, which holds the result of the factorial computation, is not saved before the recursive call, because the old contents of val is not useful after the subroutine returns. Only the new value, which is the value produced by the subcomputation, is needed.
図 5.13 は、再帰的な factorial 関数 を実装するマシンのデータパスとコントローラを示しています。マシンにはスタックと、n、val、continue という3つのレジスタがあります。データパスの図を簡略化するため、レジスタ代入ボタンには名前を付けず、スタック操作ボタン（レジスタを保存する sc と sn、レジスタを復元する rc と rn）のみに名前を付けています。マシンを操作するには、階乗を計算したい数をレジスタ n に入れてマシンを開始します。マシンが fact_done に到達すると計算は終了し、答えは val レジスタに格納されています。コントローラ列では、各再帰呼び出しの前に n と continue が保存され、呼び出しからの復帰時に復元されます。呼び出しからの復帰は、continue に格納された場所への分岐で実現されます。 continue レジスタ はマシンの開始時に初期化され、最後の復帰が fact_done に行くようになっています。階乗計算の結果を保持する val レジスタは、再帰呼び出しの前に保存されません。サブルーチンが戻った後には val の古い内容は不要だからです。必要なのは、サブ計算によって生成された新しい値だけです。

Although in principle the factorial computation requires an infinite machine, the machine in figure 5.13 is actually finite except for the stack, which is potentially unbounded. Any particular physical implementation of a stack, however, will be of finite size, and this will limit the depth of recursive calls that can be handled by the machine. This implementation of factorial illustrates the general strategy for realizing recursive algorithms as ordinary register machines augmented by stacks. When a recursive subproblem is encountered, we save on the stack the registers whose current values will be required after the subproblem is solved, solve the recursive subproblem, then restore the saved registers and continue execution on the main problem. The continue register must always be saved. Whether there are other registers that need to be saved depends on the particular machine, since not all recursive computations need the original values of registers that are modified during solution of the subproblem (see exercise 5.4).
原理的には階乗計算は無限のマシンを必要としますが、 図 5.13 のマシンは、潜在的に無限となりうるスタックを除けば、実際には有限です。しかし、スタックの特定の物理的実装は有限のサイズになるため、マシンが扱える再帰呼び出しの深さが制限されます。この階乗の実装は、再帰的アルゴリズムをスタックで拡張した通常のレジスタマシンとして実現するための一般的な戦略を示しています。再帰的なサブ問題に遭遇したら、サブ問題が解かれた後に現在の値が必要になるレジスタをスタックに保存し、再帰的なサブ問題を解き、保存したレジスタを復元してメインの問題の実行を続行します。continue レジスタは常に保存しなければなりません。他にどのレジスタの保存が必要かは、特定のマシンに依存します。すべての再帰計算がサブ問題の解決中に変更されるレジスタの元の値を必要とするわけではないからです（練習問題 5.4を参照）。

A double recursion
二重再帰

Let us examine a more complex recursive process, the tree-recursive computation of the Fibonacci numbers, which we introduced in section 1.2.2:
より複雑な再帰的プロセス、すなわち 1.2.2節で紹介した フィボナッチ数のツリー再帰的計算を調べてみましょう： 
function fib(n) {
    return n === 0
           ? 0
           : n === 1
           ? 1
           : fib(n - 1) + fib(n - 2);
}
Just as with factorial, we can implement the recursive Fibonacci computation as a register machine with registers n, val, and continue. The machine is more complex than the one for factorial, because there are two places in the controller sequence where we need to perform recursive calls—once to compute Fib$(n-1)$ and once to compute Fib$(n-2)$. To set up for each of these calls, we save the registers whose values will be needed later, set the n register to the number whose Fib we need to compute recursively ($n-1$ or $n-2$), and assign to continue the entry point in the main sequence to which to return (afterfib_n_1 or afterfib_n_2, respectively). We then go to fib_loop. When we return from the recursive call, the answer is in val. Figure 5.15 shows the controller sequence for this machine.
階乗と同様に、再帰的なフィボナッチ計算を、レジスタ n、val、continue を持つレジスタマシンとして実装できます。このマシンは階乗のマシンより複雑です。コントローラ列の中で再帰呼び出しを行う場所が2箇所あるからです—Fib$(n-1)$ を計算するために1回と、Fib$(n-2)$ を計算するために1回です。各呼び出しの準備として、後で値が必要になるレジスタを保存し、n レジスタに再帰的に Fib を計算する必要のある数（$n-1$ または $n-2$）を設定し、continue に戻り先となるメイン列のエントリポイント（それぞれ afterfib_n_1 または afterfib_n_2）を代入します。そして fib_loop に移動します。再帰呼び出しから戻ると、答えは val に入っています。図 5.15にこのマシンのコントローラ列を示します。
