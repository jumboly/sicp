1.2.6  
Example: Testing for Primality
例：素数性のテスト

This section describes two methods for checking the primality of an integer $n$, one with order of growth $\Theta(\sqrt{n})$, and a probabilistic algorithm with order of growth $\Theta(\log n)$. The exercises at the end of this section suggest programming projects based on these algorithms.
この節では、整数 $n$ の素数性を判定する2つの方法を説明します。1つは増加の次数が $\Theta(\sqrt{n})$ のもの、もう1つは増加の次数が $\Theta(\log n)$ の確率的アルゴリズムです。この節の最後にある演習問題では、これらのアルゴリズムに基づくプログラミング課題を提案します。

Searching for divisors

Since ancient times, mathematicians have been fascinated by problems concerning prime numbers, and many people have worked on the problem of determining ways to test if numbers are prime. One way to test if a number is prime is to find the number's divisors. The following program finds the smallest integral divisor (greater than 1) of a given number $n$. It does this in a straightforward way, by testing $n$ for divisibility by successive integers starting with 2.
古代から、数学者たちは素数に関する問題に魅了されてきました。数が素数かどうかを判定する方法の発見に、多くの人々が取り組んできました。ある数が素数かどうかを判定する1つの方法は、その数の約数を見つけることです。次のプログラムは、与えられた数 $n$ の最小の整数の約数（1より大きいもの）を見つけます。これは、$n$ が2から始まる連続する整数で割り切れるかどうかを順番にテストするという、素直な方法で行います。 
function smallest_divisor(n) {
    return find_divisor(n, 2);
}
function find_divisor(n, test_divisor) {
    return square(test_divisor) > n
           ? n
           : divides(test_divisor, n)
           ? test_divisor
           : find_divisor(n, test_divisor + 1);
}
function divides(a, b) {
    return b % a === 0;
}

We can test whether a number is prime as follows: $n$ is prime if and only if $n$ is its own smallest divisor.
ある数が素数かどうかは次のようにテストできます。$n$ が素数であるのは、$n$ 自身が最小の約数である場合に限ります。 
function is_prime(n) {
    return n === smallest_divisor(n);
}

The end test for find_divisor is based on the fact that if $n$ is not prime it must have a divisor less than or equal to $\sqrt{n}$.
find_divisor の終了条件は、$n$ が素数でなければ $\sqrt{n}$ 以下の約数を持つはずだという事実に基づいています。
[1]
This means that the algorithm need only test divisors between 1 and $\sqrt{n}$. Consequently, the number of steps required to identify $n$ as prime will have order of growth $\Theta(\sqrt{n})$.
これは、アルゴリズムが1から $\sqrt{n}$ の間の約数だけをテストすればよいことを意味します。したがって、$n$ が素数であることを確認するために必要なステップ数の増加の次数は $\Theta(\sqrt{n})$ になります。

The Fermat test

The $\Theta(\log n)$ primality test is based on a result from number theory known as Fermat's Little Theorem.
$\Theta(\log n)$ の素数判定テストは、 フェルマーの小定理として知られる数論の結果に基づいています。
[2]
Fermat's Little Theorem: If $n$ is a prime number and $a$ is any positive integer less than $n$, then $a$ raised to the $n$th power is congruent to $a$ modulo $n$.
フェルマーの小定理： $n$ が素数で、$a$ が $n$ より小さい任意の正の整数であるとき、$a$ の $n$ 乗は $a$ と法 $n$ で合同です。
(Two numbers are said to be congruent modulo $n$ if they both have the same remainder when divided by $n$. The remainder of a number $a$ when divided by $n$ is also referred to as the remainder of $a$ modulo $n$, or simply as $a$ modulo $n$.)
（2つの数が $n$ を法として合同であるとは、両方を $n$ で割ったときの余りが同じであることをいいます。数 $a$ を $n$ で割ったときの余りは、 $a$ の法 $n$ での余り、または単に $a$ modulo $n$ とも呼ばれます。）

If $n$ is not prime, then, in general, most of the numbers $a < n$ will not satisfy the above relation. This leads to the following algorithm for testing primality: Given a number $n$, pick a random number $a < n$ and compute the remainder of $a^n$ modulo $n$. If the result is not equal to $a$, then $n$ is certainly not prime. If it is $a$, then chances are good that $n$ is prime. Now pick another random number $a$ and test it with the same method. If it also satisfies the equation, then we can be even more confident that $n$ is prime. By trying more and more values of $a$, we can increase our confidence in the result. This algorithm is known as the Fermat test.
$n$ が素数でない場合、一般に $a < n$ である数のほとんどは上の関係を満たしません。これが次のような素数判定アルゴリズムにつながります。数 $n$ が与えられたら、 $a < n$ であるランダムな数 $a$ を選び、$a^n$ を $n$ で割った余りを計算します。結果が $a$ と等しくなければ、$n$ は確実に素数ではありません。$a$ と等しければ、$n$ が素数である可能性は高いです。次に、別のランダムな数 $a$ を選んで同じ方法でテストします。それも等式を満たすなら、$n$ が素数であるという確信をさらに強めることができます。$a$ の値をどんどん試すことで、結果に対する確信度を高めることができます。このアルゴリズムはフェルマーテストとして知られています。

To implement the Fermat test, we need a function that computes the exponential of a number modulo another number:
フェルマーテストを実装するには、ある数の別の数を法とする べき乗を計算する 関数 が必要です。 
function expmod(base, exp, m) {
    return exp === 0
           ? 1
           : is_even(exp)
           ? square(expmod(base, exp / 2, m)) % m
           : (base * expmod(base, exp - 1, m)) % m;
}
This is very similar to the fast_expt function of section 1.2.4. It uses successive squaring, so that the number of steps grows logarithmically with the exponent.
これは1.2.4節の fast_expt 関数 と非常によく似ています。逐次二乗法を使うので、ステップ数は指数に対して対数的に増加します。
[3]

The Fermat test is performed by choosing at random a number $a$ between 1 and $n-1$ inclusive and checking whether the remainder modulo $n$ of the $n$th power of $a$ is equal to $a$. The random number $a$ is chosen using the primitive function math_random, which returns a nonnegative number less than 1. Hence, to obtain a random number between 1 and $n-1$, we multiply the return value of math_random by $n-1$, round down the result with the primitive function math_floor, and add 1:
フェルマーテストは、1から $n-1$ の間のランダムな数 $a$ を選び、$a$ の $n$ 乗を $n$ で割った余りが $a$ と等しいかどうかを調べることで実行されます。ランダムな数 $a$ は、 プリミティブ関数 math_random を使って選びます。 これは1より小さい非負の数を返します。したがって、1から $n-1$ の間のランダムな数を得るには、math_random の戻り値に $n-1$ を掛け、プリミティブ関数 math_floor で結果を切り捨て、1を加えます。 
function fermat_test(n) {
    function try_it(a) {
        return expmod(a, n, n) === a;
    }
    return try_it(1 + math_floor(math_random() * (n - 1)));
}

The following function runs the test a given number of times, as specified by a parameter. Its value is true if the test succeeds every time, and false otherwise.
次の 関数 は、パラメータで指定された回数だけテストを実行します。テストが毎回成功すれば true を、そうでなければ false を返します。 
function fast_is_prime(n, times) {
    return times === 0
           ? true
           : fermat_test(n)
           ? fast_is_prime(n, times - 1)
           : false;
}

Probabilistic methods

The Fermat test differs in character from most familiar algorithms, in which one computes an answer that is guaranteed to be correct. Here, the answer obtained is only probably correct. More precisely, if $n$ ever fails the Fermat test, we can be certain that $n$ is not prime. But the fact that $n$ passes the test, while an extremely strong indication, is still not a guarantee that $n$ is prime. What we would like to say is that for any number $n$, if we perform the test enough times and find that $n$ always passes the test, then the probability of error in our primality test can be made as small as we like.
フェルマーテストは、答えが正しいことが保証されるおなじみのアルゴリズムとは性質が異なります。ここで得られる答えは、おそらく正しいというだけです。より正確に言えば、$n$ がフェルマーテストに失敗すれば、$n$ が素数でないことは確実です。しかし、$n$ がテストに合格するという事実は、非常に強い指標ではあるものの、$n$ が素数であるという保証にはなりません。私たちが言いたいのは、任意の数 $n$ について、テストを十分な回数実行して $n$ が常にテストに合格すれば、素数判定の誤りの確率をいくらでも小さくできるということです。

Unfortunately, this assertion is not quite correct. There do exist numbers that fool the Fermat test: numbers $n$ that are not prime and yet have the property that $a^n$ is congruent to $a$ modulo $n$ for all integers $a < n$. Such numbers are extremely rare, so the Fermat test is quite reliable in practice.
残念ながら、この主張は完全には正しくありません。フェルマーテストを騙す数が存在するのです。つまり、素数ではないのに、すべての整数 $a < n$ に対して $a^n$ が $a$ と法 $n$ で合同になるような数 $n$ です。そのような数は極めてまれなので、フェルマーテストは実用上かなり信頼できます。
[4]
There are variations of the Fermat test that cannot be fooled. In these tests, as with the Fermat method, one tests the primality of an integer $n$ by choosing a random integer $a < n$ and checking some condition that depends upon $n$ and $a$. (See exercise 1.28 for an example of such a test.) On the other hand, in contrast to the Fermat test, one can prove that, for any $n$, the condition does not hold for most of the integers $a < n$ unless $n$ is prime. Thus, if $n$ passes the test for some random choice of $a$, the chances are better than even that $n$ is prime. If $n$ passes the test for two random choices of $a$, the chances are better than 3 out of 4 that $n$ is prime. By running the test with more and more randomly chosen values of $a$ we can make the probability of error as small as we like.
フェルマーテストの変種で、騙されないものがあります。これらのテストでは、フェルマーの方法と同様に、ランダムな整数 $a < n$ を選び、$n$ と $a$ に依存する何らかの条件を調べることで、整数 $n$ の素数性をテストします。（このようなテストの例については、演習問題 1.28を参照してください。）一方、フェルマーテストとは対照的に、任意の $n$ について、$n$ が素数でない限り、整数 $a < n$ のほとんどに対してその条件が成り立たないことを証明できます。したがって、ランダムに選んだ $a$ で $n$ がテストに合格すれば、$n$ が素数である確率は半分より高くなります。ランダムに選んだ2つの $a$ でテストに合格すれば、$n$ が素数である確率は4分の3より高くなります。ランダムに選んだ $a$ の値をどんどん増やしてテストを実行することで、誤りの確率をいくらでも小さくできます。

The existence of tests for which one can prove that the chance of error becomes arbitrarily small has sparked interest in algorithms of this type, which have come to be known as probabilistic algorithms. There is a great deal of research activity in this area, and probabilistic algorithms have been fruitfully applied to many fields.
誤りの確率を任意に小さくできることが証明できるテストの存在は、この種のアルゴリズムへの関心を引き起こしました。これらは確率的アルゴリズムとして知られるようになりました。 この分野では多くの研究が行われており、確率的アルゴリズムは多くの分野に実りある形で応用されています。
[5]

One variant of the Fermat test that cannot be fooled is called the Miller–Rabin test (Miller 1976; Rabin 1980). This starts from an alternate form of Fermat's Little Theorem, which states that if $n$ is a prime number and $a$ is any positive integer less than $n$, then $a$ raised to the $(n-1)$st power is congruent to 1 modulo $n$. To test the primality of a number $n$ by the Miller–Rabin test, we pick a random number $a < n$ and raise $a$ to the $(n-1)$st power modulo $n$ using the expmod function. However, whenever we perform the squaring step in expmod, we check to see if we have discovered a nontrivial square root of 1 modulo $n$, that is, a number not equal to 1 or $n-1$ whose square is equal to 1 modulo $n$. It is possible to prove that if such a nontrivial square root of 1 exists, then $n$ is not prime. It is also possible to prove that if $n$ is an odd number that is not prime, then, for at least half the numbers $a < n$, computing $a^{n-1}$ in this way will reveal a nontrivial square root of 1 modulo $n$. (This is why the Miller–Rabin test cannot be fooled.) Modify the expmod function to signal if it discovers a nontrivial square root of 1, and use this to implement the Miller–Rabin test with a function analogous to fermat_test. Check your function by testing various known primes and non-primes. Hint: One convenient way to make expmod signal is to have it return 0.
フェルマーテストの変種で騙されないものの1つは、 ミラー–ラビンテスト（Miller 1976；Rabin 1980）と呼ばれます。これは、 フェルマーの小定理の別の形から始まります。その定理によれば、$n$ が素数で $a$ が $n$ より小さい任意の正の整数であるとき、$a$ の $(n-1)$ 乗は1と法 $n$ で合同です。ミラー–ラビンテストで数 $n$ の素数性をテストするには、ランダムな数 $a < n$ を選び、expmod 関数 を使って $a$ の $(n-1)$ 乗を法 $n$ で計算します。ただし、expmod の二乗ステップを実行するたびに、法 $n$ での1の非自明な平方根、つまり、1でも $n-1$ でもなく、その二乗が法 $n$ で1に等しい数を発見したかどうかを調べます。そのような1の非自明な平方根が存在すれば、$n$ が素数でないことを証明できます。また、$n$ が素数でない奇数であれば、$a < n$ の少なくとも半分の数について、この方法で $a^{n-1}$ を計算すると法 $n$ での1の非自明な平方根が見つかることも証明できます。（これがミラー–ラビンテストが騙されない理由です。）expmod 関数 を、1の非自明な平方根を発見した場合にシグナルを送るように修正し、これを使って fermat_test に類似した 関数 でミラー–ラビンテストを実装してください。さまざまな既知の素数と非素数でテストして、あなたの 関数 を確認してください。ヒント：expmod にシグナルを送らせる便利な方法の1つは、 0を返すようにすることです。 
function random(n) {

function miller_rabin_test(n) {
    function expmod(base, exp, m) {
        return exp === 0
               ? 1
               : is_even(exp)
               ? square(trivial_test(expmod(base,
                                            exp / 2,
                                            m), 
                                     m))
                 % m
               : (base * expmod(base, exp - 1, m)) 
                 % m;

        return r === 1 || r === m - 1
               ? r
               : square(r) % m === 1
               ? 0
