2.1.1  
Example: Arithmetic Operations for Rational Numbers
例：有理数の算術演算

Suppose we want to do arithmetic with rational numbers. We want to be able to add, subtract, multiply, and divide them and to test whether two rational numbers are equal.
有理数で算術演算をしたいとします。加算、減算、乗算、除算ができ、2つの有理数が等しいかどうかをテストできるようにしたいのです。

Let us begin by assuming that we already have a way of constructing a rational number from a numerator and a denominator. We also assume that, given a rational number, we have a way of extracting (or selecting) its numerator and its denominator. Let us further assume that the constructor and selectors are available as functions:
  • make_rat($n$, $d$) returns the rational number whose numerator is the integer $n$ and whose denominator is the integer $d$.
  • numer($x$) returns the numerator of the rational number $x$.
  • denom($x$) returns the denominator of the rational number $x$.
まず、分子と分母から有理数を構築する方法がすでにあると仮定することから始めましょう。また、有理数が与えられたとき、その分子と分母を取り出す（選択する）方法があると仮定します。さらに、コンストラクタとセレクタが次の関数として利用できると仮定しましょう：
  • make_rat($n$, $d$) は、分子が整数$n$で分母が整数$d$の有理数を返します。
  • numer($x$) は、有理数$x$の分子を返します。
  • denom($x$) は、有理数$x$の分母を返します。

We are using here a powerful strategy of synthesis: wishful thinking. We haven't yet said how a rational number is represented, or how the functions numer, denom, and make_rat should be implemented. Even so, if we did have these three functions, we could then add, subtract, multiply, divide, and test equality by using the following relations:
ここでは強力な合成の戦略、 希望的思考（wishful thinking）を使っています。有理数がどのように表現されるか、あるいは関数numer、denom、make_ratがどのように実装されるべきかはまだ述べていません。それでも、これら3つの関数があれば、次の関係式を使って加算、減算、乗算、除算、等値テストを行えます：
\[ \begin{array}{rll} \dfrac{n_{1}}{d_{1}}+\dfrac{n_{2}}{d_{2}} &=&\dfrac{n_{1}d_{2}+n_{2}d_{1}}{d_{1}d_{2}}\\[15pt] \dfrac{n_{1}}{d_{1}}-\dfrac{n_{2}}{d_{2}} &=&\dfrac{n_{1}d_{2}-n_{2}d_{1}}{d_{1}d_{2}}\\[15pt] \dfrac{n_{1}}{d_{1}}\cdot\dfrac{n_{2}}{d_{2}} &=&\dfrac{n_{1}n_{2}}{d_{1}d_{2}}\\[15pt] \dfrac{n_{1}/d_{1}}{n_{2}/d_{2}} &=&\dfrac{n_{1}d_{2}}{d_{1}n_{2}}\\[15pt] \dfrac{n_{1}}{d_{1}} &=&\dfrac{n_{2}}{d_{2}}\ \quad \textrm{if and only if}\ \ \ n_{1}d_{2}\ =\ n_{2}d_{1} \end{array} \]

We can express these rules as functions:
これらの規則を関数として表現できます： 
function add_rat(x, y) {
    return make_rat(numer(x) * denom(y) + numer(y) * denom(x),
                    denom(x) * denom(y));
}
function sub_rat(x, y) {
    return make_rat(numer(x) * denom(y) - numer(y) * denom(x),
                    denom(x) * denom(y));
}
function mul_rat(x, y) {
    return make_rat(numer(x) * numer(y),
                    denom(x) * denom(y));
}
function div_rat(x, y) {
    return make_rat(numer(x) * denom(y),
                    denom(x) * numer(y));
}
function equal_rat(x, y) {
    return numer(x) * denom(y) === numer(y) * denom(x);
}

Now we have the operations on rational numbers defined in terms of the selector and constructor functions numer, denom, and make_rat. But we haven't yet defined these. What we need is some way to glue together a numerator and a denominator to form a rational number.
これで、セレクタとコンストラクタの関数であるnumer、denom、make_ratを使って有理数の演算が定義できました。しかし、これらはまだ定義していません。必要なのは、分子と分母をくっつけて有理数を構成する何らかの方法です。

Pairs
ペア

To enable us to implement the concrete level of our data abstraction, our JavaScript environment provides a compound structure called a pair, which can be constructed with the primitive function pair. This function takes two arguments and returns a compound data object that contains the two arguments as parts. Given a pair, we can extract the parts using the primitive functions head and tail. Thus, we can use pair, head, and tail as follows:
データ抽象の具体的なレベルを実装するために、JavaScript 環境は ペアと呼ばれる複合構造を提供しています。ペアはプリミティブ関数 pairで構築できます。この関数は2つの引数を取り、その2つの引数を部分として含む複合データオブジェクトを返します。ペアが与えられると、プリミティブ関数 headと tailを使って部分を取り出せます。したがって、pair、head、tailは次のように使えます： 
const x = pair(1, 2);

head(x);

1
tail(x);

2
Notice that a pair is a data object that can be given a name and manipulated, just like a primitive data object. Moreover, pair can be used to form pairs whose elements are pairs, and so on:
ペアは、プリミティブなデータオブジェクトと同じように、名前を付けて操作できるデータオブジェクトであることに注目してください。さらに、pairを使って、要素がペアであるペアを作ることもできます： 
const x = pair(1, 2);

const y = pair(3, 4);

const z = pair(x, y);

head(head(z));

1
head(tail(z));

3
In section 2.2 we will see how this ability to combine pairs means that pairs can be used as general-purpose building blocks to create all sorts of complex data structures. The single compound-data primitive pair, implemented by the functions pair, head, and tail, is the only glue we need. Data objects constructed from pairs are called list-structured data.
2.2節では、このペアの組み合わせ能力により、ペアがあらゆる種類の複雑なデータ構造を作るための汎用的な構成要素として使えることを見ていきます。関数pair、head、tailで実装される単一の複合データプリミティブペアが、必要な接着剤のすべてです。ペアから構築されたデータオブジェクトは、 リスト構造データと呼ばれます。

Representing rational numbers
有理数の表現

Pairs offer a natural way to complete the rational-number system. Simply represent a rational number as a pair of two integers: a numerator and a denominator. Then make_rat, numer, and denom are readily implemented as follows:
ペアは、 有理数システムを完成させる自然な方法を提供します。有理数を2つの整数のペア、すなわち分子と分母として表現すればよいのです。そうすれば、make_rat、numer、denomは次のように簡単に実装できます：
[1] 
function make_rat(n, d) { return pair(n, d); }

function numer(x) { return head(x); }

function denom(x) { return tail(x); }
Also, in order to display the results of our computations, we can print rational numbers by printing the numerator, a slash, and the
また、計算結果を表示するために、分子、スラッシュ、そして
denominator. We use the primitive function stringify to turn any value (here a number) into a string. The operator + in JavaScript is overloaded; it can be applied to two numbers or to two strings, and in the latter case it returns the result of concatenating the two strings.
分母を表示することで有理数を表示できます。 プリミティブ関数 stringifyを使って任意の値（ここでは数値）を文字列に変換します。JavaScript の演算子 +は オーバーロードされています。2つの数値または2つの文字列に適用でき、後者の場合は2つの文字列を連結した結果を返します。
[2] 
function print_rat(x) {
    return display(stringify(numer(x)) + " / " + stringify(denom(x)));
}
Now we can try our rational-number functions:
これで有理数の関数を試してみることができます：
[3] 
const one_half = make_rat(1, 2);

print_rat(one_half);

"1 / 2"
const one_third = make_rat(1, 3);
print_rat(add_rat(one_half, one_third));

"5 / 6"
print_rat(mul_rat(one_half, one_third));

"1 / 6"
print_rat(add_rat(one_third, one_third));

"6 / 9"

As the final example shows, our rational-number implementation does not reduce rational numbers to lowest terms. We can remedy this by changing make_rat. If we have a gcd function like the one in section 1.2.5 that produces the greatest common divisor of two integers, we can use gcd to reduce the numerator and the denominator to lowest terms before constructing the pair:
最後の例が示すように、この有理数の実装では有理数を 既約分数に約分していません。これはmake_ratを変更することで対処できます。1.2.5節のような、2つの整数の 最大公約数を求めるgcd関数があれば、ペアを構築する前にgcdを使って分子と分母を既約にできます： 
function make_rat(n, d) {
    const g = gcd(n, d);
    return pair(n / g, d / g);
}
Now we have
これで次の結果が得られます。
print_rat(add_rat(one_third, one_third));

"2 / 3"
as desired. This modification was accomplished by changing the constructor make_rat without changing any of the functions (such as add_rat and mul_rat) that implement the actual operations.
望み通りです。この変更は、実際の演算を実装する関数（add_ratやmul_ratなど）を一切変更せずに、コンストラクタmake_ratを変更するだけで実現されました。

Exercise 2.1
Define a better version of make_rat that handles both positive and negative arguments. The function make_rat should normalize the sign so that if the rational number is positive, both the numerator and denominator are positive, and if the rational number is negative, only the numerator is negative.
正と負の両方の引数を扱えるように、make_ratのより良いバージョンを定義してください。関数make_ratは、有理数が正の場合は分子と分母の両方を正にし、有理数が負の場合は分子だけを負にするように符号を正規化するべきです。 
function sign(x) {
    return x < 0 
           ? -1
	   : x > 0
	     ? 1
	     : 0;
}
function make_rat(n, d) {
    const g = gcd(n, d);
    return pair(sign(n) * sign(d) * abs(n / g), 
                abs(d / g));
}
[1]
Another way to define the selectors and constructor is
セレクタとコンストラクタを定義する別の方法は次のとおりです。
const make_rat = pair;
const numer = head;
const denom = tail;
The first definition associates the name make_rat with the value of the expression pair, which is the primitive function that constructs pairs. Thus make_rat and pair are names for the same primitive constructor.

Defining selectors and constructors in this way is efficient: Instead of make_rat calling pair, make_rat is pair, so there is only one function called, not two, when make_rat is called. On the other hand, doing this defeats debugging aids that trace function calls or put breakpoints on function calls: You may want to watch make_rat being called, but you certainly don't want to watch every call to pair.

We have chosen not to use this style of definition in this book.

最初の定義は、名前make_ratを、ペアを構築するプリミティブ関数である式pairの値に関連付けます。したがって、make_ratとpairは同じプリミティブコンストラクタの名前です。

この方法でセレクタとコンストラクタを定義するのは効率的です。make_ratがpairを呼び出すのではなく、make_ratがpairそのものなので、make_ratが呼び出されたとき、2つではなく1つの関数だけが呼び出されます。一方で、これをすると関数呼び出しをトレースしたりブレークポイントを設定したりするデバッグ支援が使えなくなります。make_ratが呼び出されるのを見たいかもしれませんが、pairへのすべての呼び出しを見たいとは思わないでしょう。

本書ではこのスタイルの定義を使わないことにしました。

[2]
In JavaScript, the operator + can also be applied to a string and a number and to other operand combinations, but in this book, we choose to apply it either to two numbers or to two strings.
JavaScript では、演算子+は文字列と数値やその他のオペランドの組み合わせにも適用できますが、本書では2つの数値または2つの文字列のいずれかに適用することにします。
[3]
The primitive function display introduced in exercise 1.22 returns its argument, but in the uses of print_rat below, we show only what print_rat prints, not what the interpreter prints as the value returned by print_rat.
練習問題 1.22で導入したプリミティブ関数 displayは引数を返しますが、以下のprint_ratの使用例では、print_ratが表示するものだけを示し、print_ratが返す値としてインタプリタが表示するものは示しません。
