1.3.4  
Functions as Returned Values
戻り値としての 関数

The above examples demonstrate how the ability to pass functions as arguments significantly enhances the expressive power of our programming language. We can achieve even more expressive power by creating functions whose returned values are themselves functions.
上の例は、 関数 を引数として渡す能力がプログラミング言語の表現力をいかに大幅に高めるかを示しています。戻り値自体が 関数 であるような 関数 を作ることで、さらに大きな表現力を実現できます。

We can illustrate this idea by looking again at the fixed-point example described at the end of section 1.3.3. We formulated a new version of the square-root function as a fixed-point search, starting with the observation that $\sqrt{x}$ is a fixed-point of the function $y\mapsto x/y$. Then we used average damping to make the approximations converge. Average damping is a useful general technique in itself. Namely, given a function $f$, we consider the function whose value at $x$ is equal to the average of $x$ and $f(x)$.
このアイデアは、 1.3.3節の最後で説明した不動点の例をもう一度見ることで説明できます。$\sqrt{x}$ が関数 $y\mapsto x/y$ の不動点であるという観察から出発して、平方根 関数 の新しいバージョンを不動点探索として定式化しました。そして、近似を収束させるために平均減衰を使いました。平均減衰はそれ自体が有用な一般的テクニックです。すなわち、関数 $f$ が与えられたとき、$x$ での値が $x$ と $f(x)$ の平均に等しい関数を考えます。

We can express the idea of average damping by means of the following function:
平均減衰のアイデアを次の 関数 で表現できます：
function average_damp(f) {
    return x => average(x, f(x));
}
The function average_damp takes as its argument a function f and returns as its value a function (produced by the lambda expression) that, when applied to a number x, produces the average of x and f(x). For example, applying average_damp to the square function produces a function whose value at some number $x$ is the average of $x$ and $x^2$. Applying this resulting function to 10 returns the average of 10 and 100, or 55:
関数 average_damp は 引数として 関数 f を取り、値として、数 x に適用されると x と f(x) の平均を生成する 関数（ラムダ式によって生成） を返します。例えば、 average_damp を square 関数 に適用すると、ある数 $x$ での値が $x$ と $x^2$ の平均である 関数 が生成されます。この結果の 関数 を10に適用すると、10と100の平均、つまり55が返されます：
[1] 
average_damp(square)(10);

55

Using average_damp, we can reformulate the square-root function as follows:
average_damp を使えば、 平方根 関数 を次のように再定式化できます：
function sqrt(x) {
    return fixed_point(average_damp(y => x / y), 1);
}
Notice how this formulation makes explicit the three ideas in the method: fixed-point search, average damping, and the function $y\mapsto x/y$. It is instructive to compare this formulation of the square-root method with the original version given in section 1.1.7. Bear in mind that these functions express the same process, and notice how much clearer the idea becomes when we express the process in terms of these abstractions. In general, there are many ways to formulate a process as a function. Experienced programmers know how to choose process formulations that are particularly perspicuous, and where useful elements of the process are exposed as separate entities that can be reused in other applications. As a simple example of reuse, notice that the cube root of $x$ is a fixed point of the function $y\mapsto x/y^2$, so we can immediately generalize our square-root function to one that extracts cube roots:
この定式化が、この方法の3つのアイデア——不動点探索、平均減衰、関数 $y\mapsto x/y$——をいかに明確にしているかに注目してください。平方根法のこの定式化を、 1.1.7節で示した元のバージョンと比較してみると有益です。これらの 関数 は同じプロセスを表現しているということを念頭に置き、これらの抽象でプロセスを表現するとアイデアがどれほど明確になるかに注目してください。一般に、プロセスを 関数 として定式化する方法は多数あります。経験豊富なプログラマは、特に見通しが良く、プロセスの有用な要素が他の応用で再利用可能な別個のエンティティとして公開されるような定式化を選ぶ方法を知っています。再利用の簡単な例として、$x$ の立方根は関数 $y\mapsto x/y^2$ の不動点なので、平方根 関数 を 立方根を求めるものに直ちに一般化できます：
[2] 
function cube_root(x) {
    return fixed_point(average_damp(y => x / square(y)), 1);
}

Newton's method
ニュートン法

When we first introduced the square-root function, in section 1.1.7, we mentioned that this was a special case of Newton's method. If $x\mapsto g(x)$ is a differentiable function, then a solution of the equation $g(x)=0$ is a fixed point of the function $x\mapsto f(x)$ where
 1.1.7節で平方根 関数 を最初に導入したとき、これが ニュートン法の特殊ケースであることに触れました。$x\mapsto g(x)$ が微分可能な関数である場合、方程式 $g(x)=0$ の解は、次の関数 $x\mapsto f(x)$ の不動点です。
\[ \begin{array}{lll} f(x) & = & x - \dfrac{g(x)}{Dg(x)} \end{array} \]
and $Dg(x)$ is the derivative of $g$ evaluated at $x$. Newton's method is the use of the fixed-point method we saw above to approximate a solution of the equation by finding a fixed point of the function $f$. For many functions $g$ and for sufficiently good initial guesses for $x$, Newton's method converges very rapidly to a solution of $g(x)=0$.
ここで $Dg(x)$ は $g$ の $x$ における導関数です。 ニュートン法は、上で見た不動点法を使って、関数 $f$ の不動点を見つけることで方程式の解を近似する方法です。多くの関数 $g$ と、$x$ の十分に良い初期推測に対して、ニュートン法は $g(x)=0$ の解に非常に速く収束します。
[3][4]

In order to implement Newton's method as a function, we must first express the idea of derivative. Note that derivative, like average damping, is something that transforms a function into another function. For instance, the derivative of the function $x\mapsto x^3$ is the function $x \mapsto 3x^2$. In general, if $g$ is a function and $dx$ is a small number, then the derivative $Dg$ of $g$ is the function whose value at any number $x$ is given (in the limit of small $dx$) by
ニュートン法を 関数 として実装するには、まず 導関数のアイデアを表現する必要があります。導関数は、平均減衰と同様に、関数を別の関数に変換するものであることに注意してください。例えば、関数 $x\mapsto x^3$ の導関数は関数 $x \mapsto 3x^2$ です。一般に、$g$ が関数で $dx$ が小さい数であるとき、$g$ の導関数 $Dg$ は、任意の数 $x$ での値が（$dx$ が小さいという極限において）次の式で与えられる関数です。
\[ \begin{array}{lll} Dg(x) & = & \dfrac {g(x+dx) - g(x)}{dx} \end{array} \]
Thus, we can express the idea of derivative (taking $dx$ to be, say, 0.00001) as the function
したがって、導関数のアイデアを（$dx$ を例えば 0.00001 として）次の 関数 で表現できます。
function deriv(g) {
    return x => (g(x + dx) - g(x)) / dx;
}
along with the declaration
および次の 宣言 を組み合わせます。
const dx = 0.00001;

Like average_damp, deriv is a function that takes a function as argument and returns a function as value. For example, to approximate the derivative of $x \mapsto x^3$ at 5 (whose exact value is 75) we can evaluate
average_damp と同様に、 deriv は 関数 を引数として取り、 関数 を値として返す 関数 です。例えば、$x \mapsto x^3$ の5での導関数（正確な値は75）を近似するには、次のように評価します。
function cube(x) { return x * x * x; }

deriv(cube)(5);

75.00014999664018

With the aid of deriv, we can express Newton's method as a fixed-point process:
deriv を使えば、ニュートン法を不動点プロセスとして表現できます：
function newton_transform(g) {
    return x => x - g(x) / deriv(g)(x);
}
function newtons_method(g, guess) {
    return fixed_point(newton_transform(g), guess);
}
The newton_transform function expresses the formula at the beginning of this section, and newtons_method is readily defined in terms of this. It takes as arguments a function that computes the function for which we want to find a zero, together with an initial guess. For instance, to find the square root of $x$, we can use Newton's method to find a zero of the function $y\mapsto y^2-x$ starting with an initial guess of 1. This provides yet another form of the square-root function:
newton_transform 関数 はこのセクションの冒頭の公式を表現し、 newtons_method はこれを使って容易に定義できます。零点を見つけたい関数を計算する 関数 と初期推測を引数として取ります。例えば、$x$ の平方根を求めるには、 ニュートン法を使って関数 $y\mapsto y^2-x$ の零点を初期推測1から探せます。これにより、平方根 関数 のまた別の形が得られます：
[5] 
function sqrt(x) {
    return newtons_method(y => square(y) - x, 1);
}

Abstractions and first-class functions
抽象と第一級 関数

We've seen two ways to express the square-root computation as an instance of a more general method, once as a fixed-point search and once using Newton's method. Since Newton's method was itself expressed as a fixed-point process, we actually saw two ways to compute square roots as fixed points. Each method begins with a function and finds a fixed point of some transformation of the function. We can express this general idea itself as a function:
平方根の計算を、より一般的な方法のインスタンスとして表現する2つの方法を見てきました。一つは不動点探索として、もう一つはニュートン法を使って。ニュートン法自体が不動点プロセスとして表現されたので、実際には平方根を不動点として計算する2つの方法を見たことになります。各方法は関数から始めて、関数のある変換の 不動点を見つけます。この一般的なアイデア自体を 関数 として表現できます：
function fixed_point_of_transform(g, transform, guess) {
    return fixed_point(transform(g), guess);
}
This very general function takes as its arguments a function g that computes some function, a function that transforms g, and an initial guess. The returned result is a fixed point of the transformed function.
この非常に一般的な 関数 は、ある関数を計算する 関数 g、g を変換する 関数 、そして初期推測を引数として取ります。返される結果は、変換された関数の不動点です。

Using this abstraction, we can recast the first square-root computation from this section (where we look for a fixed point of the average-damped version of $y \mapsto x/y$) as an instance of this general method:
この抽象を使えば、このセクションの最初の平方根計算（$y \mapsto x/y$ の平均減衰版の不動点を探す）を、この一般的な方法のインスタンスとして書き直せます： 
function sqrt(x) {
    return fixed_point_of_transform(
               y => x / y,
               average_damp,
               1);
}
Similarly, we can express the second square-root computation from this section (an instance of Newton's method that finds a fixed point of the Newton transform of $y\mapsto y^2-x$) as
同様に、このセクションの2番目の平方根計算（$y\mapsto y^2-x$ のニュートン変換の不動点を見つける ニュートン法のインスタンス）を次のように表現できます。
function sqrt(x) {
    return fixed_point_of_transform(
               y => square(y) - x,
               newton_transform,
               1);
}

We began section 1.3 with the observation that compound functions are a crucial abstraction mechanism, because they permit us to express general methods of computing as explicit elements in our programming language. Now we've seen how higher-order functions permit us to manipulate these general methods to create further abstractions.
 1.3節は、複合 関数 が重要な抽象化メカニズムであるという観察から始めました。なぜなら、計算の一般的な方法をプログラミング言語の明示的な要素として表現することを可能にするからです。今度は、高階 関数 がこれらの一般的な方法を操作してさらなる抽象を作り出すことを可能にする様子を見てきました。

As programmers, we should be alert to opportunities to identify the underlying abstractions in our programs and to build upon them and generalize them to create more powerful abstractions. This is not to say that one should always write programs in the most abstract way possible; expert programmers know how to choose the level of abstraction appropriate to their task. But it is important to be able to think in terms of these abstractions, so that we can be ready to apply them in new contexts. The significance of higher-order functions is that they enable us to represent these abstractions explicitly as elements in our programming language, so that they can be handled just like other computational elements.
プログラマとして、プログラムの根底にある抽象を見つけ、それを基にしてより強力な抽象を一般化して作り出す機会に敏感であるべきです。これは、常にできるだけ抽象的にプログラムを書くべきだということではありません。熟練したプログラマは、タスクに適した抽象のレベルを選ぶ方法を知っています。しかし、これらの抽象で考えることができることは重要です。そうすれば、新しいコンテキストでそれらを適用する準備ができます。高階 関数 の重要性は、これらの抽象をプログラミング言語の要素として明示的に表現し、他の計算要素と同じように扱えるようにすることにあります。

In general, programming languages impose restrictions on the ways in which computational elements can be manipulated. Elements with the fewest restrictions are said to have first-class status. Some of the rights and privileges of first-class elements are:
一般に、プログラミング言語は計算要素を操作する方法に制限を課します。最も制限の少ない要素は 第一級の地位を持つと言われます。第一級要素の権利と特権の一部は次の通りです：
[6]
  • They may be referred to using names.
  • They may be passed as arguments to functions.
  • They may be returned as the results of functions.
  • They may be included in data structures.
  • 名前を使って参照できます。
  • 関数 に引数として渡すことができます。
  • 関数 の結果として返すことができます。
  • データ構造に含めることができます。

JavaScript, like other high-level programming languages, awards functions full first-class status. This poses challenges for efficient implementation, but the resulting gain in expressive power is enormous.
JavaScript は、他の高水準 プログラミング言語 と同様に 、 関数 に完全な第一級の地位を与えています。これは効率的な実装に課題をもたらしますが、結果として得られる表現力の向上は莫大です。

Several of the numerical methods described in this chapter are instances of an extremely general computational strategy known as iterative improvement. Iterative improvement says that, to compute something, we start with an initial guess for the answer, test if the guess is good enough, and otherwise improve the guess and continue the process using the improved guess as the new guess. Write a function iterative_improve that takes two functions as arguments: a method for telling whether a guess is good enough and a method for improving a guess. この章で説明した数値的方法のいくつかは、 反復的改善として知られる非常に一般的な計算戦略のインスタンスです。反復的改善は、何かを計算するには、答えの初期推測から始めて、推測が十分に良いかどうかをテストし、そうでなければ推測を改善し、改善された推測を新しい推測としてプロセスを続ける、というものです。推測が十分に良いかどうかを判定する方法と推測を改善する方法の2つの 関数 を引数として取る 関数 iterative_improve を書いてください。 関数 iterative_improve は、推測を引数として取り、十分に良くなるまで推測を改善し続ける 関数 を値として返すべきです。 1.1.7節の sqrt 関数 と 1.3.3節の fixed_point 関数 を iterative_improve で書き直してください。

        return is_good_enough(guess)
               ? guess

}
