3.5.3  
Exploiting the Stream Paradigm
ストリームパラダイムを活かす

Streams with delayed evaluation can be a powerful modeling tool, providing many of the benefits of local state and assignment. Moreover, they avoid some of the theoretical tangles that accompany the introduction of assignment into a programming language.
遅延評価を伴うストリームは強力なモデリングツールとなり、ローカル状態と代入がもたらす利点の多くを提供してくれます。さらに、プログラミング言語に代入を導入することに伴う理論的な厄介事の一部を避けられます。

The stream approach can be illuminating because it allows us to build systems with different module boundaries than systems organized around assignment to state variables. For example, we can think of an entire time series (or signal) as a focus of interest, rather than the values of the state variables at individual moments. This makes it convenient to combine and compare components of state from different moments.
ストリームアプローチには示唆に富む面があります。というのも、状態変数への代入を中心に構成されたシステムとは異なる モジュール境界を持つシステムを構築できるからです。たとえば、個々の瞬間における状態変数の値ではなく、時系列（あるいは信号）全体を興味の対象として捉えることができます。これにより、異なる瞬間における状態の構成要素を組み合わせたり比較したりすることが容易になります。

Formulating iterations as stream processes
反復をストリームプロセスとして定式化する

In section 1.2.1, we introduced iterative processes, which proceed by updating state variables. We know now that we can represent state as a timeless stream of values rather than as a set of variables to be updated. Let's adopt this perspective in revisiting the square-root function from section 1.1.7. Recall that the idea is to generate a sequence of better and better guesses for the square root of $x$ by applying over and over again the function that improves guesses:
1.2.1節では、状態変数を更新することによって進む反復的プロセスを導入しました。今や状態を、更新される変数の集合としてではなく、値の時間に依存しないストリームとして表現できることを知っています。この観点を取って1.1.7節の平方根 関数 を再訪してみましょう。アイデアは、推測を改善する 関数 を何度も適用することによって、$x$の平方根のよりよい推測の列を生成するというものでした。
function sqrt_improve(guess, x) {
    return average(guess, x / guess);
}

In our original sqrt function, we made these guesses be the successive values of a state variable. Instead we can generate the infinite stream of guesses, starting with an initial guess of 1:
元の sqrt 関数 では、これらの推測を状態変数の連続した値としていました。代わりに、初期推測値を1として、推測の無限ストリームを生成できます。
function sqrt_stream(x) {
   return pair(1, () => stream_map(guess => sqrt_improve(guess, x),
                                   sqrt_stream(x)));
}

display_stream(sqrt_stream(2));

We can generate more and more terms of the stream to get better and better guesses. If we like, we can write a function that keeps generating terms until the answer is good enough. (See exercise 3.64.)
ストリームの項をどんどん生成していけば、よりよい推測が得られます。望むなら、答えが十分よくなるまで項を生成し続ける 関数 を書くこともできます（演習 3.64を参照）。

Another iteration that we can treat in the same way is to generate an approximation to $\pi$, based upon the alternating series that we saw in section 1.3.1:
同じ方法で扱える別の反復として、 $\pi$ の近似を生成するというものがあります。これは 1.3.1節で見た交代級数に基づいています。
\[ \begin{array}{lll} \dfrac {\pi}{4} &=& 1-\dfrac{1}{3}+\dfrac{1}{5}-\dfrac{1}{7}+\cdots \end{array} \]
We first generate the stream of summands of the series (the reciprocals of the odd integers, with alternating signs). Then we take the stream of sums of more and more terms (using the partial_sums function of exercise 3.55) and scale the result by 4:
まず、級数の加数のストリーム（奇数の逆数に交互の符号を付けたもの）を生成します。次に、項をどんどん増やして総和をとったストリーム（演習 3.55の partial_sums関数 を使います）をとり、結果を 4 倍にスケールします。 
function pi_summands(n) {
   return pair(1 / n, () => stream_map(x => - x, pi_summands(n + 2)));
}
const pi_stream = scale_stream(partial_sums(pi_summands(1)), 4);

display_stream(pi_stream);

This gives us a stream of better and better approximations to $\pi$, although the approximations converge rather slowly. Eight terms of the sequence bound the value of $\pi$ between 3.284 and 3.017.
これにより $\pi$ に対するどんどん良くなる近似のストリームが得られます。ただし、収束はかなりゆっくりです。この数列を 8 項まで計算すると、$\pi$ は 3.017 と 3.284 の間に収まります。

So far, our use of the stream of states approach is not much different from updating state variables. But streams give us an opportunity to do some interesting tricks. For example, we can transform a stream with a sequence accelerator that converts a sequence of approximations to a new sequence that converges to the same value as the original, only faster.
ここまでのところ、状態のストリームというアプローチの使い方は、状態変数を更新するのとあまり変わりません。しかし、ストリームを使うと、いくつかの興味深いトリックを行う機会が得られます。たとえば、近似の数列を、元のものと同じ値に収束する新しい数列（ただし収束はより速い）に変換する 数列の加速器でストリームを変換できます。

One such accelerator, due to the eighteenth-century Swiss mathematician Leonhard Euler, works well with sequences that are partial sums of alternating series (series of terms with alternating signs). In Euler's technique, if $S_n$ is the $n$th term of the original sum sequence, then the accelerated sequence has terms
その一つに、18 世紀のスイスの数学者 レオンハルト・オイラーによる加速器があり、交代級数（項の符号が交互に変わる級数）の部分和である数列に対してよく機能します。オイラーの技法では、$S_n$ を元の総和数列の $n$ 番目の項とすると、加速された数列の項は次のようになります。
\[ \begin{array}{l} S_{n+1} - \dfrac{(S_{n+1}-S_n)^2}{S_{n-1}-2S_n+S_{n+1}} \end{array} \]
Thus, if the original sequence is represented as a stream of values, the transformed sequence is given by
したがって、元の数列が値のストリームとして表現されているなら、変換された数列は次で与えられます。
function euler_transform(s) { const s0 = stream_ref(s, 0); // $S_{n-1}$ const s1 = stream_ref(s, 1); // $S_{n}$ const s2 = stream_ref(s, 2); // $S_{n+1}$ return pair(s2 - square(s2 - s1) / (s0 + (-2) * s1 + s2), memo(() => euler_transform(stream_tail(s)))); }
Note that we make use of the memoization optimization of section 3.5.1, because in the following we will rely on repeated evaluation of the resulting stream.
ここでは3.5.1節のメモ化の最適化を利用していることに注意してください。以降では、得られたストリームに対する繰り返しの評価に依存するためです。

We can demonstrate Euler acceleration with our sequence of approximations to $\pi$:
オイラー加速を、先ほどの $\pi$ の近似数列で実演してみましょう。 
display_stream(euler_transform(pi_stream));

Even better, we can accelerate the accelerated sequence, and recursively accelerate that, and so on. Namely, we create a stream of streams (a structure we'll call a tableau) in which each stream is the transform of the preceding one:
さらによいことに、加速された数列をさらに加速し、それを再帰的に加速し、というように繰り返せます。つまり、ストリームのストリーム（ タブローと呼ぶ構造）を作り、その各ストリームが前のものの変換となるようにします。 
function make_tableau(transform, s) {
    return pair(s, () => make_tableau(transform, transform(s)));
}
The tableau has the form
このタブローは次の形をしています。
\[ \begin{array}{llllll} s_{00} & s_{01} & s_{02} & s_{03} & s_{04} & \ldots\\ & s_{10} & s_{11} & s_{12} & s_{13} & \ldots\\ & & s_{20} & s_{21} & s_{22} & \ldots\\ & & & & \ldots & \end{array} \]
Finally, we form a sequence by taking the first term in each row of the tableau:
最後に、タブローの各行の最初の項を取ることで数列を作ります。 
function accelerated_sequence(transform, s) {
    return stream_map(head, make_tableau(transform, s));
}

We can demonstrate this kind of super-acceleration of the $\pi$ sequence:
この種の超加速を$\pi$の数列で実演できます。 
display_stream(accelerated_sequence(euler_transform, pi_stream));

4
3.166666666666667
3.142105263157895
3.141599357319005
3.1415927140337785
3.1415926539752927
3.1415926535911765
3.141592653589778
...
The result is impressive. Taking eight terms of the sequence yields the correct value of $\pi$ to 14 decimal places. If we had used only the original $\pi$ sequence, we would need to compute on the order of $10^{13}$ terms (i.e., expanding the series far enough so that the individual terms are less then $10^{-13}$) to get that much accuracy!
結果は印象的です。この数列の8項を取るだけで、$\pi$の正しい値が小数点以下14桁まで得られます。もし元の$\pi$の数列だけを使っていたとすれば、これだけの精度を得るには$10^{13}$程度のオーダーの項を計算する必要があるでしょう（つまり、個々の項が$10^{-13}$より小さくなるまで級数を展開する必要があります）。

We could have implemented these acceleration techniques without using streams. But the stream formulation is particularly elegant and convenient because the entire sequence of states is available to us as a data structure that can be manipulated with a uniform set of operations.
これらの加速の技法は、ストリームを使わずに実装することもできたでしょう。しかし、ストリームによる定式化は特にエレガントで便利です。なぜなら、状態の全体の数列が、統一された演算の集合で操作できるデータ構造として手元にあるからです。

Exercise 3.63
Louis Reasoner is not happy with the performance of the stream produced by the sqrt_stream function and tries to optimize it using memoization:
Louis Reasonerは、 sqrt_stream関数が生成するストリームの性能に不満で、メモ化を使ってそれを最適化しようとします。 
function sqrt_stream_optimized(x) {
    return pair(1,
                memo(() => stream_map(guess =>
                                        sqrt_improve(guess, x),
                                      sqrt_stream_optimized(x))));
}
Alyssa P. Hacker instead proposes
一方、Alyssa P. Hackerは次のように提案します。
function sqrt_stream_optimized_2(x) {
    const guesses = pair(1,
                         memo(() => stream_map(guess =>
                                                 sqrt_improve(guess, x),
                                               guesses)));
    return guesses;
}
and claims that Louis's version is considerably less efficient than hers, because it performs redundant computation. Explain Alyssa's answer. Would Alyssa's approach without memoization be more efficient than the original sqrt_stream?
そして、Louisのバージョンは冗長な計算を行うため、自分のものよりかなり非効率だと主張します。Alyssaの答えを説明してください。Alyssaのアプローチがメモ化なしの場合、元のsqrt_streamよりも効率的になるでしょうか。

Exercise 3.64
Write a function stream_limit that takes as arguments a stream and a number (the tolerance). It should examine the stream until it finds two successive elements that differ in absolute value by less than the tolerance, and return the second of the two elements. Using this, we could compute square roots up to a given tolerance by
ストリームと数値（許容誤差）を引数に取る 関数stream_limit を書いてください。この関数は、ストリームを調べていき、絶対値の差が許容誤差未満となる連続した2つの要素が見つかるまで続け、その2つのうち2番目の要素を返します。これを使うと、与えられた許容誤差までの平方根を次のように計算できます。 
function sqrt(x, tolerance) {
    return stream_limit(sqrt_stream(x), tolerance);
}

Exercise 3.65
Use the series
級数
\[ \begin{array}{lll} \ln 2 &=& 1-\dfrac{1}{2}+\dfrac{1}{3}-\dfrac{1}{4}+\cdots \end{array} \]
to compute three sequences of approximations to the natural logarithm of 2, in the same way we did above for $\pi$. How rapidly do these sequences converge?

Infinite streams of pairs
ペアの無限ストリーム

In section 2.2.3, we saw how the sequence paradigm handles traditional nested loops as processes defined on sequences of pairs. If we generalize this technique to infinite streams, then we can write programs that are not easily represented as loops, because the looping must range over an infinite set.
2.2.3節では、シーケンスのパラダイムが、従来の入れ子のループをペアのシーケンス上で定義されたプロセスとしてどう扱うかを見ました。この手法を無限ストリームに一般化すると、ループとしては表現しにくいプログラムを書けるようになります。なぜなら、ループが無限集合にわたって変動しなければならないからです。

For example, suppose we want to generalize the prime_sum_pairs function of section 2.2.3 to produce the stream of pairs of all integers $(i,j)$ with $i \leq j$ such that $i+j$ is prime. If int_pairs is the sequence of all pairs of integers $(i,j)$ with $i \leq j$, then our required stream is simply
たとえば、2.2.3節の prime_sum_pairs関数 を一般化して、$i \leq j$を満たすすべての整数のペア$(i,j)$のうち、$i+j$が素数となるペアからなるストリームを生成したいとしましょう。 int_pairs が$i \leq j$を満たすすべての整数のペア$(i,j)$のシーケンスだとすると、求めるストリームは単に次のように書けます。
[1] 
stream_filter(pair => is_prime(head(pair) + head(tail(pair))),
              int_pairs);

Our problem, then, is to produce the stream int_pairs. More generally, suppose we have two streams $S = (S_i)$ and $T = (T_j)$, and imagine the infinite rectangular array
では、私たちの課題はストリーム int_pairs を生成することです。より一般的に、2つのストリーム$S = (S_i)$と$T = (T_j)$があるとして、次のような無限の矩形配列を考えます。
\[ \begin{array}{cccc} (S_0,T_0) & (S_0,T_1) & (S_0, T_2) & \ldots\\ (S_1,T_0) & (S_1,T_1) & (S_1, T_2) & \ldots\\ (S_2,T_0) & (S_2,T_1) & (S_2, T_2) & \ldots\\ \ldots \end{array} \]
We wish to generate a stream that contains all the pairs in the array that lie on or above the diagonal, i.e., the pairs
この配列の中で、対角線上またはその上にあるすべてのペアを含むストリームを生成したいのです。すなわち、次のペア群です。
\[ \begin{array}{cccc} (S_0,T_0) & (S_0,T_1) & (S_0, T_2) & \ldots\\ & (S_1,T_1) & (S_1, T_2) & \ldots\\ & & (S_2, T_2) & \ldots\\ & & & \ldots \end{array} \]
(If we take both $S$ and $T$ to be the stream of integers, then this will be our desired stream int_pairs.)
（$S$と$T$の両方を整数のストリームとすれば、これが求めるストリーム int_pairsになります。）

Call the general stream of pairs pairs(S, T), and consider it to be composed of three parts: the pair $(S_0,T_0)$, the rest of the pairs in the first row, and the remaining pairs:
ペアの一般的なストリームを pairs(S, T) と呼ぶことにし、それを 3 つの部分から構成されると考えます。すなわち、ペア $(S_0,T_0)$、最初の行の残りのペア、そしてそれ以外のペアです。
[2] \[ \begin{array}{c|ccc} (S_0,T_0) & (S_0,T_1) & (S_0, T_2) & \ldots\\ \hline{} %--------------------------------------------------- \\ & (S_1,T_1) & (S_1, T_2) & \ldots\\ & & (S_2, T_2) & \ldots\\ & & & \ldots \end{array} \]
Observe that the third piece in this decomposition (pairs that are not in the first row) is (recursively) the pairs formed from stream_tail(S) and stream_tail(T). Also note that the second piece (the rest of the first row) is
この分解における 3 つ目の部分（最初の行にないペア）は、(再帰的に) stream_tail(S) と stream_tail(T) から作られるペアであることに注意してください。また、2 つ目の部分（最初の行の残り）は次のように書けることにも注意してください。
stream_map(x => list(head(s), x),
           stream_tail(t));
Thus we can form our stream of pairs as follows:
したがって、ペアのストリームは次のように作ることができます。
function pairs(s, t) { return pair(list(head(s), head(t)), () => $combine$-$in$-$some$-$way$( stream_map(x => list(head(s), x), stream_tail(t)), pairs(stream_tail(s), stream_tail(t)))); }

In order to complete the function, we must choose some way to combine the two inner streams. One idea is to use the stream analog of the append function from section 2.2.1:
この 関数 を完成させるには、内側の 2 つのストリームを組み合わせる方法を選ぶ必要があります。一つのアイデアは、2.2.1節の append 関数 に対応する版をストリームに対して使うというものです。
function stream_append(s1, s2) {
    return is_null(s1)
           ? s2
           : pair(head(s1), 
                  () => stream_append(stream_tail(s1), s2));
}
This is unsuitable for infinite streams, however, because it takes all the elements from the first stream before incorporating the second stream. In particular, if we try to generate all pairs of positive integers using
しかしこれは無限ストリームには適しません。なぜなら、2 つ目のストリームを取り込む前に 1 つ目のストリームのすべての要素を取り尽くしてしまうからです。特に、次のコードを使って正の整数のすべてのペアを生成しようとすると、
pairs(integers, integers);
our stream of results will first try to run through all pairs with the first integer equal to 1, and hence will never produce pairs with any other value of the first integer.
結果のストリームは、まず 1 つ目の整数が 1 に等しいすべてのペアを走査しようとしてしまい、したがって 1 つ目の整数が他の値を取るペアを決して生成しません。

To handle infinite streams, we need to devise an order of combination that ensures that every element will eventually be reached if we let our program run long enough. An elegant way to accomplish this is with the following interleave function:
無限ストリームを扱うには、プログラムを十分長く実行すれば結局どの要素にも到達することが保証されるような結合の順序を考案する必要があります。これをエレガントに実現する方法が、次の interleave 関数です。
[3] 
function interleave(s1, s2) {
    return is_null(s1)
           ? s2
           : pair(head(s1), 
                  () => interleave(s2, stream_tail(s1)));
}
Since interleave takes elements alternately from the two streams, every element of the second stream will eventually find its way into the interleaved stream, even if the first stream is infinite.
interleave は 2 つのストリームから交互に要素を取り出すので、たとえ 1 つ目のストリームが無限であっても、2 つ目のストリームのすべての要素は結局インターリーブされたストリームに入り込みます。

We can thus generate the required stream of pairs as
こうして、求めるペアのストリームを次のように生成できます。 
function pairs(s, t) {
    return pair(list(head(s), head(t)), 
                () => interleave(stream_map(x => list(head(s), x),
                                            stream_tail(t)),
                                 pairs(stream_tail(s), 
                                       stream_tail(t))));
}

Streams as signals
信号としてのストリーム

We began our discussion of streams by describing them as computational analogs of the signals in signal-processing systems. In fact, we can use streams to model signal-processing systems in a very direct way, representing the values of a signal at successive time intervals as consecutive elements of a stream. For instance, we can implement an integrator or summer that, for an input stream $x=(x_{i})$, an initial value $C$, and a small increment $dt$, accumulates the sum \[ \begin{array}{lll} S_i &=& C +\sum_{j=1}^{i} x_{j} \, dt \end{array} \] and returns the stream of values $S=(S_{i})$. The following integral function is reminiscent of the implicit style definition of the stream of integers (section 3.5.2):
ストリームに関する議論を始めたとき、私たちはストリームを信号処理システムにおける信号の計算上の対応物として説明しました。実際、ストリームを使えば信号処理システムを非常に直接的にモデル化でき、連続した時刻における信号の値をストリームの連続する要素として表現できます。たとえば、入力ストリーム$x=(x_{i})$、初期値 $C$、小さい増分$dt$に対して、次の和 \[ \begin{array}{lll} S_i &=& C +\sum_{j=1}^{i} x_{j} \, dt \end{array} \] を累積し、値のストリーム$S=(S_{i})$を返す積分器または加算器を実装できます。次のintegral関数は、整数のストリームの暗黙的なスタイルによる定義（3.5.2節）を彷彿とさせます。 
function integral(integrand, initial_value, dt) {
    const integ = pair(initial_value,
                       () => add_streams(scale_stream(integrand, dt),
                                         integ));
    return integ;
}

Figure 3.58 is a picture of a signal-processing system that corresponds to the integral function. The input stream is scaled by $dt$ and passed through an adder, whose output is passed back through the same adder. The self-reference in the definition of integ is reflected in the figure by the feedback loop that connects the output of the adder to one of the inputs.
図 3.58 は、integral関数に対応する信号処理システムを描いたものです。入力ストリームは$dt$でスケーリングされ、加算器を通り、その出力が同じ加算器に戻されます。integの定義における自己参照は、図中では加算器の出力をその入力の一つに接続するフィードバックループとして表現されています。
