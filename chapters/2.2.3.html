2.2.3  
Sequences as Conventional Interfaces
規約インターフェースとしてのシーケンス

In working with compound data, we've stressed how data abstraction permits us to design programs without becoming enmeshed in the details of data representations, and how abstraction preserves for us the flexibility to experiment with alternative representations. In this section, we introduce another powerful design principle for working with data structures—the use of conventional interfaces.
複合データを扱う中で、データ抽象がデータ表現の詳細に巻き込まれずにプログラムを設計することを可能にすること、そして抽象化が代替表現を試す柔軟性を保ってくれることを強調してきました。この節では、データ構造を扱うためのもう一つの強力な設計原理——規約インターフェースの使用——を導入します。

In section 1.3 we saw how program abstractions, implemented as higher-order functions, can capture common patterns in programs that deal with numerical data. Our ability to formulate analogous operations for working with compound data depends crucially on the style in which we manipulate our data structures. Consider, for example, the following function, analogous to the count_leaves function of section 2.2.2, which takes a tree as argument and computes the sum of the squares of the leaves that are odd:
節 1.3では、高階 関数 として実装されたプログラム抽象が、数値データを扱うプログラムの共通パターンを捉えられることを見ました。複合データを扱うための類似の操作を定式化する能力は、データ構造を操作するスタイルに大きく依存します。たとえば、節 2.2.2の count_leaves 関数 に類似した次の 関数 を考えてみましょう。これはツリーを引数として取り、奇数の葉の二乗の和を計算します： 
function sum_odd_squares(tree) {
    return is_null(tree)
           ? 0
           : ! is_pair(tree)
           ? is_odd(tree) ? square(tree) : 0
           : sum_odd_squares(head(tree)) +
             sum_odd_squares(tail(tree));
}
On the surface, this function is very different from the following one, which constructs a list of all the even Fibonacci numbers ${\textrm{Fib}}(k)$, where $k$ is less than or equal to a given integer $n$:
一見すると、この 関数 は、与えられた整数 $n$ 以下の $k$ に対するすべての偶数フィボナッチ数 ${\textrm{Fib}}(k)$ のリストを構築する次の 関数 とは大きく異なります： 
function even_fibs(n) {
    function next(k) {
        if (k > n) {
            return null;
        } else {
            const f = fib(k);
            return is_even(f)
                   ? pair(f, next(k + 1))
                   : next(k + 1);
        }
    }
    return next(0);
}

Despite the fact that these two functions are structurally very different, a more abstract description of the two computations reveals a great deal of similarity. The first program
  • enumerates the leaves of a tree;
  • filters them, selecting the odd ones;
  • squares each of the selected ones; and
  • accumulates the results using +, starting with 0.
The second program
  • enumerates the integers from 0 to $n$;
  • computes the Fibonacci number for each integer;
  • filters them, selecting the even ones; and
  • accumulates the results using pair, starting with the empty list.
この2つの 関数 は構造的に大きく異なりますが、2つの計算をより抽象的に記述すると多くの類似性が明らかになります。最初のプログラムは
  • ツリーの葉を列挙し、
  • 奇数のものを選んでフィルタリングし、
  • 選ばれた各要素を二乗し、
  • 0 から始めて + を使って結果を累積します。
2番目のプログラムは
  • 0 から $n$ までの整数を列挙し、
  • 各整数のフィボナッチ数を計算し、
  • 偶数のものを選んでフィルタリングし、
  • 空リストから始めて pair を使って結果を累積します。

A signal-processing engineer would find it natural to conceptualize these processes in terms of signals flowing through a cascade of stages, each of which implements part of the program plan, as shown in figure 2.14. In sum_odd_squares, we begin with an enumerator, which generates a signal consisting of the leaves of a given tree. This signal is passed through a filter, which eliminates all but the odd elements. The resulting signal is in turn passed through a map, which is a transducer that applies the square function to each element. The output of the map is then fed to an accumulator, which combines the elements using +, starting from an initial 0. The plan for even_fibs is analogous.
信号処理のエンジニアなら、これらのプロセスを、 図 2.14 に示すように、プログラム計画の各部分を実装するステージのカスケードを流れる信号として概念化するのが自然でしょう。 sum_odd_squares では、与えられたツリーの葉からなる「信号」を生成する 列挙子から始まります。この信号は奇数の要素以外をすべて除去する フィルタを通過します。結果の信号は次に、各要素に square 関数 を適用する「トランスデューサ」である マップを通過します。マップの出力は アキュムレータに渡され、初期値 0 から始めて + を使って要素を組み合わせます。 even_fibs の計画も同様です。

Unfortunately, the two function declarations above fail to exhibit this signal-flow structure. For instance, if we examine the sum_odd_squares function, we find that the enumeration is implemented partly by the is_null and is_pair tests and partly by the tree-recursive structure of the function. Similarly, the accumulation is found partly in the tests and partly in the addition used in the recursion. In general, there are no distinct parts of either function that correspond to the elements in the signal-flow description. Our two functions decompose the computations in a different way, spreading the enumeration over the program and mingling it with the map, the filter, and the accumulation. If we could organize our programs to make the signal-flow structure manifest in the functions we write, this would increase the conceptual clarity of the resulting program.
残念ながら、上の2つの 関数宣言 はこの信号フロー構造を示していません。たとえば、 sum_odd_squares 関数 を調べると、列挙は部分的に is_null と is_pair のテストで、部分的に 関数 のツリー再帰的構造で実装されていることがわかります。同様に、累積は部分的にテストの中に、部分的に再帰で使われる加算の中に見出されます。一般に、どちらの 関数 にも、信号フローの記述の各要素に対応する明確な部分がありません。2つの 関数 は計算を異なる方法で分解し、列挙をプログラム全体に分散させ、マップ、フィルタ、累積と混ぜ合わせています。書く 関数 の中で信号フロー構造を明示的にするようにプログラムを組織化できれば、結果の プログラム の概念的明確さが増すでしょう。

Sequence Operations
シーケンス操作

The key to organizing programs so as to more clearly reflect the signal-flow structure is to concentrate on the signals that flow from one stage in the process to the next. If we represent these signals as lists, then we can use list operations to implement the processing at each of the stages. For instance, we can implement the mapping stages of the signal-flow diagrams using the map function from section 2.2.1:
信号フロー構造をより明確に反映するようにプログラムを組織化する鍵は、プロセスのあるステージから次のステージへ流れる「信号」に注目することです。これらの信号をリストとして表現すれば、各ステージの処理をリスト操作で実装できます。たとえば、信号フロー図のマッピングステージは、節 2.2.1の map 関数 を使って実装できます： 
map(square, list(1, 2, 3, 4, 5));

list(1, 4, 9, 16, 25)

Filtering a sequence to select only those elements that satisfy a given predicate is accomplished by
与えられた述語を満たす要素だけを選択するためのシーケンスのフィルタリングは、次のようにして実現されます。 
function filter(predicate, sequence) {
    return is_null(sequence)
           ? null
           : predicate(head(sequence))
           ? pair(head(sequence),
                  filter(predicate, tail(sequence)))
           : filter(predicate, tail(sequence));
}
For example,
たとえば、 
filter(is_odd, list(1, 2, 3, 4, 5));

list(1, 3, 5)

Accumulations can be implemented by
累積は次のようにして実装できます。 
function accumulate(op, initial, sequence) {
    return is_null(sequence)
           ? initial
           : op(head(sequence),
                accumulate(op, initial, tail(sequence)));
}

accumulate(plus, 0, list(1, 2, 3, 4, 5));

15
accumulate(times, 1, list(1, 2, 3, 4, 5));

120
accumulate(pair, null, list(1, 2, 3, 4, 5));

list(1, 2, 3, 4, 5)

All that remains to implement signal-flow diagrams is to enumerate the sequence of elements to be processed. For even_fibs, we need to generate the sequence of integers in a given range, which we can do as follows:
信号フロー図を実装するために残っているのは、処理する要素のシーケンスを列挙することだけです。 even_fibs では、与えられた範囲の整数のシーケンスを生成する必要があり、次のようにして行えます： 
function enumerate_interval(low, high) {
    return low > high
           ? null
           : pair(low,
                  enumerate_interval(low + 1, high));
}

enumerate_interval(2, 7);

list(2, 3, 4, 5, 6, 7)
To enumerate the leaves of a tree, we can use
ツリーの葉を列挙するには、次を使えます。
[1] 
function enumerate_tree(tree) {
    return is_null(tree)
           ? null
           : ! is_pair(tree)
           ? list(tree)
           : append(enumerate_tree(head(tree)),
                    enumerate_tree(tail(tree)));
}

enumerate_tree(list(1, list(2, list(3, 4)), 5));

list(1, 2, 3, 4, 5)

Now we can reformulate sum_odd_squares and even_fibs as in the signal-flow diagrams. For sum_odd_squares, we enumerate the sequence of leaves of the tree, filter this to keep only the odd numbers in the sequence, square each element, and sum the results:
これで sum_odd_squares と even_fibs を信号フロー図のように再定式化できます。 sum_odd_squares では、ツリーの葉のシーケンスを列挙し、シーケンス内の奇数だけを残すようにフィルタリングし、各要素を二乗して結果を合計します： 
function sum_odd_squares(tree) {
    return accumulate(plus,
                      0,
                      map(square,
                          filter(is_odd,
                                 enumerate_tree(tree))));
}
For even_fibs, we enumerate the integers from 0 to $n$, generate the Fibonacci number for each of these integers, filter the resulting sequence to keep only the even elements, and accumulate the results into a list:
even_fibs では、0 から $n$ までの整数を列挙し、各整数のフィボナッチ数を生成し、結果のシーケンスをフィルタリングして偶数の要素だけを残し、結果をリストに累積します： 
function even_fibs(n) {
    return accumulate(pair,
                      null,
                      filter(is_even,
                             map(fib,
                                 enumerate_interval(0, n))));
}

The value of expressing programs as sequence operations is that this helps us make program designs that are modular, that is, designs that are constructed by combining relatively independent pieces. We can encourage modular design by providing a library of standard components together with a conventional interface for connecting the components in flexible ways.
プログラムをシーケンス操作として表現することの価値は、モジュール的なプログラム設計——比較的独立した部品を組み合わせて構築される設計——を行う助けになることです。標準的な部品のライブラリと、部品を柔軟に接続するための規約インターフェースを提供することで、モジュール的な設計を促進できます。

Modular construction is a powerful strategy for controlling complexity in engineering design. In real signal-processing applications, for example, designers regularly build systems by cascading elements selected from standardized families of filters and transducers. Similarly, sequence operations provide a library of standard program elements that we can mix and match. For instance, we can reuse pieces from the sum_odd_squares and even_fibs functions in a program that constructs a list of the squares of the first $n+1$ Fibonacci numbers:
モジュール的な構築は、 工学設計において複雑さを制御するための強力な戦略です。たとえば、実際の信号処理応用では、設計者は標準化されたフィルタとトランスデューサのファミリーから選んだ要素をカスケード接続してシステムを構築するのが常です。同様に、シーケンス操作は標準的なプログラム要素のライブラリを提供し、自由に組み合わせることができます。たとえば、最初の $n+1$ 個のフィボナッチ数の二乗のリストを構築するプログラムで、 sum_odd_squares や even_fibs 関数 の部品を再利用できます： 
function list_fib_squares(n) {
    return accumulate(pair,
                      null,
                      map(square,
                          map(fib,
                              enumerate_interval(0, n))));
}

list_fib_squares(10);

list(0, 1, 1, 4, 9, 25, 64, 169, 441, 1156, 3025)
We can rearrange the pieces and use them in computing the product of the squares of the odd integers in a sequence:
部品を並べ替えて、シーケンス内の奇数の二乗の積を計算するのに使うこともできます： 
function product_of_squares_of_odd_elements(sequence) {
    return accumulate(times,
                      1,
                      map(square,

We can extend the sequence paradigm to include many computations that are commonly expressed using nested loops.
シーケンスパラダイムを拡張して、入れ子のループで一般的に表現される多くの計算を含めることができます。

Consider this problem: Given a positive integer $n$, find all ordered pairs of distinct positive integers $i$ and $j$, where $1\leq j < i\leq n$, such that $i +j$ is prime. For example, if $n$ is 6, then the pairs are the following: \[ \begin{array}{c|ccccccc} i & 2 & 3 & 4 & 4 & 5 & 6 & 6 \\ j & 1 & 2 & 1 & 3 & 2 & 1 & 5 \\ \hline i+j & 3 & 5 & 5 & 7 & 7 & 7 & 11 \end{array} \] A natural way to organize this computation is to generate the sequence of all ordered pairs of positive integers less than or equal to $n$, filter to select those pairs whose sum is prime, and then, for each pair $(i, j)$ that passes through the filter, produce the triple $(i, j, i+j)$.
次の問題を考えてみましょう：正の整数 $n$ が与えられたとき、$1\leq j < i\leq n$ で $i +j$ が素数であるような、異なる正の整数の順序付きペア $i$ と $j$ をすべて見つけてください。たとえば、$n$ が 6 なら、ペアは次の通りです： \[ \begin{array}{c|ccccccc} i & 2 & 3 & 4 & 4 & 5 & 6 & 6 \\ j & 1 & 2 & 1 & 3 & 2 & 1 & 5 \\ \hline i+j & 3 & 5 & 5 & 7 & 7 & 7 & 11 \end{array} \] この計算を組織化する自然な方法は、$n$ 以下の正の整数のすべての順序付きペアのシーケンスを生成し、和が素数であるペアを選択するようにフィルタリングし、フィルタを通過した各ペア $(i, j)$ に対して三つ組 $(i, j, i+j)$ を生成することです。

Here is a way to generate the sequence of pairs: For each integer $i\leq n$, enumerate the integers $j < i$, and for each such $i$ and $j$ generate the pair $(i, j)$. In terms of sequence operations, we map along the sequence enumerate_interval(1, n). For each $i$ in this sequence, we map along the sequence enumerate_interval(1, i - 1). For each $j$ in this latter sequence, we generate the pair list(i, j). This gives us a sequence of pairs for each $i$. Combining all the sequences for all the $i$ (by accumulating with append) produces the required sequence of pairs:
ペアのシーケンスを生成する方法はこうです：各整数 $i\leq n$ に対して、整数 $j < i$ を列挙し、各 $i$ と $j$ に対してペア $(i, j)$ を生成します。シーケンス操作の観点では、シーケンス enumerate_interval(1, n) に沿ってマップします。このシーケンスの各 $i$ に対して、シーケンス enumerate_interval(1, i - 1) に沿ってマップします。この後者のシーケンスの各 $j$ に対して、ペア list(i, j) を生成します。これにより各 $i$ に対するペアのシーケンスが得られます。すべての $i$ に対するすべてのシーケンスを（append で累積して）結合すると、必要なペアのシーケンスが得られます：

           null,

                        enumerate_interval(1, i - 1)),

マッピングと append による累積の組み合わせはこの種のプログラムでは非常に一般的なので、別の 関数 として分離します：

The eight-queens puzzle asks how to place eight queens on a chessboard so that no queen is in check from any other (i.e., no two queens are in the same row, column, or diagonal). One possible solution is shown in figure 2.15. One way to solve the puzzle is to work across the board, placing a queen in each column. Once we have placed $k-1$ queens, we must place the $k$th queen in a position where it does not check any of the queens already on the board. We can formulate this approach recursively: Assume that we have already generated the sequence of all possible ways to place $k-1$ queens in the first $k-1$ columns of the board. For each of these ways, generate an extended set of positions by placing a queen in each row of the $k$th column. Now filter these, keeping only the positions for which the queen in the $k$th column is safe with respect to the other queens. This produces the sequence of all ways to place $k$ queens in the first $k$ columns. By continuing this process, we will produce not only one solution, but all solutions to the puzzle.
「8クイーン問題」は、8つのクイーンをチェス盤上に、どのクイーンも他のクイーンに攻撃されないように（つまり、2つのクイーンが同じ行、列、または対角線上にないように）配置する方法を問うものです。一つの解が図 2.15に示されています。この問題を解く一つの方法は、盤を横に進みながら各列にクイーンを配置することです。$k-1$ 個のクイーンを配置したら、$k$ 番目のクイーンをすでに盤上にあるどのクイーンも攻撃しない位置に配置しなければなりません。このアプローチを再帰的に定式化できます：盤の最初の $k-1$ 列に $k-1$ 個のクイーンを配置するすべての可能な方法のシーケンスをすでに生成したと仮定します。これらの各方法に対して、$k$ 列目の各行にクイーンを配置することで、位置の拡張された集合を生成します。次に、$k$ 列目のクイーンが他のクイーンに対して安全である位置だけを残すようにフィルタリングします。これにより、最初の $k$ 列に $k$ 個のクイーンを配置するすべての方法のシーケンスが得られます。このプロセスを続けることで、1つの解だけでなくパズルのすべての解が生成されます。

We implement this solution as a function queens, which returns a sequence of all solutions to the problem of placing $n$ queens on an $n\times n$ chessboard. The function queens has an internal function queens_cols that returns the sequence of all ways to place queens in the first $k$ columns of the board.
この解を、$n\times n$ のチェス盤上に $n$ 個のクイーンを配置する問題のすべての解のシーケンスを返す 関数 queens として実装します。 関数 queens は、盤の最初の $k$ 列にクイーンを配置するすべての方法のシーケンスを返す内部 関数 queens_cols を持っています。 
function queens(board_size) {
    function queen_cols(k) {
        return k === 0
               ? list(empty_board)
               : filter(positions => is_safe(k, positions),
                        flatmap(rest_of_queens =>
                                  map(new_row =>
                                        adjoin_position(new_row, k,
                                                        rest_of_queens),
                                      enumerate_interval(1, board_size)),
                                queen_cols(k - 1)));
    }
    return queen_cols(board_size);
}
In this function rest_of_queens is a way to place $k-1$ queens in the first $k-1$ columns, and new_row is a proposed row in which to place the queen for the $k$th column. Complete the program by implementing the representation for sets of board positions, including the function adjoin_position, which adjoins a new row-column position to a set of positions, and empty_board, which represents an empty set of positions. You must also write the function is_safe, which determines for a set of positions whether the queen in the $k$th column is safe with respect to the others. (Note that we need only check whether the new queen is safe—the other queens are already guaranteed safe with respect to each other.)
この 関数 では、 rest_of_queens は最初の $k-1$ 列に $k-1$ 個のクイーンを配置する方法で、 new_row は $k$ 列目のクイーンを配置する行の候補です。盤上の位置の集合の表現を実装してプログラムを完成させてください。これには、新しい行-列の位置を位置の集合に付加する 関数 adjoin_position と、空の位置集合を表す empty_board が含まれます。また、位置の集合に対して $k$ 列目のクイーンが他のクイーンに対して安全かどうかを判定する 関数 is_safe も書く必要があります（新しいクイーンが安全かどうかだけをチェックすればよいことに注意してください。他のクイーン同士はすでに安全であることが保証されています）。 

function adjoin_position(row, col, rest) {
    return pair(pair(row, col), rest);
}

const empty_board = null;

function is_safe(k, positions) {
    const first_row = head(head(positions));
    const first_col = tail(head(positions));
    return accumulate((pos, so_far) => {
                         const row = head(pos);
                         const col = tail(pos);
                         return so_far &&
                                first_row - first_col !==
                                row - col &&
                                first_row + first_col !==
                                row + col &&
                                first_row !== row;
                      },
                      true,
                      tail(positions));
}

According to Knuth (1997b), this rule was formulated by W. G. Horner early in the nineteenth century, but the method was actually used by Newton over a hundred years earlier. Horner's rule evaluates the polynomial using fewer additions and multiplications than does the straightforward method of first computing $a_{n} x^n$, then adding $a_{n-1}x^{n-1}$, and so on.
