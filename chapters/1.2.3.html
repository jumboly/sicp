1.2.3  
Orders of Growth
増加のオーダー

The previous examples illustrate that processes can differ considerably in the rates at which they consume computational resources. One convenient way to describe this difference is to use the notion of order of growth to obtain a gross measure of the resources required by a process as the inputs become larger.
前の例は、プロセスが計算資源を消費する速度に大きな違いがありうることを示しました。この違いを記述する便利な方法は、 増加のオーダーの概念を使って、入力が大きくなるにつれてプロセスが必要とする 資源の大まかな尺度を得ることです。

Let $n$ be a parameter that measures the size of the problem, and let $R(n)$ be the amount of resources the process requires for a problem of size $n$. In our previous examples we took $n$ to be the number for which a given function is to be computed, but there are other possibilities. For instance, if our goal is to compute an approximation to the square root of a number, we might take $n$ to be the number of digits accuracy required. For matrix multiplication we might take $n$ to be the number of rows in the matrices. In general there are a number of properties of the problem with respect to which it will be desirable to analyze a given process. Similarly, $R(n)$ might measure the number of internal storage registers used, the number of elementary machine operations performed, and so on. In computers that do only a fixed number of operations at a time, the time required will be proportional to the number of elementary machine operations performed.
$n$ を問題のサイズを測るパラメータとし、$R(n)$ をサイズ $n$ の問題に対してプロセスが必要とする資源の量とします。前の例では $n$ を与えられた関数を計算する対象の数としましたが、他の可能性もあります。たとえば、数の平方根の近似値を計算することが目的なら、$n$ を必要な精度の桁数とするかもしれません。行列の乗算なら、$n$ を行列の行数とするかもしれません。一般に、与えられたプロセスを分析する際に注目したい問題の性質はいくつかあります。同様に、$R(n)$ は使用される内部記憶レジスタの数、実行される基本的な機械操作の数などを測るかもしれません。一度に固定数の操作しか行わないコンピュータでは、必要な時間は実行される基本的な機械操作の数に比例します。

We say that $R(n)$ has order of growth $\Theta(f(n))$, written $R(n)=\Theta(f(n))$ (pronounced theta of $f(n)$), if there are positive constants $k_1$ and $k_2$ independent of $n$ such that
$R(n)$ の増加のオーダーが $\Theta(f(n))$ であるとは、$R(n)=\Theta(f(n))$ と書き（「シータ $f(n)$」と読みます）、$n$ に依存しない正の定数 $k_1$ と $k_2$ が存在して、
\[ \begin{array}{lllll} k_1\,f(n) & \leq & R(n) & \leq & k_2\,f(n) \end{array} \]
for any sufficiently large value of $n$. (In other words, for large $n$, the value $R(n)$ is sandwiched between $k_1f(n)$ and $k_2f(n)$.)
が十分大きな $n$ のすべてに対して成り立つことです。（言い換えれば、大きな $n$ に対して、$R(n)$ の値は $k_1f(n)$ と $k_2f(n)$ の間に挟まれます。）

For instance, with the linear recursive process for computing factorial described in section 1.2.1 the number of steps grows proportionally to the input $n$. Thus, the steps required for this process grows as $\Theta(n)$. We also saw that the space required grows as $\Theta(n)$. For the iterative factorial, the number of steps is still $\Theta(n)$ but the space is $\Theta(1)$—that is, constant.
たとえば、1.2.1節で述べた階乗を計算する線形再帰的プロセスでは、ステップ数は入力 $n$ に比例して増加します。したがって、このプロセスに必要なステップは $\Theta(n)$ で増加します。必要な空間も $\Theta(n)$ で増加することも見ました。 反復的な階乗では、ステップ数はやはり $\Theta(n)$ ですが、空間は $\Theta(1)$—つまり定数です。
[1]
The tree-recursive Fibonacci computation requires $\Theta(\phi^{n})$ steps and space $\Theta(n)$, where $\phi$ is the golden ratio described in section 1.2.2.
ツリー再帰的なフィボナッチ計算は $\Theta(\phi^{n})$ のステップと $\Theta(n)$ の空間を必要とします。ここで $\phi$ は 1.2.2節で述べた黄金比です。

Orders of growth provide only a crude description of the behavior of a process. For example, a process requiring $n^2$ steps and a process requiring $1000n^2$ steps and a process requiring $3n^2+10n+17$ steps all have $\Theta(n^2)$ order of growth. On the other hand, order of growth provides a useful indication of how we may expect the behavior of the process to change as we change the size of the problem. For a $\Theta(n)$ (linear) process, doubling the size will roughly double the amount of resources used. For an exponential process, each increment in problem size will multiply the resource utilization by a constant factor. In the remainder of section 1.2 we will examine two algorithms whose order of growth is logarithmic, so that doubling the problem size increases the resource requirement by a constant amount.
増加のオーダーは、プロセスの振る舞いの大まかな記述しか提供しません。たとえば、$n^2$ ステップを必要とするプロセスと $1000n^2$ ステップを必要とするプロセスと $3n^2+10n+17$ ステップを必要とするプロセスは、すべて $\Theta(n^2)$ の増加のオーダーを持ちます。一方で、増加のオーダーは、問題のサイズを変えたときにプロセスの振る舞いがどう変わるかを予測するのに有用な指標を提供します。 $\Theta(n)$（線形）のプロセスでは、サイズを倍にすると使用する資源もおよそ倍になります。 指数的なプロセスでは、問題のサイズが1つ増えるごとに資源の使用量が定数倍になります。1.2節の残りでは、増加のオーダーが 対数的であるアルゴリズムを2つ調べます。つまり、問題のサイズを倍にしても資源の要件は一定量しか増えません。

Exercise 1.14
Draw the tree illustrating the process generated by the count_change function of section 1.2.2 in making change for 11 cents. What are the orders of growth of the space and number of steps used by this process as the amount to be changed increases?
1.2.2節の count_change 関数が 11 セントの両替で生成するプロセスを図示するツリーを描いてください。両替する金額が増加するとき、このプロセスが使用する空間とステップ数の増加のオーダーはどうなりますか。
The tree-recursive process generated in computing cc(11, 5) is illustrated by the image below, due to Toby Thain, assuming that the coin values in first_denomination are $\mathbb{C}_{1} = 1$, $\mathbb{C}_{2} = 5$, $\mathbb{C}_{3} = 10$, $\mathbb{C}_{4} = 25$ and $\mathbb{C}_{5} = 50$.
cc(11, 5) の計算で生成されるツリー再帰的プロセスは、以下の画像に示されています（Toby Thain による）。first_denomination の硬貨の値は $\mathbb{C}_{1} = 1$、$\mathbb{C}_{2} = 5$、$\mathbb{C}_{3} = 10$、$\mathbb{C}_{4} = 25$、$\mathbb{C}_{5} = 50$ と仮定しています。
Let us consider the process for evaluating cc(n, k), which means the amount to be changed is n and the number of kinds of coins is k. Let us assume the coin values are constants, not dependent on n or k.

The space required for a tree-recursive process is—as discussed in section 1.2.2—proportional to the maximum depth of the tree. At each step from a parent to a child in the tree, either n strictly decreases (by a constant coin value) or k decreases (by 1), and leaf nodes have an amount of at most 0 or a number of kinds of coins of 0. Thus, every path has a length of $\Theta(n + k)$, which is also the order of growth of the space required for cc(n, k).

Let us derive a function $T(n, k)$ such that the time required for calculating cc(n, k) has an order of growth of $\Theta(T(n, k))$. The following argument is due to Yati Sagade, including the illustrations (Sagade 2015). Let us start with the call tree for changing some amount $n$ with just 1 kind of coin, i.e., the call tree for cc(n, 1).
cc(n, k) を評価するプロセスを考えましょう。つまり、両替する金額が n で、硬貨の種類数が k です。硬貨の値は n や k に依存しない定数と仮定します。

ツリー再帰的プロセスに必要な空間は—1.2.2節で議論したように—ツリーの最大深さに比例します。ツリーの親から子への各ステップで、n が（定数の硬貨の値だけ）厳密に減少するか、k が（1だけ）減少します。葉ノードの金額は最大で 0 か、硬貨の種類数が 0 です。したがって、すべてのパスの長さは $\Theta(n + k)$ であり、これは cc(n, k) に必要な空間の増加のオーダーでもあります。

cc(n, k) の計算に必要な時間の増加のオーダーが $\Theta(T(n, k))$ となるような関数 $T(n, k)$ を導出しましょう。以下の議論は図を含めて Yati Sagade によるものです（Sagade 2015）。ある金額 $n$ を 1 種類の硬貨だけで両替する場合の呼び出しツリー、つまり cc(n, 1) の呼び出しツリーから始めましょう。
We are only allowed here to use one kind of coin, with value $\mathbb{C}_{1} = 1$. The red nodes are terminal nodes that yield 0, the green node is a terminal node that yields 1 (corresponding to the first condition in the declaration of cc). Each nonterminal node spawns two calls to cc, one (on the left) with the same amount, but fewer kinds of coins, and the other (on the right) with the amount reduced by 1 and equal kinds of coins.

Excluding the root, each level has exactly 2 nodes, and there are $n$ such levels. This means, the number of cc calls generated by a single cc(n, 1) call (including the original call) is:
ここでは値 $\mathbb{C}_{1} = 1$ の 1 種類の硬貨しか使えません。赤いノードは 0 を返す末端ノードであり、緑のノードは 1 を返す末端ノードです（cc の宣言の最初の条件に対応）。各非末端ノードは cc への 2 つの呼び出しを生成します。1 つ（左側）は同じ金額でより少ない種類の硬貨、もう 1 つ（右側）は金額を 1 減らして同じ種類の硬貨です。

ルートを除くと、各レベルにはちょうど 2 つのノードがあり、そのようなレベルは $n$ 個あります。つまり、1 回の cc(n, 1) 呼び出し（元の呼び出しを含む）が生成する cc の呼び出し回数は次のとおりです。
\[ T(n,1) = 2n + 1 = \Theta(n) \]
Next, we will look at the call tree of cc(n, 2) to calculate $T(n,2)$:
次に、$T(n,2)$ を計算するために cc(n, 2) の呼び出しツリーを見てみましょう。
Here, we are allowed to use two denominations of coins: $\mathbb{C}_{2} = 5$ and $\mathbb{C}_{1} = 1$.

Each black node spawns a cc(m, 1) subtree (blue), which we’ve already analyzed, and a cc(m - 5, 2) subtree. The node colored in red and green is a terminal node, but yields 0 if the amount is less than zero and 1 if the amount is exactly zero. Sagade denotes this final amount as $\epsilon$, which can be $\le0$.

Excluding the root and and the last level in this tree which contains the red-green terminal node, there will be exactly $\big\lfloor {\frac {n} {5}} \big\rfloor$ levels. Now each of these levels contains a call to cc(m, 1) (the blue nodes), each of which, in turn, is $\Theta(n)$ in time. So each of these levels contains $T(n,1) + 1$ calls to cc. Therefore, the total number of nodes (including the terminal node and the root) in the call tree for cc(n, 2) is:
ここでは 2 種類の額面の硬貨を使えます：$\mathbb{C}_{2} = 5$ と $\mathbb{C}_{1} = 1$ です。

各黒ノードは、すでに分析済みの cc(m, 1) サブツリー（青）と cc(m - 5, 2) サブツリーを生成します。赤と緑に色付けされたノードは末端ノードですが、金額が 0 未満なら 0 を、ちょうど 0 なら 1 を返します。Sagade はこの最終的な金額を $\epsilon$ と表記し、$\le0$ となりえます。

ルートと赤緑の末端ノードを含む最後のレベルを除くと、ちょうど $\big\lfloor {\frac {n} {5}} \big\rfloor$ レベルあります。各レベルには cc(m, 1)（青ノード）への呼び出しが含まれ、それぞれの時間計算量は $\Theta(n)$ です。したがって各レベルには $T(n,1) + 1$ 回の cc 呼び出しが含まれます。よって、cc(n, 2) の呼び出しツリーのノード総数（末端ノードとルートを含む）は次のとおりです。
\[ T(n,2) = \big\lfloor {\frac {n} {5} } \big\rfloor ( T(n,1) + 1) + 2 = \big\lfloor {\frac {n} {5} } \big\rfloor ( 2n + 2 ) + 2 = \Theta(n^2) \]
Moving ahead, let’s take a look at the call tree of cc(n, 3), i.e., we are now allowed to use three denominations of coins, the new addition being $\mathbb{C}_{3} = 10$:
先に進んで、cc(n, 3) の呼び出しツリーを見てみましょう。つまり、3 種類の額面の硬貨を使え、新たに $\mathbb{C}_{3} = 10$ が加わります。
Here also, we see, similar to the previous case, that the total number of calls to cc will be
ここでも前の場合と同様に、cc への呼び出し総数は次のようになることがわかります。
\[ T(n,3) = \big\lfloor {\frac {n} {10} } \big\rfloor ( T(n,2) + 1) + 2 = \big\lfloor {\frac {n} {10} } \big\rfloor \times \Theta(n^2) + 2 = \Theta(n^3) \]
We can see a pattern here. For some $k$, $k \gt 1$, we have,
ここにパターンが見えます。ある $k$（$k \gt 1$）について、
\[ T(n,k) = \big\lfloor {\frac {n} { \mathbb{C}_{k} } } \big\rfloor ( T(n, k-1) + 1) + 2 \]
Here, $\mathbb{C}_{k}$ is the $k^{th}$ coin denomination. We can expand this further:
ここで $\mathbb{C}_{k}$ は $k$ 番目の硬貨の額面です。これをさらに展開できます。
\[ T(n,k) = \big\lfloor {\frac {n} { \mathbb{C}_{k} } } \big\rfloor ( T(n, k-1) + 1 ) + 2 = \big\lfloor {\frac {n} { \mathbb{C}_{k} } } \big\rfloor ( \big\lfloor {\frac {n} { \mathbb{C}_{k-1} } } \big\rfloor (... \big\lfloor \frac {n} { \mathbb{C}_{2} } \big\rfloor (2n+1) ...) ) + 2 = \Theta(n^k) \]
Note that the actual values of the coin denominations have no effect on the order of growth of this process, if we assume they are constants that do not depend on n and k.
硬貨の額面の実際の値は、n と k に依存しない定数であると仮定する限り、このプロセスの増加のオーダーに影響しないことに注意してください。
Exercise 1.15
The sine of an angle (specified in radians) can be computed by making use of the approximation $\sin x\approx x$ if $x$ is sufficiently small, and the trigonometric identity
角度（ラジアンで指定）の正弦は、$x$ が十分小さい場合の近似 $\sin x\approx x$ と、三角関数の恒等式
\[ \begin{array}{lll} \sin x &=& 3\sin {\dfrac{x}{3}}-4\sin^3{\dfrac{x}{3}} \end{array} \]
to reduce the size of the argument of $\sin$. (For purposes of this exercise an angle is considered sufficiently small if its magnitude is not greater than 0.1 radians.) These ideas are incorporated in the following functions:
を使って $\sin$ の引数のサイズを縮小することで計算できます。（この演習では、大きさが 0.1 ラジアン以下の角度を「十分小さい」とみなします。）これらのアイデアは次の関数に組み込まれています。 
function cube(x) {
    return x * x * x;
}
function p(x) {
    return 3 * x - 4 * cube(x);
}
function sine(angle) {
    return ! (abs(angle) > 0.1)
           ? angle
           : p(sine(angle / 3));
}
  1. How many times is the function p applied when sine(12.15) is evaluated?
  2. What is the order of growth in space and number of steps (as a function of $a$) used by the process generated by the sine function when sine(a) is evaluated?
  1. sine(12.15) が評価されるとき、関数 p は何回適用されますか。
  2. sine(a) が評価されるとき、sine 関数が生成するプロセスが使用する空間とステップ数の増加のオーダー（$a$ の関数として）はどうなりますか。

  1. The function p will call itself recursively as long as the angle value is greater than 0.1. There will be altogether 5 calls of p, with arguments 12.15, 4.05, 1.35, 0.45, 0.15 and 0.05.
  2. The function sine gives rise to a recursive process. In each recursive call, the angle is divided by 3 until its absolute value is smaller than 0.1. Thus the number of steps and the space required has an order of growth of $O(\log a)$. Note that the base of the logarithm is immaterial for the order of growth because the logarithms of different bases differ only by a constant factor.
  1. 関数 p は、角度の値が 0.1 より大きい間は再帰的に呼び出されます。引数 12.15、4.05、1.35、0.45、0.15、0.05 で合計 5 回の p の呼び出しがあります。
  2. 関数 sine は再帰的プロセスを生じます。各再帰呼び出しで angle は 3 で割られ、絶対値が 0.1 より小さくなるまで続きます。したがって、ステップ数と必要な空間の増加のオーダーは $O(\log a)$ です。対数の底は増加のオーダーには関係ありません。異なる底の対数は定数倍しか異ならないからです。

[1]
These statements mask a great deal of oversimplification. For instance, if we count process steps as machine operations we are making the assumption that the number of machine operations needed to perform, say, a multiplication is independent of the size of the numbers to be multiplied, which is false if the numbers are sufficiently large. Similar remarks hold for the estimates of space. Like the design and description of a process, the analysis of a process can be carried out at various levels of abstraction.
これらの記述は大幅な単純化を隠しています。たとえば、プロセスのステップを「機械操作」として数えるなら、乗算を実行するのに必要な機械操作の数が乗算される数のサイズに依存しないと仮定していることになりますが、数が十分大きければこれは偽です。空間の見積もりについても同様のことが言えます。プロセスの設計と記述と同様に、プロセスの分析もさまざまな抽象化のレベルで行うことができます。
