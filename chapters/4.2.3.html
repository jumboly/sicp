4.2.3  
Streams as Lazy Lists
遅延リストとしてのストリーム

In section 3.5.1, we showed how to implement streams as delayed lists. We used a lambda expression to construct a promise to compute the tail of a stream, without actually fulfilling that promise until later. We were forced to create streams as a new kind of data object similar but not identical to lists, and this required us to reimplement many ordinary list operations (map, append, and so on) for use with streams.
 3.5.1節では、ストリームを遅延リストとして実装する方法を示しました。 ラムダ式を使って ストリームの tail を計算する 「プロミス」を構築しましたが、そのプロミスの実行は後で必要になるまで先延ばしにしていました。 ストリームをリストに似ているが同一ではない新しい種類のデータオブジェクトとして作成しなければならず、そのために通常のリスト操作（map、appendなど）の多くをストリーム用に再実装する必要がありました。

With lazy evaluation, streams and lists can be identical, so there is no need for separate list and stream operations. All we need to do is to arrange matters so that pair is non-strict. One way to accomplish this is to extend the lazy evaluator to allow for non-strict primitives, and to implement pair as one of these. An easier way is to recall (section 2.1.3) that there is no fundamental need to implement pair as a primitive at all. Instead, we can represent pairs as functions:
遅延評価を使えば、ストリームとリストを同一にできるので、リストとストリームを別々に操作する必要もなくなります。必要なのは、 pair を非正格にすることだけです。これを実現する一つの方法は、遅延評価器を拡張して非正格なプリミティブを許容し、 pair をその一つとして実装することです。より簡単な方法は、（ 2.1.3節を思い出すと） pair をプリミティブとして実装する根本的な必要性はないということです。代わりに、 ペアを関数として表現できます。
[1] 
function pair(x, y) {
    return m => m(x, y);
}
function head(z) {
    return z((p, q) => p);
}
function tail(z) {
    return z((p, q) => q);
}

In terms of these basic operations, the standard definitions of the list operations will work with infinite lists (streams) as well as finite ones, and the stream operations can be implemented as list operations. Here are some examples:
これらの基本操作を使えば、リスト操作の標準的な定義が有限リストだけでなく無限リスト（ストリーム）でも機能し、ストリーム操作をリスト操作として実装できます。いくつかの例を示します。 
function list_ref(items, n) {
    return n === 0
           ? head(items)
           : list_ref(tail(items), n - 1);
}
function map(fun, items) {
    return is_null(items)
           ? null
           : pair(fun(head(items)),
                  map(fun, tail(items)));
}
function scale_list(items, factor) {
    return map(x => x * factor, items);
}
function add_lists(list1, list2) {
    return is_null(list1)
           ? list2
           : is_null(list2)
           ? list1
           : pair(head(list1) + head(list2),
                  add_lists(tail(list1), tail(list2)));
}
const ones = pair(1, ones);
const integers = pair(1, add_lists(ones, integers));
L-evaluate input:
list_ref(integers, 17);
L-evaluate value:
18

Note that these lazy lists are even lazier than the streams of chapter 3: The head of the list, as well as the tail, is delayed.
これらの遅延リストは、第 3章のストリームよりもさらに遅延的であることに注意してください。リストの head も tail も遅延されます。
[2]
In fact, even accessing the head or tail of a lazy pair need not force the value of a list element. The value will be forced only when it is really needed—e.g., for use as the argument of a primitive, or to be printed as an answer.
実際、遅延ペアの head や tail にアクセスしても、リスト要素の値を強制する必要はありません。値が強制されるのは、本当に必要になったとき—例えば、プリミティブの引数として使われるときや、回答として表示されるときだけです。

Lazy pairs also help with the problem that arose with streams in section 3.5.4, where we found that formulating stream models of systems with loops may require us to sprinkle our programs with additional lambda expressions for delays, beyond the ones required to construct a stream pair. With lazy evaluation, all arguments to functions are delayed uniformly. For instance, we can implement functions to integrate lists and solve differential equations as we originally intended in section 3.5.4:
遅延ペアは、 3.5.4節でストリームに関して生じた問題にも役立ちます。その節では、ループを持つシステムのストリームモデルを定式化するには、プログラム中に ストリームペアを構築するために必要なもの以上の、遅延のための追加のラムダ式 を散りばめる必要があるかもしれないことがわかりました。遅延評価では、 関数 へのすべての引数が一様に遅延されます。例えば、 3.5.4節で当初意図していたように、リストの積分や微分方程式の解法を行う 関数 を実装できます。 
function integral(integrand, initial_value, dt) {
    const int = pair(initial_value,
                     add_lists(scale_list(integrand, dt),
                               int));
    return int;
}
function solve(f, y0, dt) {
    const y = integral(dy, y0, dt);
    const dy = map(f, y);
    return y;
}
L-evaluate input:
list_ref(solve(x => x, 1, 0.001), 1000);
L-evaluate value:
2.716924

Exercise 4.31
Ben Bitdiddle tests the lazy list implementation given above by evaluating the expression
Ben Bitdiddle は、上記の遅延リストの実装を次の式を評価してテストします。 
head(list("a", "b", "c"));
To his surprise, this produces an error. After some thought, he realizes that the lists obtained from the primitive list function are different from the lists manipulated by the new definitions of pair, head, and tail. Modify the evaluator such that applications of the primitive list function typed at the driver loop will produce true lazy lists.
驚いたことに、これはエラーが発生します。しばらく考えた後、彼は プリミティブの list 関数から 得られる「リスト」は、 pair、 head、 tail の新しい定義で操作されるリストとは異なることに気づきます。ドライバループで入力された プリミティブの list 関数の適用が 真の遅延リストを生成するように、評価器を修正してください。

Notice that we can install these definitions in the lazy evaluator simply by typing them at the driver loop. If we had originally included pair, head, and tail as primitives in the global environment, they will be redefined. (Also see exercises 4.31 and 4.32.)
これは練習問題 2.4で説明した 関数的 表現です。基本的にどのような 関数的 表現（例えばメッセージパッシングによる実装）でも同様に機能します。これらの定義は、ドライバループで入力するだけで遅延評価器にインストールできることに注目してください。もともとグローバル環境に pair、 head、 tail がプリミティブとして含まれていた場合、それらは再定義されます。（練習問題 4.31と 4.32も参照してください。）

This permits us to create delayed versions of more general kinds of list structures, not just sequences. Hughes 1990 discusses some applications of lazy trees.
これにより、シーケンスだけでなく、より一般的な種類のリスト構造の遅延版を作成できます。 Hughes 1990では、 「遅延ツリー」のいくつかの応用について論じています。
