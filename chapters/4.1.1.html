4.1.1  
The Core of the Evaluator
評価器の中核

The evaluation process can be described as the interplay between two functions: evaluate and apply.
評価のプロセスは、二つの関数evaluateとapplyのあいだのやりとりとして記述できます。

The function evaluate

The function evaluate takes as arguments a program component—a statement or expression—and an environment. It classifies the component and directs its evaluation. The function evaluate is structured as a case analysis of the syntactic type of the component to be evaluated. In order to keep the function general, we express the determination of the type of a component abstractly, making no commitment to any particular representation for the various types of components. Each type of component has a syntax predicate that tests for it and an abstract means for selecting its parts. This abstract syntax makes it easy to see how we can change the syntax of the language by using the same evaluator, but with a different collection of syntax functions.
関数evaluateは、引数としてプログラムのコンポーネント（文または式）と環境を受け取ります。evaluateはそのコンポーネントを分類し、その評価を進めていきます。関数evaluateは、評価対象のコンポーネントの構文的な型に対する場合分けとして構成されています。この関数を一般的なものに保つために、コンポーネントの型を判定する処理は抽象的に表現し、さまざまな型のコンポーネントの具体的な表現方法には踏み込まないようにします。それぞれの型のコンポーネントには、その型かどうかを判定する構文述語と、その構成要素を取り出す抽象的な手段が用意されています。この抽象構文のおかげで、同じ評価器を使いつつ、異なる構文関数の集合に差し替えるだけで言語の構文を変更できることが、容易に見て取れます。
[1]

Primitive expressions

  • For literal expressions, such as numbers, evaluate returns their value.
  • The function evaluate must look up names in the environment to find their values.

Combinations

  • For a function application, evaluate must recursively evaluate the function expression and the argument expressions of the application. The resulting function and arguments are passed to apply, which handles the actual function application.
  • An operator combination is transformed into a function application and then evaluated.

Syntactic forms

  • A conditional expression or statement requires special processing of its parts, so as to evaluate the consequent if the predicate is true, and otherwise to evaluate the alternative.
  • A lambda expression must be transformed into an applicable function by packaging together the parameters and body specified by the lambda expression with the environment of the evaluation.
  • A sequence of statements requires evaluating its components in the order in which they appear.
  • A block requires evaluating its body in a new environment that reflects all names declared within the block.
  • A return statement must produce a value that becomes the result of the function call that gave rise to the evaluation of the return statement.
  • A function declaration is transformed into a constant declaration and then evaluated.
  • A constant or variable declaration or an assignment must call evaluate recursively to compute the new value to be associated with the name being declared or assigned. The environment must be modified to reflect the new value of the name.
Here is the declaration of evaluate:
  • 数値などのリテラル式に対しては、evaluateはその値を返します。
  • 関数evaluateは、名前の値を見つけるために環境内を探索しなければなりません。

Combinations

  • 関数適用に対しては、evaluateは適用の関数式と引数式を再帰的に評価しなければなりません。得られた関数と引数はapplyに渡され、applyが実際の関数適用を処理します。
  • 演算子の組み合わせは、関数適用に変換されたうえで評価されます。

Syntactic forms

  • 条件式または条件文は、その構成要素を特別に処理する必要があります。述語が真であれば帰結式を評価し、そうでなければ代替式を評価します。
  • ラムダ式は、ラムダ式で指定されたパラメータと本体を、評価時の環境とまとめて一つにパッケージ化することで、適用可能な関数に変換しなければなりません。
  • 文の列は、その構成要素を出現順に評価する必要があります。
  • ブロックは、そのブロック内で宣言されたすべての名前を反映した新しい環境のもとで本体を評価する必要があります。
  • return文は、そのreturn文の評価を引き起こした関数呼び出しの結果となる値を生成しなければなりません。
  • 関数宣言は、定数宣言に変換されたうえで評価されます。
  • 定数宣言、変数宣言、または代入は、宣言または代入の対象となる名前に結び付けるべき新しい値を計算するために、evaluateを再帰的に呼び出さなければなりません。そのうえで、環境はその名前の新しい値を反映するように変更されなければなりません。
以下がevaluateの宣言です。 
function evaluate(component, env) {
    return is_literal(component)
           ? literal_value(component)
           : is_name(component)
           ? lookup_symbol_value(symbol_of_name(component), env)
           : is_application(component)
           ? apply(evaluate(function_expression(component), env),
                   list_of_values(arg_expressions(component), env))
           : is_operator_combination(component)
           ? evaluate(operator_combination_to_application(component),
                      env)
           : is_conditional(component)
           ? eval_conditional(component, env)
           : is_lambda_expression(component)
           ? make_function(lambda_parameter_symbols(component),
                           lambda_body(component), env)
           : is_sequence(component)
           ? eval_sequence(sequence_statements(component), env)
           : is_block(component)
           ? eval_block(component, env)
           : is_return_statement(component)
           ? eval_return_statement(component, env)
           : is_function_declaration(component)
           ? evaluate(function_decl_to_constant_decl(component), env)
           : is_declaration(component)
           ? eval_declaration(component, env)
           : is_assignment(component)
           ? eval_assignment(component, env)
           : error(component, "unknown syntax -- evaluate");
}

For clarity, evaluate has been implemented as a case analysis using conditional expressions. The disadvantage of this is that our function handles only a few distinguishable types of statements and expressions, and no new ones can be defined without editing the declaration of evaluate. In most interpreter implementations, dispatching on the type of a component is done in a data-directed style. This allows a user to add new types of components that evaluate can distinguish, without modifying the declaration of evaluate itself. (See exercise 4.3.)
分かりやすさのために、evaluateは条件式を使った場合分けとして実装してあります。この方式の欠点は、私たちの関数が区別できる文や式の種類がごく限られたものになってしまい、evaluateの宣言を編集しない限り新しい種類を追加できないことです。多くのインタプリタの実装では、コンポーネントの型によるディスパッチはデータ指向のスタイルで行われています。これにより、ユーザーはevaluate自身の宣言を変更することなく、evaluateが区別できる新しい種類のコンポーネントを追加できるようになります（演習 4.3を参照してください）。

The representation of names is handled by the syntax abstractions. Internally, the evaluator uses strings to represent names, and we refer to such strings as symbols. The function symbol_of_name used in evaluate extracts from a name the symbol by which it is represented.
名前の表現は構文の抽象化によって扱われます。評価器は内部的には文字列を使って名前を表現しており、そのような文字列をシンボルと呼びます。evaluateの中で使われている関数symbol_of_nameは、名前から、それを表すシンボルを取り出します。

Apply

The function apply takes two arguments, a function and a list of arguments to which the function should be applied. The function apply classifies functions into two kinds: It calls apply_primitive_function to apply primitives; it applies compound functions by evaluating the block that makes up the body of the function. The environment for the evaluation of the body of a compound function is constructed by extending the base environment carried by the function to include a frame that binds the parameters of the function to the arguments to which the function is to be applied. Here is the declaration of apply:
関数 apply は 2 つの引数、つまり 関数 と、その 関数 に適用すべき引数のリストを受け取ります。 関数 apply は 関数 を 2 種類に分類します。プリミティブを適用するには apply_primitive_function を呼び出し、複合 関数 については、 その関数本体を構成するブロックを評価する ことで適用します。複合 関数 の本体を評価するための環境は、その 関数 が保持している基底環境を拡張し、 関数 のパラメータを、その 関数 が適用される引数に束縛するフレームを加えることで構築されます。apply の 宣言 は次のとおりです。 
function apply(fun, args) {
    if (is_primitive_function(fun)) {
        return apply_primitive_function(fun, args);
    } else if (is_compound_function(fun)) {
        const result = evaluate(function_body(fun),
                                extend_environment(
                                    function_parameters(fun),
                                    args,
                                    function_environment(fun)));
        return is_return_value(result)
               ? return_value_content(result)
               : undefined;
    } else {
        error(fun, "unknown function type -- apply");
    }
}
In order to return a value, a JavaScript function needs to evaluate a return statement. If a function terminates without evaluating a return statement, the value undefined is returned. To distinguish the two cases, the evaluation of a return statement will wrap the result of evaluating its return expression into a return value. If the evaluation of the function body yields such a return value, the content of the return value is retrieved; otherwise the value undefined is returned.
値を返すためには、JavaScript の関数は return 文を評価する必要があります。 関数が return 文を評価せずに終了した場合には、値 undefined が返されます。 この 2 つのケースを区別するため、return 文の評価では、return 式を評価した結果を 戻り値（return value）としてラップします。関数本体の評価がそのような戻り値を生じた場合には、その戻り値の中身が取り出されます。そうでない場合には、値 undefined が返されます。
[2]

Function arguments

When evaluate processes a function application, it uses list_of_values to produce the list of arguments to which the function is to be applied. The function list_of_values takes as an argument the argument expressions of the application. It evaluates each argument expression and returns a list of the corresponding values:
evaluate が 関数 適用を処理するとき、その 関数 に適用すべき引数のリストを生成するために list_of_values を使います。 関数 list_of_values は、 適用の引数式 を引数として受け取ります。そして各 引数式 を評価し、対応する値のリストを返します。
[3] 
function list_of_values(exps, env) {
    return map(arg => evaluate(arg, env), exps);
}

Conditionals

The function eval_conditional evaluates the predicate part of a conditional component in the given environment. If the result is true, the consequent is evaluated, otherwise the alternative is evaluated:
関数 eval_conditional は、与えられた環境で 条件コンポーネント の述語部分を評価します。結果が真であれば、 帰結式が評価され、そうでなければ代替式が評価されます。 
function eval_conditional(component, env) {
    return is_truthy(evaluate(conditional_predicate(component), env))
           ? evaluate(conditional_consequent(component), env)
           : evaluate(conditional_alternative(component), env);
}
Note that the evaluator does not need to distinguish between conditional expressions and conditional statements.
なお、評価器は条件式と条件文を区別する必要がないことに注意してください。

The use of is_truthy in eval_conditional highlights the issue of the connection between an implemented language and an implementation language. The conditional_predicate is evaluated in the language being implemented and thus yields a value in that language. The interpreter predicate is_truthy translates that value into a value that can be tested by the conditional expression in the implementation language: The metacircular representation of truth might not be the same as that of the underlying JavaScript.
eval_conditional で is_truthy を使っていることは、 実装対象の言語と実装言語のつながりという問題を浮き彫りにします。 conditional_predicate は実装対象の言語の中で評価されるので、その言語における値を生み出します。インタプリタの述語 is_truthy は、その値を、実装言語の 条件式 でテストできる値へと変換します。メタ循環的な真理の表現は、基盤となる JavaScript における真理の表現と同じとは限りません。
[4]

Sequences

The function eval_sequence is used by evaluate to evaluate a sequence of statements at the top level or in a block. It takes as arguments a sequence of statements and an environment, and evaluates the statements in the order in which they occur. The value returned is the value of the final statement, except that if the evaluation of any statement in the sequence yields a return value, that value is returned and the subsequent statements are ignored.
関数 eval_sequence は、トップレベルまたはブロック内の文の列を評価するために evaluate から使われます。eval_sequence は文の列と環境を引数として受け取り、文をそれらが出現する順序で評価します。返される値は最後の文の値です。ただし、列中のいずれかの文の評価が戻り値を生じた場合には、その値が返され、以降の文は無視されます。
[5] 
function eval_sequence(stmts, env) {
    if (is_empty_sequence(stmts)) {
        return undefined;
    } else if (is_last_statement(stmts)) {
        return evaluate(first_statement(stmts), env);
    } else {
        const first_stmt_value =
            evaluate(first_statement(stmts), env);
        if (is_return_value(first_stmt_value)) {
            return first_stmt_value;
        } else {
            return eval_sequence(rest_statements(stmts), env);
        }
    }
}

Blocks

The function eval_block handles blocks. The variables and constants (including functions) declared in the block have the whole block as their scope and thus are scanned out before the body of the block is evaluated. The body of the block is evaluated with respect to an environment that extends the current environment by a frame that binds each local name to a special value, "*unassigned*". This string serves as a placeholder, before the evaluation of the declaration assigns the name its proper value. An attempt to access the value of the name before its declaration is evaluated leads to an error at run time (see exercise 4.12), as stated in footnote undefined in chapter 1.
関数 eval_block はブロックを処理します。 ブロック内で宣言された変数や定数（関数を含む）は、ブロック全体をスコープとして持つため、 ブロックの本体が評価される前にスキャンアウトされます。 ブロックの本体は、現在の環境を拡張した環境のもとで評価されます。 この拡張では、各ローカル名を特別な値 "*unassigned*" に束縛するフレームが追加されます。 この文字列はプレースホルダの役割を果たし、その後に宣言が評価されることで名前に本来の値が代入されます。 宣言が評価される前にその名前の値にアクセスしようとすると、 第 1章の脚注 undefinedで述べたとおり、 実行時エラーとなります（演習 4.12を参照）。 
function eval_block(component, env) {
    const body = block_body(component);
    const locals = scan_out_declarations(body);
    const unassigneds = list_of_unassigned(locals);
    return evaluate(body, extend_environment(locals,
                                             unassigneds,
                                             env));
}
function list_of_unassigned(symbols) {
    return map(symbol => "*unassigned*", symbols);
}
The function scan_out_declarations collects a list of all symbols representing names declared in the body. It uses declaration_symbol to retrieve the symbol that represents the name from the declaration statements it finds.
関数 scan_out_declarations は、 本体内で宣言された名前を表すシンボルのリストを集めます。 見つけた宣言文から名前を表すシンボルを取り出すために、 declaration_symbol を使用します。 
function scan_out_declarations(component) {
    return is_sequence(component)
           ? accumulate(append,
                        null,
                        map(scan_out_declarations,
                            sequence_statements(component)))
           : is_declaration(component)
           ? list(declaration_symbol(component))
           : null;
}
We ignore declarations that are nested in another block, because the evaluation of that block will take care of them. The function scan_out_declarations looks for declarations only in sequences because declarations in conditional statements, function declarations, and lambda expressions are always in a nested block.
入れ子のブロック内にある宣言は、そのブロックの評価が処理してくれるため、ここでは無視します。 関数 scan_out_declarations はシーケンスの中だけを対象に宣言を探します。 これは、条件文、関数宣言、ラムダ式の中の宣言が常に入れ子のブロック内にあるためです。

Return statements

The function eval_return_statement is used to evaluate return statements. As seen in apply and the evaluation of sequences, the result of evaluation of a return statement needs to be identifiable so that the evaluation of a function body can return immediately, even if there are statements after the return statement. For this purpose, the evaluation of a return statement wraps the result of evaluating the return expression in a return value object.
関数 eval_return_statement は return 文を評価するために使われます。 apply の実装やシーケンスの評価で見たとおり、 return 文の評価結果は識別可能である必要があります。 これは、return 文のあとに続く文があったとしても、 関数本体の評価が直ちに戻れるようにするためです。 そのために、return 文の評価では、return 式を評価した結果を戻り値オブジェクトで包みます。
[6] 
function eval_return_statement(component, env) {
    return make_return_value(evaluate(return_expression(component),
                                      env));
}

Assignments and declarations

The function eval_assignment handles assignments to names. (To simplify the presentation of our evaluator, we are allowing assignment not just to variables but also—erroneously—to constants. Exercise 4.11 explains how we could distinguish constants from variables and prevent assignment to constants.) The function eval_assignment calls evaluate on the value expression to find the value to be assigned and calls assignment_symbol to retrieve the symbol that represents the name from the assignment. The function eval_assignment transmits the symbol and the value to assign_symbol_value to be installed in the designated environment. The evaluation of an assignment returns the value that was assigned.
関数 eval_assignment は 名前への代入を処理します。 （評価器の記述を簡潔にするため、変数だけでなく—誤ってではありますが—定数への代入も許しています。 定数と変数を区別して定数への代入を防ぐ方法については、 演習 4.11で説明します。） 関数 eval_assignment は、 値式に対して evaluate を呼び出して代入すべき値を求め、 assignment_symbol を呼び出して 代入文から名前を表すシンボルを取り出します。 そして関数 eval_assignment は、 そのシンボルと値を assign_symbol_value に渡し、 指定された環境に設定します。 代入の評価結果は、代入された値そのものを返します。 
function eval_assignment(component, env) {
    const value = evaluate(assignment_value_expression(component),
                           env);
    assign_symbol_value(assignment_symbol(component), value, env);
    return value;
}

Constant and variable declarations are both recognized by the is_declaration syntax predicate. They are treated in a manner similar to assignments, because eval_block has already bound their symbols to "*unassigned*" in the current environment. Their evaluation replaces "*unassigned*" with the result of evaluating the value expression.
定数宣言と変数宣言は、どちらも構文述語 is_declaration によって認識されます。 これらは代入と似た方法で扱われます。 なぜなら、eval_block がすでに現在の環境で それらのシンボルを "*unassigned*" に束縛しているからです。 宣言の評価は、この "*unassigned*" を 値式を評価した結果で置き換えます。 
function eval_declaration(component, env) {
    assign_symbol_value(
        declaration_symbol(component),
        evaluate(declaration_value_expression(component), env),
        env);
    return undefined;
}
The result of evaluating the body of a function is determined by return statements, and therefore the return value undefined in eval_declaration only matters when the declaration occurs at the top level, outside of any function body. Here we use the return value undefined to simplify the presentation; exercise 4.8 describes the real result of evaluating top-level components in JavaScript.
関数本体を評価した結果は return 文によって決定されるため、 eval_declaration における戻り値 undefined は、 宣言がどの関数本体にも含まれないトップレベルで現れる場合にのみ意味を持ちます。 ここでは記述を簡潔にするために戻り値 undefined を使っていますが、 JavaScript におけるトップレベル構文要素を評価した実際の結果については、 演習 4.8で説明します。

Notice that we cannot tell whether the metacircular evaluator evaluates argument expressions from left to right or from right to left. Its evaluation order is inherited from the underlying JavaScript: If the arguments to pair in map are evaluated from left to right, then list_of_values will evaluate argument expressions from left to right; and if the arguments to pair are evaluated from right to left, then list_of_values will evaluate argument expressions from right to left.

Write a version of list_of_values that evaluates argument expressions from left to right regardless of the order of evaluation in the underlying JavaScript. Also write a version of list_of_values that evaluates argument expressions from right to left.
このメタ循環評価器が 引数式を左から右に評価するのか、それとも右から左に評価するのかは、 この評価器を見ただけでは分からないことに注意してください。 その評価順序は、土台となっている JavaScript から引き継がれます。 すなわち、map 内の pair への引数が左から右に評価されるのであれば、 list_of_values は引数式を左から右に評価します。 逆に pair への引数が右から左に評価されるのであれば、 list_of_values は引数式を右から左に評価します。

土台となっている JavaScript の評価順序にかかわらず、 引数式を左から右に評価する list_of_values を書いてください。 また、引数式を右から左に評価する list_of_values も書いてください。
