2.3.3  
Example: Representing Sets
例：集合の表現

In the previous examples we built representations for two kinds of compound data objects: rational numbers and algebraic expressions. In one of these examples we had the choice of simplifying (reducing) the expressions at either construction time or selection time, but other than that the choice of a representation for these structures in terms of lists was straightforward. When we turn to the representation of sets, the choice of a representation is not so obvious. Indeed, there are a number of possible representations, and they differ significantly from one another in several ways.
これまでの例では、有理数と代数式という2種類の複合データオブジェクトの表現を構築しました。一方の例では、式の簡約化（約分）を構成時に行うか選択時に行うかの選択肢がありましたが、それ以外はこれらの構造をリストで表現する選択は素直なものでした。集合の表現に目を向けると、表現の選択はそれほど明白ではありません。実際、多くの可能な表現があり、それらはいくつかの点で大きく異なります。

Informally, a set is simply a collection of distinct objects. To give a more precise definition we can employ the method of data abstraction. That is, we define set by specifying the operations that are to be used on sets. These are union_set, intersection_set, is_element_of_set, and adjoin_set. The function is_element_of_set is a predicate that determines whether a given element is a member of a set. The function adjoin_set takes an object and a set as arguments and returns a set that contains the elements of the original set and also the adjoined element. The function union_set computes the union of two sets, which is the set containing each element that appears in either argument. The function intersection_set computes the intersection of two sets, which is the set containing only elements that appear in both arguments. From the viewpoint of data abstraction, we are free to design any representation that implements these operations in a way consistent with the interpretations given above.
非公式には、集合とは互いに異なるオブジェクトの集まりのことです。より正確な定義を与えるために、データ抽象の方法を使うことができます。つまり、集合に対して使う 演算を指定することで集合を定義します。それらは union_set、intersection_set、is_element_of_set、および adjoin_set です。 関数 is_element_of_set は、与えられた要素が集合のメンバーかどうかを判定する述語です。 関数 adjoin_set はオブジェクトと集合を引数に取り、元の集合の要素と追加された要素を含む集合を返します。 関数 union_set は2つの集合の和集合を計算します。和集合とは、どちらかの引数に現れる各要素を含む集合です。 関数 intersection_set は2つの集合の積集合を計算します。積集合とは、両方の引数に現れる要素のみを含む集合です。データ抽象の観点から見れば、上記の解釈と整合的な方法でこれらの演算を実装する任意の表現を自由に設計できます。
[1]

Sets as unordered lists
順序なしリストとしての集合

One way to represent a set is as a list of its elements in which no element appears more than once. The empty set is represented by the empty list. In this representation, is_element_of_set is similar to the function member of section 2.3.1. It uses equal instead of === so that the set elements need not be just numbers or strings:
集合を表現する一つの方法は、同じ要素が2回以上現れない要素のリストとすることです。空集合は空リストで表現されます。この表現では、is_element_of_set はセクション 2.3.1の関数 member に似ています。集合の要素が単なる数や文字列でなくてもよいように、=== の代わりに equal を使用しています。 
function is_element_of_set(x, set) {
    return is_null(set) 
           ? false
           : equal(x, head(set))
           ? true
           : is_element_of_set(x, tail(set));
}
Using this, we can write adjoin_set. If the object to be adjoined is already in the set, we just return the set. Otherwise, we use pair to add the object to the list that represents the set:
これを使って adjoin_set を書くことができます。追加するオブジェクトが既に集合にある場合は、集合をそのまま返します。そうでなければ、pair を使って集合を表すリストにオブジェクトを追加します。 
function adjoin_set(x, set) {
    return is_element_of_set(x, set)
           ? set
           : pair(x, set);
}
For intersection_set we can use a recursive strategy. If we know how to form the intersection of set2 and the tail of set1, we only need to decide whether to include the head of set1 in this. But this depends on whether head(set1) is also in set2. Here is the resulting function:
intersection_set には再帰的な戦略を使うことができます。set2 と set1 の tail の積集合を形成する方法がわかっていれば、set1 の head をこれに含めるかどうかを決めるだけで済みます。しかし、これは head(set1) が set2 にも含まれているかどうかに依存します。結果として得られる関数は次の通りです。 
function intersection_set(set1, set2) {
    return is_null(set1) || is_null(set2)
           ? null
           : is_element_of_set(head(set1), set2)
           ? pair(head(set1), intersection_set(tail(set1), set2))
           : intersection_set(tail(set1), set2);
}

In designing a representation, one of the issues we should be concerned with is efficiency. Consider the number of steps required by our set operations. Since they all use is_element_of_set, the speed of this operation has a major impact on the efficiency of the set implementation as a whole. Now, in order to check whether an object is a member of a set, is_element_of_set may have to scan the entire set. (In the worst case, the object turns out not to be in the set.) Hence, if the set has $n$ elements, is_element_of_set might take up to $n$ steps. Thus, the number of steps required grows as $\Theta(n)$. The number of steps required by adjoin_set, which uses this operation, also grows as $\Theta(n)$. For intersection_set, which does an is_element_of_set check for each element of set1, the number of steps required grows as the product of the sizes of the sets involved, or $\Theta(n^{2})$ for two sets of size $n$. The same will be true of union_set.
表現を設計する際に注意すべき問題の一つは効率です。集合演算に必要なステップ数を考えてみましょう。すべての演算が is_element_of_set を使用するため、この演算の速度は集合の実装全体の効率に大きく影響します。オブジェクトが集合のメンバーかどうかを調べるには、is_element_of_set は集合全体を走査しなければならないかもしれません（最悪の場合、オブジェクトが集合に含まれていないことがわかります）。したがって、集合が $n$ 個の要素を持つ場合、is_element_of_set は最大 $n$ ステップかかる可能性があります。したがって、必要なステップ数は $\Theta(n)$ で増加します。この演算を使用する adjoin_set に必要なステップ数も $\Theta(n)$ で増加します。set1 の各要素に対して is_element_of_set のチェックを行う intersection_set では、必要なステップ数は関与する集合のサイズの積として増加し、サイズ $n$ の2つの集合に対しては $\Theta(n^{2})$ になります。union_set についても同様です。

Exercise 2.59
Implement the union_set operation for the unordered-list representation of sets.
集合の順序なしリスト表現に対する union_set 演算を実装しなさい。 
function union_set(set1, set2) {
    return is_null(set1)
           ? set2
           : adjoin_set(head(set1), 
                        union_set(tail(set1), set2));
}
Exercise 2.60
We specified that a set would be represented as a list with no duplicates. Now suppose we allow duplicates. For instance, the set $\{1,2,3\}$ could be represented as the list list(2, 3, 2, 1, 3, 2, 2). Design functions is_element_of_set, adjoin_set, union_set, and intersection_set that operate on this representation. How does the efficiency of each compare with the corresponding function for the non-duplicate representation? Are there applications for which you would use this representation in preference to the non-duplicate one?
集合は重複のないリストとして表現すると規定しました。ここで、重複を許すとしましょう。例えば、集合 $\{1,2,3\}$ はリスト list(2, 3, 2, 1, 3, 2, 2) として表現できます。この表現に対して動作する関数 is_element_of_set、adjoin_set、union_set、および intersection_set を設計しなさい。各演算の効率は、重複なし表現に対応する関数と比べてどうですか？ 重複なし表現よりもこの表現を使うほうが好ましいアプリケーションはありますか？
The functions is_element_of_set and intersection_set remain unchanged. Here is the new implementation of adjoin_set and union_set.
関数 is_element_of_set と intersection_set は変更なしです。adjoin_set と union_set の新しい実装は次の通りです。 
function adjoin_set(x, set) {
    return pair(x, set);
}
function union_set(set1, set2) {
    return append(set1, set2);
}
In the version with no duplicates, the required number of steps for is_element_of_set and adjoin_set has an order of growth of $O(n)$, where $n$ is the number of element occurrences in the given representation, and the required number of steps for intersection_set and union_set has an order of growth of $O(n m)$, where $n$ is the number of element occurrences in the representation of the first set and $m$ is the number of element occurrences in the representation of the second set. In the version that allows duplicates, the number of steps for adjoin_set shrinks to $O(n)$, and the number of steps for union_set shrinks to $O(n)$. However, note that the number of element occurrences may be much larger in the second version, because many duplicates may accumulate. For applications where duplicate elements are rare, the version that allows duplicates is preferrable.
重複なしバージョンでは、is_element_of_set と adjoin_set に必要なステップ数の増加のオーダーは $O(n)$ です（$n$ は与えられた表現の要素の出現回数）。intersection_set と union_set に必要なステップ数の増加のオーダーは $O(n m)$ です（$n$ は第1集合の表現の要素出現回数、$m$ は第2集合の要素出現回数）。重複許容バージョンでは、adjoin_set のステップ数は $O(n)$ に縮小し、union_set のステップ数は $O(n)$ に縮小します。ただし、多くの重複が蓄積される可能性があるため、2番目のバージョンでは要素の出現回数がはるかに大きくなる場合があることに注意してください。重複要素がまれなアプリケーションでは、重複を許容するバージョンのほうが好ましいです。

Sets as ordered lists
順序付きリストとしての集合

One way to speed up our set operations is to change the representation so that the set elements are listed in increasing order. To do this, we need some way to compare two objects so that we can say which is bigger. For example, we could compare strings lexicographically, or we could agree on some method for assigning a unique number to an object and then compare the elements by comparing the corresponding numbers. To keep our discussion simple, we will consider only the case where the set elements are numbers, so that we can compare elements using > and <. We will represent a set of numbers by listing its elements in increasing order. Whereas our first representation above allowed us to represent the set $\{1,3,6,10\}$ by listing the elements in any order, our new representation allows only the list list(1, 3, 6, 10).
集合演算を高速化する一つの方法は、集合の要素が昇順にリストされるように表現を変更することです。これを行うには、2つのオブジェクトを比較してどちらが大きいか言えるようにする方法が必要です。例えば、文字列を辞書順で比較したり、オブジェクトに一意の番号を割り当てる方法を決めて、対応する番号を比較することで要素を比較したりできます。議論を単純にするために、集合の要素が数である場合のみを考え、> と < を使って要素を比較できるようにします。数の集合を、その要素を昇順にリストすることで表現します。上の最初の表現では集合 $\{1,3,6,10\}$ を任意の順序で要素をリストすることで表現できましたが、新しい表現ではリスト list(1, 3, 6, 10) のみが許されます。

One advantage of ordering shows up in is_element_of_set: In checking for the presence of an item, we no longer have to scan the entire set. If we reach a set element that is larger than the item we are looking for, then we know that the item is not in the set:
順序付けの一つの利点は is_element_of_set に現れます。項目の存在を調べる際に、もはや集合全体を走査する必要はありません。探している項目より大きい集合の要素に到達すれば、その項目が集合にないことがわかります。
function is_element_of_set(x, set) { return is_null(set) ? false : x === head(set) ? true : x < head(set) ? false : // $\texttt{x > head(set)}$ is_element_of_set(x, tail(set)); }
How many steps does this save? In the worst case, the item we are looking for may be the largest one in the set, so the number of steps is the same as for the unordered representation. On the other hand, if we search for items of many different sizes we can expect that sometimes we will be able to stop searching at a point near the beginning of the list and that other times we will still need to examine most of the list. On the average we should expect to have to examine about half of the items in the set. Thus, the average number of steps required will be about $n/2$. This is still $\Theta(n)$ growth, but it does save us, on the average, a factor of 2 in number of steps over the previous implementation.
これでどれだけステップが節約されるでしょうか？ 最悪の場合、探している項目が集合の中で最大のものかもしれないため、ステップ数は順序なし表現と同じです。一方、さまざまなサイズの項目を検索する場合、リストの先頭近くで検索を止められることもあれば、リストのほとんどを調べなければならないこともあると予想できます。平均すると、集合の項目の約半分を調べることになるでしょう。したがって、必要な平均ステップ数は約 $n/2$ です。これはまだ $\Theta(n)$ の増加ですが、平均すると前の実装よりステップ数が2分の1に節約されます。

We obtain a more impressive speedup with intersection_set. In the unordered representation this operation required $\Theta(n^2)$ steps, because we performed a complete scan of set2 for each element of set1. But with the ordered representation, we can use a more clever method. Begin by comparing the initial elements, x1 and x2, of the two sets. If x1 equals x2, then that gives an element of the intersection, and the rest of the intersection is the intersection of the tails of the two sets. Suppose, however, that x1 is less than x2. Since x2 is the smallest element in set2, we can immediately conclude that x1 cannot appear anywhere in set2 and hence is not in the intersection. Hence, the intersection is equal to the intersection of set2 with the tail of set1. Similarly, if x2 is less than x1, then the intersection is given by the intersection of set1 with the tail of set2. Here is the function:
intersection_set ではより印象的な高速化が得られます。順序なし表現ではこの演算に $\Theta(n^2)$ ステップが必要でした。set1 の各要素に対して set2 の完全な走査を行ったからです。しかし、順序付き表現では、より賢い方法を使えます。2つの集合の最初の要素 x1 と x2 を比較することから始めます。x1 が x2 と等しければ、それは積集合の要素であり、残りの積集合は2つの集合の tail の積集合です。しかし、x1 が x2 より小さいとします。x2 は set2 の最小の要素なので、x1 は set2 のどこにも現れず、したがって積集合にも含まれないと直ちに結論できます。よって、積集合は set2 と set1 の tail の積集合に等しくなります。同様に、x2 が x1 より小さければ、積集合は set1 と set2 の tail の積集合で与えられます。次がその関数です。
function intersection_set(set1, set2) { if (is_null(set1) || is_null(set2)) { return null; } else { const x1 = head(set1); const x2 = head(set2); return x1 === x2 ? pair(x1, intersection_set(tail(set1), tail(set2))) : x1 < x2 ? intersection_set(tail(set1), set2) : // $\texttt{x2 < x1}$ intersection_set(set1, tail(set2)); } }
To estimate the number of steps required by this process, observe that at each step we reduce the intersection problem to computing intersections of smaller sets—removing the first element from set1 or set2 or both. Thus, the number of steps required is at most the sum of the sizes of set1 and set2, rather than the product of the sizes as with the unordered representation. This is $\Theta(n)$ growth rather than $\Theta(n^2)$—a considerable speedup, even for sets of moderate size.
このプロセスに必要なステップ数を見積もるには、各ステップで積集合の問題をより小さい集合の積集合の計算に帰着させていることに注目してください。set1 または set2、あるいは両方から最初の要素を取り除いています。したがって、必要なステップ数は最大でも set1 と set2 のサイズの和であり、順序なし表現のようなサイズの積ではありません。これは $\Theta(n^2)$ ではなく $\Theta(n)$ の増加であり、中程度のサイズの集合でもかなりの高速化です。

Sets as binary trees
二分木としての集合

We can do better than the ordered-list representation by arranging the set elements in the form of a tree. Each node of the tree holds one element of the set, called the entry at that node, and a link to each of two other (possibly empty) nodes. The left link points to elements smaller than the one at the node, and the right link to elements greater than the one at the node. Figure 2.25 shows some trees that represent the set $\{1,3,5,7,9,11\}$. The same set may be represented by a tree in a number of different ways. The only thing we require for a valid representation is that all elements in the left subtree be smaller than the node entry and that all elements in the right subtree be larger.
集合の要素をツリーの形に配置することで、順序付きリスト表現よりさらに良い結果を得ることができます。ツリーの各ノードは集合の1つの要素（そのノードのエントリと呼ばれます）と、他の2つの（空の可能性がある）ノードへのリンクを保持します。左のリンクはそのノードの要素より小さい要素を指し、右のリンクはそのノードの要素より大きい要素を指します。図 2.25は集合 $\{1,3,5,7,9,11\}$ を表すいくつかのツリーを示しています。同じ集合をツリーでいくつかの異なる方法で表現できます。有効な表現に必要な唯一のことは、左の部分木のすべての要素がノードのエントリより小さく、右の部分木のすべての要素がより大きいことです。

The advantage of the tree representation is this: Suppose we want to check whether a number $x$ is contained in a set. We begin by comparing $x$ with the entry in the top node. If $x$ is less than this, we know that we need only search the left subtree; if $x$ is greater, we need only search the right subtree. Now, if the tree is balanced, each of these subtrees will be about half the size of the original. Thus, in one step we have reduced the problem of searching a tree of size $n$ to searching a tree of size $n/2$. Since the size of the tree is halved at each step, we should expect that the number of steps needed to search a tree of size $n$ grows as $\Theta(\log n)$.
ツリー表現の利点はこうです。数 $x$ が集合に含まれているかどうかを調べたいとします。$x$ をトップノードのエントリと比較することから始めます。$x$ がそれより小さければ、左の部分木だけを探索すればよいことがわかります。$x$ がそれより大きければ、右の部分木だけを探索すればよいのです。ツリーが平衡している場合、これらの部分木はそれぞれ元のものの約半分のサイズになります。したがって、1ステップでサイズ $n$ のツリーの探索問題をサイズ $n/2$ のツリーの探索に帰着させたことになります。各ステップでツリーのサイズが半分になるため、サイズ $n$ のツリーを探索するのに必要なステップ数は $\Theta(\log n)$ で増加すると予想されます。
[2]
For large sets, this will be a significant speedup over the previous representations.
大きな集合では、これは以前の表現に比べて大幅な高速化になります。

We can represent trees by using lists. Each node will be a list of three items: the entry at the node, the left subtree, and the right subtree. A left or a right subtree of the empty list will indicate that there is no subtree connected there. We can describe this representation by the following functions:
ツリーは リストを使って表現できます。各ノードは3つの項目のリストです。ノードのエントリ、左の部分木、右の部分木です。空リストの左または右の部分木は、そこに接続された部分木がないことを示します。この表現は次の関数で記述できます。
[3] 
function entry(tree) { return head(tree); }

function left_branch(tree) { return head(tail(tree)); }

function right_branch(tree) { return head(tail(tail(tree))); }

function make_tree(entry, left, right) { 
    return list(entry, left, right);
}

Now we can write is_element_of_set using the strategy described above:
上で述べた戦略を使って is_element_of_setを書くことができます。
function is_element_of_set(x, set) { return is_null(set) ? false : x === entry(set) ? true : x < entry(set) ? is_element_of_set(x, left_branch(set)) : // $\texttt{x > entry(set)}$ is_element_of_set(x, right_branch(set)); }

Adjoining an item to a set is implemented similarly and also requires $\Theta(\log n)$ steps. To adjoin an item x, we compare x with the node entry to determine whether x should be added to the right or to the left branch, and having adjoined x to the appropriate branch we piece this newly constructed branch together with the original entry and the other branch. If x is equal to the entry, we just return the node. If we are asked to adjoin x to an empty tree, we generate a tree that has x as the entry and empty right and left branches. Here is the function:
集合に項目を追加する操作も同様に実装され、$\Theta(\log n)$ ステップを必要とします。項目 x を追加するには、x をノードのエントリと比較して、x を右の枝に追加すべきか左の枝に追加すべきかを判定します。適切な枝に x を追加したら、この新しく構成された枝を元のエントリともう一方の枝と組み合わせます。x がエントリと等しい場合は、ノードをそのまま返します。空のツリーに x を追加するよう求められた場合は、x をエントリとし、右と左の枝が空であるツリーを生成します。次がその関数です。
function adjoin_set(x, set) { return is_null(set) ? make_tree(x, null, null) : x === entry(set) ? set : x < entry(set) ? make_tree(entry(set), adjoin_set(x, left_branch(set)), right_branch(set)) : // $\texttt{x > entry(set)}$ make_tree(entry(set), left_branch(set), adjoin_set(x, right_branch(set))); }

The above claim that searching the tree can be performed in a logarithmic number of steps rests on the assumption that the tree is balanced, i.e., that the left and the right subtree of every tree have approximately the same number of elements, so that each subtree contains about half the elements of its parent. But how can we be certain that the trees we construct will be balanced? Even if we start with a balanced tree, adding elements with adjoin_set may produce an unbalanced result. Since the position of a newly adjoined element depends on how the element compares with the items already in the set, we can expect that if we add elements randomly the tree will tend to be balanced on the average. But this is not a guarantee. For example, if we start with an empty set and adjoin the numbers 1 through 7 in sequence we end up with the highly unbalanced tree shown in figure 2.26. In this tree all the left subtrees are empty, so it has no advantage over a simple ordered list. One way to solve this problem is to define an operation that transforms an arbitrary tree into a balanced tree with the same elements. Then we can perform this transformation after every few adjoin_set operations to keep our set in balance. There are also other ways to solve this problem, most of which involve designing new data structures for which searching and insertion both can be done in $\Theta(\log n)$ steps.
ツリーの探索が対数的なステップ数で実行できるという上記の主張は、ツリーが 平衡している、つまり各ツリーの左の部分木と右の部分木がおよそ同じ数の要素を持ち、各部分木がその親の約半分の要素を含むという仮定に基づいています。しかし、構築するツリーが平衡していることをどのように保証できるでしょうか？ 平衡したツリーから始めたとしても、adjoin_set で要素を追加すると、非平衡な結果を生む可能性があります。新しく追加される要素の位置は、その要素が集合に既にある項目とどう比較されるかに依存するため、要素をランダムに追加すれば、ツリーは平均的に平衡する傾向があると予想できます。しかし、これは保証ではありません。例えば、空の集合から始めて数 1 から 7 を順に追加すると、図 2.26に示す非常に非平衡なツリーができあがります。このツリーでは左の部分木がすべて空なので、単純な順序付きリストに対する利点はありません。この問題を解決する一つの方法は、任意のツリーを同じ要素を持つ平衡ツリーに変換する演算を定義することです。そして、数回の adjoin_set 演算ごとにこの変換を実行して、集合を平衡に保つことができます。この問題を解決する他の方法もあり、その多くは探索と挿入の両方が $\Theta(\log n)$ ステップで行える新しいデータ構造の設計を含みます。

Sets and information retrieval
集合と情報検索

We have examined options for using lists to represent sets and have seen how the choice of representation for a data object can have a large impact on the performance of the programs that use the data. Another reason for concentrating on sets is that the techniques discussed here appear again and again in applications involving information retrieval.
リストを使って集合を表現する選択肢を検討し、データオブジェクトの表現の選択がそのデータを使うプログラムの性能に大きな影響を与えうることを見てきました。集合に注目するもう一つの理由は、ここで議論した技法が情報検索を含むアプリケーションに繰り返し現れるからです。

Consider a data base containing a large number of individual records, such as the personnel files for a company or the transactions in an accounting system. A typical data-management system spends a large amount of time accessing or modifying the data in the records and therefore requires an efficient method for accessing records. This is done by identifying a part of each record to serve as an identifying key. A key can be anything that uniquely identifies the record. For a personnel file, it might be an employee's ID number. For an accounting system, it might be a transaction number. Whatever the key is, when we define the record as a data structure we should include a key selector function that retrieves the key associated with a given record.
多数の個別レコードを含むデータベースを考えてみましょう。 例えば、企業の人事ファイルや会計システムの取引記録などです。典型的なデータ管理システムは、レコードのデータへのアクセスや変更に多くの時間を費やすため、レコードにアクセスする効率的な方法が必要です。これは、各レコードの一部を識別用の キーとして指定することで行われます。キーはレコードを一意に識別するものなら何でも構いません。人事ファイルの場合は従業員のID番号、会計システムの場合は取引番号かもしれません。キーが何であれ、レコードをデータ構造として定義する際には、与えられたレコードに関連付けられたキーを取得する key セレクタ関数を含めるべきです。

Now we represent the data base as a set of records. To locate the record with a given key we use a function lookup, which takes as arguments a key and a data base and which returns the record that has that key, or false if there is no such record. The function lookup is implemented in almost the same way as is_element_of_set. For example, if the set of records is implemented as an unordered list, we could use
データベースをレコードの集合として表現します。与えられたキーを持つレコードを見つけるために、関数 lookup を使います。これはキーとデータベースを引数に取り、そのキーを持つレコードを返すか、そのようなレコードがなければ false を返します。関数 lookup は is_element_of_set とほぼ同じ方法で実装されます。例えば、レコードの集合が順序なしリストとして実装されている場合、次のように使えます。 
function lookup(given_key, set_of_records) {
    return is_null(set_of_records)
           ? false
           : equal(given_key, key(head(set_of_records)))
           ? head(set_of_records)
           : lookup(given_key, tail(set_of_records));
}

Of course, there are better ways to represent large sets than as unordered lists. Information-retrieval systems in which records have to be randomly accessed are typically implemented by a tree-based method, such as the binary-tree representation discussed previously. In designing such a system the methodology of data abstraction can be a great help. The designer can create an initial implementation using a simple, straightforward representation such as unordered lists. This will be unsuitable for the eventual system, but it can be useful in providing a quick and dirty data base with which to test the rest of the system. Later on, the data representation can be modified to be more sophisticated. If the data base is accessed in terms of abstract selectors and constructors, this change in representation will not require any changes to the rest of the system.
もちろん、大きな集合を表現するには順序なしリストよりも良い方法があります。レコードにランダムアクセスする必要がある情報検索システムは、典型的には前述の二分木表現のようなツリーベースの方法で実装されます。このようなシステムを設計する際に、データ抽象の方法論は大きな助けとなります。設計者は、順序なしリストのような単純で素直な表現を使って初期実装を作成できます。これは最終的なシステムには不適切ですが、システムの残りの部分をテストするための簡易なデータベースを提供するのに役立ちます。後になってから、データ表現をより洗練されたものに変更できます。データベースが抽象的なセレクタとコンストラクタを通じてアクセスされていれば、この表現の変更はシステムの残りの部分に一切変更を必要としません。

Exercise 2.66
Implement the lookup function for the case where the set of records is structured as a binary tree, ordered by the numerical values of the keys.
レコードの集合がキーの数値で順序付けられた二分木として構造化されている場合の lookup 関数を実装しなさい。 
function lookup(given_key, tree_of_records) {
    if (is_null(tree_of_records)) {
        return null;
    } else {
        const this_entry = entry(tree_of_records);
        const this_key = key(this_entry);
        return given_key === this_key 
               ? this_entry
               : given_key < this_key
               ? lookup(given_key, 
                        left_branch(tree_of_records))
               : lookup(given_key, 
                        right_branch(tree_of_records));
    }
}

If we want to be more formal, we can specify consistent with the interpretations given above to mean that the operations satisfy a collection of rules such as these:
  • For any set S and any object x, is_element_of_set(x, adjoin_set(x, S)) is true (informally: Adjoining an object to a set produces a set that contains the object).
  • For any sets S and T and any object x, is_element_of_set(x, union_set(S, T)) is equal to is_element_of_set(x, S) || is_element_of_set(x, T) (informally: The elements of union_set(S, T) are the elements that are in S or in T).
  • For any object x, is_element_of_set(x, null) is false (informally: No object is an element of the empty set).
より形式的にするなら、上記の解釈と整合的ということは、演算が次のような規則の集まりを満たすことを意味すると規定できます。
