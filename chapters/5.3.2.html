5.3.2  
Maintaining the Illusion of Infinite Memory
無限メモリの幻想を維持する

The representation method outlined in section 5.3.1 solves the problem of implementing list structure, provided that we have an infinite amount of memory. With a real computer we will eventually run out of free space in which to construct new pairs.
5.3.1節で概説した表現方法は、無限のメモリがあるという前提のもとでリスト構造の実装問題を解決します。しかし実際のコンピュータでは、新しいペアを構築するためのフリーな領域がいずれ尽きてしまいます。
[1]
However, most of the pairs generated in a typical computation are used only to hold intermediate results. After these results are accessed, the pairs are no longer needed—they are garbage. For instance, the computation
しかし、一般的な計算で生成されるペアの大部分は、中間結果を保持するためだけに使われます。これらの結果にアクセスした後はペアはもう不要になります。つまり、それらはゴミ（ガベージ）です。例えば、次の計算
accumulate((x, y) => x + y,
           0,
           filter(is_odd, enumerate_interval(0, n)))
constructs two lists: the enumeration and the result of filtering the enumeration. When the accumulation is complete, these lists are no longer needed, and the allocated memory can be reclaimed. If we can arrange to collect all the garbage periodically, and if this turns out to recycle memory at about the same rate at which we construct new pairs, we will have preserved the illusion that there is an infinite amount of memory.
は、列挙のリストとフィルタリング結果のリストの2つを構築します。累積が完了すると、これらのリストはもう不要になり、割り当てたメモリを回収できます。すべてのゴミ（ガベージ）を定期的に回収するようにし、新しいペアを構築するのとほぼ同じ速度でメモリを再利用できれば、無限のメモリがあるという幻想を維持できます。

In order to recycle pairs, we must have a way to determine which allocated pairs are not needed (in the sense that their contents can no longer influence the future of the computation). The method we shall examine for accomplishing this is known as garbage collection. Garbage collection is based on the observation that, at any moment in an interpretation based on list-structured memory, the only objects that can affect the future of the computation are those that can be reached by some succession of head and tail operations starting from the pointers that are currently in the machine registers.
ペアを再利用するためには、割り当てられたペアのうちどれが不要であるか（その内容が計算の将来にもはや影響を与えられないという意味で）を判定する方法が必要です。これを達成するために検討する方法は、ガベージコレクションとして知られています。ガベージコレクションは、 リスト構造ベースのメモリを使ったインタプリタ において、どの時点でも計算の将来に影響を与えうるオブジェクトは、現在マシンレジスタにあるポインタから head と tail 操作を連続的に適用して到達できるものだけである、という観察に基づいています。
[2]
Any memory cell that is not so accessible may be recycled.
このようにアクセスできないメモリセルは、再利用できます。

There are many ways to perform garbage collection. The method we shall examine here is called stop-and-copy. The basic idea is to divide memory into two halves: working memory and free memory. When pair constructs pairs, it allocates these in working memory. When working memory is full, we perform garbage collection by locating all the useful pairs in working memory and copying these into consecutive locations in free memory. (The useful pairs are located by tracing all the head and tail pointers, starting with the machine registers.) Since we do not copy the garbage, there will presumably be additional free memory that we can use to allocate new pairs. In addition, nothing in the working memory is needed, since all the useful pairs in it have been copied. Thus, if we interchange the roles of working memory and free memory, we can continue processing; new pairs will be allocated in the new working memory (which was the old free memory). When this is full, we can copy the useful pairs into the new free memory (which was the old working memory).
ガベージコレクションを実行する方法は多数あります。ここで検討する方法はストップアンドコピーと呼ばれます。基本的な考え方は、メモリを2つの半分に分けることです。ワーキングメモリとフリーメモリです。 pair がペアを構築するとき、ワーキングメモリに割り当てます。ワーキングメモリがいっぱいになると、ワーキングメモリ内の有用なペアをすべて見つけ出し、フリーメモリの連続した位置にコピーすることでガベージコレクションを実行します。（有用なペアは、マシンレジスタから始めてすべての head と tail ポインタをたどって見つけます。）ゴミ（ガベージ）はコピーしないので、新しいペアの割り当てに使えるフリーメモリが追加で確保されるはずです。さらに、ワーキングメモリ内の有用なペアはすべてコピー済みなので、ワーキングメモリ内には必要なものが何もありません。したがって、ワーキングメモリとフリーメモリの役割を入れ替えれば、処理を続行できます。新しいペアは新しいワーキングメモリ（旧フリーメモリ）に割り当てられます。これがいっぱいになったら、有用なペアを新しいフリーメモリ（旧ワーキングメモリ）にコピーできます。
[3]

Implementation of a stop-and-copy garbage collector
ストップアンドコピーガベージコレクタの実装

We now use our register-machine language to describe the stop-and-copy algorithm in more detail. We will assume that there is a register called root that contains a pointer to a structure that eventually points at all accessible data. This can be arranged by storing the contents of all the machine registers in a preallocated list pointed at by root just before starting garbage collection.
ここからレジスタマシン言語を使って、ストップアンドコピーアルゴリズムをより詳細に記述します。 rootというレジスタがあり、最終的にアクセス可能なすべてのデータを指す構造へのポインタを保持していると仮定します。これは、ガベージコレクション開始直前にすべてのマシンレジスタの内容をrootが指す事前割り当てリストに格納することで実現できます。
[4]
We also assume that, in addition to the current working memory, there is free memory available into which we can copy the useful data. The current working memory consists of vectors whose base addresses are in registers called the_heads and the_tails, and the free memory is in registers called new_heads and new_tails.
また、現在のワーキングメモリに加えて、有用なデータをコピーできるフリーメモリがあると仮定します。現在のワーキングメモリは、 the_heads と the_tails というレジスタにベースアドレスが格納されているベクトルで構成されます。フリーメモリは new_heads と new_tails というレジスタに格納されています。

Garbage collection is triggered when we exhaust the free cells in the current working memory, that is, when a pair operation attempts to increment the free pointer beyond the end of the memory vector. When the garbage-collection process is complete, the root pointer will point into the new memory, all objects accessible from the root will have been moved to the new memory, and the free pointer will indicate the next place in the new memory where a new pair can be allocated. In addition, the roles of working memory and new memory will have been interchanged—new pairs will be constructed in the new memory, beginning at the place indicated by free, and the (previous) working memory will be available as the new memory for the next garbage collection. Figure 5.20 shows the arrangement of memory just before and just after garbage collection.
ガベージコレクションは、現在のワーキングメモリのフリーセルを使い果たしたとき、つまり pair 操作がメモリベクトルの末尾を超えてfreeポインタをインクリメントしようとしたときに発動されます。ガベージコレクションプロセスが完了すると、rootポインタは新しいメモリ内を指し、rootからアクセス可能なすべてのオブジェクトは新しいメモリに移動済みとなり、freeポインタは新しいメモリ内で新しいペアを割り当てられる次の場所を示します。加えて、ワーキングメモリと新しいメモリの役割が入れ替わります。—新しいペアはfreeが示す場所から新しいメモリ内に構築され、（以前の）ワーキングメモリは次のガベージコレクション用の新しいメモリとして利用可能になります。 図 5.20 は、ガベージコレクションの直前と直後のメモリの配置を示しています。

The state of the garbage-collection process is controlled by maintaining two pointers: free and scan. These are initialized to point to the beginning of the new memory. The algorithm begins by relocating the pair pointed at by root to the beginning of the new memory. The pair is copied, the root pointer is adjusted to point to the new location, and the free pointer is incremented. In addition, the old location of the pair is marked to show that its contents have been moved. This marking is done as follows: In the head position, we place a special tag that signals that this is an already-moved object. (Such an object is traditionally called a broken heart.)
ガベージコレクションプロセスの状態は、2つのポインタ、 freeと scanを維持することで制御されます。これらは新しいメモリの先頭を指すように初期化されます。アルゴリズムは、rootが指すペアを新しいメモリの先頭に再配置することから始まります。ペアがコピーされ、rootポインタが新しい位置を指すように調整され、freeポインタがインクリメントされます。さらに、ペアの旧位置には内容が移動済みであることを示すマークが付けられます。このマーキングは次のように行います。 head 位置に、すでに移動済みのオブジェクトであることを示す特別なタグを配置します。（このようなオブジェクトは伝統的に ブロークンハートと呼ばれます。）
[5]
In the tail position we place a forwarding address that points at the location to which the object has been moved.
tail 位置には、オブジェクトの移動先を指す フォワーディングアドレスを配置します。

After relocating the root, the garbage collector enters its basic cycle. At each step in the algorithm, the scan pointer (initially pointing at the relocated root) points at a pair that has been moved to the new memory but whose head and tail pointers still refer to objects in the old memory. These objects are each relocated, and the scan pointer is incremented. To relocate an object (for example, the object indicated by the head pointer of the pair we are scanning) we check to see if the object has already been moved (as indicated by the presence of a broken-heart tag in the head position of the object). If the object has not already been moved, we copy it to the place indicated by free, update free, set up a broken heart at the object's old location, and update the pointer to the object (in this example, the head pointer of the pair we are scanning) to point to the new location. If the object has already been moved, its forwarding address (found in the tail position of the broken heart) is substituted for the pointer in the pair being scanned. Eventually, all accessible objects will have been moved and scanned, at which point the scan pointer will overtake the free pointer and the process will terminate.
ルートを再配置した後、ガベージコレクタは基本サイクルに入ります。アルゴリズムの各ステップで、scanポインタ（最初は再配置されたルートを指しています）は、新しいメモリに移動済みだがその head と tail ポインタがまだ旧メモリ内のオブジェクトを参照しているペアを指しています。これらのオブジェクトはそれぞれ再配置され、scanポインタがインクリメントされます。オブジェクトを再配置するには（例えば、スキャン中のペアの head ポインタが示すオブジェクト）、まずそのオブジェクトがすでに移動済みかどうかを確認します（オブジェクトの head 位置にブロークンハートタグがあるかどうかで判断します）。オブジェクトがまだ移動されていなければ、freeが示す場所にコピーし、freeを更新し、オブジェクトの旧位置にブロークンハートを設定し、オブジェクトへのポインタ（この例ではスキャン中のペアの head ポインタ）を新しい位置を指すように更新します。オブジェクトがすでに移動済みの場合は、そのフォワーディングアドレス（ブロークンハートの tail 位置にあります）がスキャン中のペア内のポインタに代入されます。最終的に、アクセス可能なすべてのオブジェクトが移動およびスキャンされ、その時点でscanポインタがfreeポインタに追いつき、プロセスが終了します。

We can specify the stop-and-copy algorithm as a sequence of instructions for a register machine. The basic step of relocating an object is accomplished by a subroutine called relocate_old_result_in_new. This subroutine gets its argument, a pointer to the object to be relocated, from a register named old. It relocates the designated object (incrementing free in the process), puts a pointer to the relocated object into a register called new, and returns by branching to the entry point stored in the register relocate_continue. To begin garbage collection, we invoke this subroutine to relocate the root pointer, after initializing free and scan. When the relocation of root has been accomplished, we install the new pointer as the new root and enter the main loop of the garbage collector.

In the main loop of the garbage collector we must determine whether there are any more objects to be scanned. We do this by testing whether the scan pointer is coincident with the free pointer. If the pointers are equal, then all accessible objects have been relocated, and we branch to gc_flip, which cleans things up so that we can continue the interrupted computation. If there are still pairs to be scanned, we call the relocate subroutine to relocate the head of the next pair (by placing the head pointer in old). The relocate_continue register is set up so that the subroutine will return to update the head pointer.
ガベージコレクタのメインループでは、スキャンすべきオブジェクトがまだあるかどうかを判定しなければなりません。これはscanポインタがfreeポインタと一致するかどうかをテストして行います。ポインタが等しければ、アクセス可能なすべてのオブジェクトが再配置済みなので、 gc_flip に分岐して後始末を行い、中断された計算を続行できるようにします。まだスキャンすべきペアがある場合は、再配置サブルーチンを呼び出して次のペアの head を再配置します（ head ポインタをoldに配置することで）。 relocate_continue レジスタは、サブルーチンが head ポインタの更新に戻るように設定されます。
"gc_loop",

  branch(label("gc_flip")),
  assign("old", list(op("vector_ref"), reg("new_heads"), reg("scan"))),
  assign("relocate_continue", label("update_head")),
  go_to(label("relocate_old_result_in_new")),

At update_head, we modify the head pointer of the pair being scanned, then proceed to relocate the tail of the pair. We return to update_tail when that relocation has been accomplished. After relocating and updating the tail, we are finished scanning that pair, so we continue with the main loop.
update_head では、スキャン中のペアの head ポインタを更新し、次にペアの tail の再配置に進みます。その再配置が完了すると update_tail に戻ります。 tail の再配置と更新が終わると、そのペアのスキャンは完了なので、メインループに戻ります。

The subroutine relocate_old_result_in_new relocates objects as follows: If the object to be relocated (pointed at by old) is not a pair, then we return the same pointer to the object unchanged (in new). (For example, we may be scanning a pair whose head is the number 4. If we represent the head by n4, as described in section 5.3.1, then we want the relocated head pointer to still be n4.) Otherwise, we must perform the relocation. If the head position of the pair to be relocated contains a broken-heart tag, then the pair has in fact already been moved, so we retrieve the forwarding address (from the tail position of the broken heart) and return this in new. If the pointer in old points at a yet-unmoved pair, then we move the pair to the first free cell in new memory (pointed at by free) and set up the broken heart by storing a broken-heart tag and forwarding address at the old location. The subroutine relocate_old_result_in_new uses a register oldht to hold the head or the tail of the object pointed at by old.
サブルーチン relocate_old_result_in_new は、次のようにオブジェクトを再配置します。再配置するオブジェクト（oldが指すもの）がペアでない場合は、同じポインタを変更せずにnewに返します。（例えば、 head が数値4であるペアをスキャンしているかもしれません。5.3.1節で説明したように head をn4で表現している場合、再配置された head ポインタは依然としてn4であってほしいのです。）それ以外の場合は再配置を実行しなければなりません。再配置するペアの head 位置にブロークンハートタグが含まれている場合、そのペアは実際にはすでに移動済みなので、フォワーディングアドレスを（ブロークンハートの tail 位置から）取得してnewに返します。oldのポインタがまだ移動されていないペアを指している場合は、そのペアを新しいメモリの最初のフリーセル（freeが指す場所）に移動し、旧位置にブロークンハートタグとフォワーディングアドレスを格納してブロークンハートを設定します。 サブルーチン relocate_old_result_in_new はレジスタ oldht を使って、oldが指すオブジェクトの head または tail を保持します。

This idea was invented and first implemented by Minsky, as part of the implementation of Lisp for the PDP-1 at the MIT Research Laboratory of Electronics. It was further developed by Fenichel and Yochelson (1969) for use in the Lisp implementation for the Multics time-sharing system. Later, Baker (1978) developed a real-time version of the method, which does not require the computation to stop during garbage collection. Baker's idea was extended by Hewitt, Lieberman, and Moon (see Lieberman and Hewitt 1983) to take advantage of the fact that some structure is more volatile and other structure is more permanent.

An alternative commonly used garbage-collection technique is the mark-sweep method. This consists of tracing all the structure accessible from the machine registers and marking each pair we reach. We then scan all of memory, and any location that is unmarked is swept up as garbage and made available for reuse. A full discussion of the mark-sweep method can be found in Allen 1978.

The Minsky-Fenichel-Yochelson algorithm is the dominant algorithm in use for large-memory systems because it examines only the useful part of memory. This is in contrast to mark-sweep, in which the sweep phase must check all of memory. A second advantage of stop-and-copy is that it is a compacting garbage collector. That is, at the end of the garbage-collection phase the useful data will have been moved to consecutive memory locations, with all garbage pairs compressed out. This can be an extremely important performance consideration in machines with virtual memory, in which accesses to widely separated memory addresses may require extra paging operations.
このアイデアは Minskyが発明し最初に実装しました。 MIT Research Laboratory of Electronicsにおける PDP-1用Lisp実装の一部としてです。その後、 FenichelとYochelson（1969）が Multicsタイムシェアリングシステム用のLisp実装のために発展させました。後に、 Baker（1978）がガベージコレクション中に計算を停止する必要のないリアルタイム版を開発しました。Bakerのアイデアは Hewitt、 Lieberman、 Moon（Lieberman and Hewitt 1983を参照）によって拡張され、一部の構造はより揮発的で他の構造はより永続的であるという事実を利用するようになりました。
