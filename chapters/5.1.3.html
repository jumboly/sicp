5.1.3  
Subroutines
サブルーチン

When designing a machine to perform a computation, we would often prefer to arrange for components to be shared by different parts of the computation rather than duplicate the components. Consider a machine that includes two GCD computations—one that finds the GCD of the contents of registers a and b and one that finds the GCD of the contents of registers c and d. We might start by assuming we have a primitive gcd operation, then expand the two instances of gcd in terms of more primitive operations. Figure 5.9 shows just the GCD portions of the resulting machine's data paths, without showing how they connect to the rest of the machine. The figure also shows the corresponding portions of the machine's controller sequence.
計算を行うマシンを設計するとき、コンポーネントを重複させるよりも、計算の異なる部分で共有できるように配置することが望ましい場合がよくあります。2つの最大公約数（GCD）計算を含むマシンを考えましょう—1つはレジスタ a と b の内容の GCD を求め、もう1つはレジスタ c と d の内容の GCD を求めます。まずプリミティブな gcd 演算があると仮定し、その2つの gcd のインスタンスをより基本的な演算で展開することから始めるとよいでしょう。 図 5.9 は、結果として得られるマシンのデータパスのうち GCD 部分だけを示しており、マシンの残りの部分との接続は省略しています。この図には、マシンのコントローラシーケンスの対応する部分も示されています。

This machine has two remainder operation boxes and two boxes for testing equality. If the duplicated components are complicated, as is the remainder box, this will not be an economical way to build the machine. We can avoid duplicating the data-path components by using the same components for both GCD computations, provided that doing so will not affect the rest of the larger machine's computation. If the values in registers a and b are not needed by the time the controller gets to gcd_2 (or if these values can be moved to other registers for safekeeping), we can change the machine so that it uses registers a and b, rather than registers c and d, in computing the second GCD as well as the first. If we do this, we obtain the controller sequence shown in figure 5.10.
このマシンには剰余演算ボックスが2つと、等値テスト用のボックスが2つあります。剰余ボックスのように重複するコンポーネントが複雑な場合、これはマシンを構築する経済的な方法とは言えません。両方の GCD 計算で同じコンポーネントを使用すれば、データパスコンポーネントの重複を避けることができます。ただし、そうすることでマシン全体の残りの計算に影響を与えないことが条件です。コントローラが gcd_2 に到達するまでにレジスタ a と b の値が不要になっている場合（あるいはこれらの値を他のレジスタに退避できる場合）、2番目の GCD の計算でもレジスタ c と d の代わりにレジスタ a と b を使うようにマシンを変更できます。そうすると、図 5.10に示すコントローラシーケンスが得られます。

We have removed the duplicate data-path components (so that the data paths are again as in figure 5.1), but the controller now has two GCD sequences that differ only in their entry-point labels. It would be better to replace these two sequences by branches to a single sequence—a gcd subroutine—at the end of which we branch back to the correct place in the main instruction sequence. We can accomplish this as follows: Before branching to gcd, we place a distinguishing value (such as 0 or 1) into a special register, continue. At the end of the gcd subroutine we return either to after_gcd_1 or to after_gcd_2, depending on the value of the continue register. Figure 5.11 shows the relevant portion of the resulting controller sequence, which includes only a single copy of the gcd instructions.
重複するデータパスコンポーネントを取り除きました（データパスは再び図 5.1と同じになります）が、コントローラにはエントリポイントのラベルだけが異なる2つの GCD シーケンスが残っています。これら2つのシーケンスを、単一のシーケンス—gcd サブルーチン—への分岐に置き換え、その末尾でメインの命令シーケンスの正しい場所に戻るようにした方がよいでしょう。これは次のように実現できます。gcd に分岐する前に、特別なレジスタ continue に識別用の値（0 や 1 など）を格納します。gcd サブルーチンの末尾では、continue レジスタの値に応じて after_gcd_1 または after_gcd_2 のいずれかに戻ります。図 5.11は、結果として得られるコントローラシーケンスの該当部分を示しており、gcd 命令のコピーは1つだけです。

This is a reasonable approach for handling small problems, but it would be awkward if there were many instances of GCD computations in the controller sequence. To decide where to continue executing after the gcd subroutine, we would need tests in the data paths and branch instructions in the controller for all the places that use gcd. A more powerful method for implementing subroutines is to have the continue register hold the label of the entry point in the controller sequence at which execution should continue when the subroutine is finished. Implementing this strategy requires a new kind of connection between the data paths and the controller of a register machine: There must be a way to assign to a register a label in the controller sequence in such a way that this value can be fetched from the register and used to continue execution at the designated entry point.
これは小さな問題を扱うには合理的なアプローチですが、コントローラシーケンス内に GCD 計算のインスタンスが多数ある場合には厄介です。gcd サブルーチンの後でどこから実行を継続するかを決めるには、gcd を使用するすべての場所に対して、データパス内のテストとコントローラ内の分岐命令が必要になります。サブルーチンを実装するより強力な方法は、continue レジスタに、サブルーチン完了後に実行を継続すべきコントローラシーケンス内のエントリポイントのラベルを保持させることです。この戦略を実装するには、レジスタマシンのデータパスとコントローラの間に新しい種類の接続が必要です。すなわち、コントローラシーケンス内のラベルをレジスタに代入し、その値をレジスタから取り出して指定されたエントリポイントから実行を継続できるようにする方法が必要です。

To reflect this ability, we will extend the assign instruction of the register-machine language to allow a register to be assigned as value a label from the controller sequence (as a special kind of constant). We will also extend the go_to instruction to allow execution to continue at the entry point described by the contents of a register rather than only at an entry point described by a constant label. Using these new constructs we can terminate the gcd subroutine with a branch to the location stored in the continue register. This leads to the controller sequence shown in figure 5.12.
この能力を反映するために、レジスタマシン言語の assign 命令を拡張して、コントローラシーケンスのラベルを（特殊な定数として）レジスタに代入できるようにします。また、 go_to 命令も拡張して、定数ラベルで記述されたエントリポイントだけでなく、レジスタの内容で記述されたエントリポイントからも実行を継続できるようにします。これらの新しい構成要素を使えば、gcd サブルーチンを continue レジスタに格納された場所への分岐で終了させることができます。これにより、図 5.12に示すコントローラシーケンスが得られます。

A machine with more than one subroutine could use multiple continuation registers (e.g., gcd_continue, factorial_continue) or we could have all subroutines share a single continue register. Sharing is more economical, but we must be careful if we have a subroutine (sub1) that calls another subroutine (sub2). Unless sub1 saves the contents of continue in some other register before setting up continue for the call to sub2, sub1 will not know where to go when it is finished. The mechanism developed in the next section to handle recursion also provides a better solution to this problem of nested subroutine calls.
複数のサブルーチンを持つマシンでは、複数の継続レジスタを使用できます（例えば gcd_continue や factorial_continue）。あるいは、すべてのサブルーチンで単一の continue レジスタを共有することもできます。共有する方がより経済的ですが、あるサブルーチン（sub1）が別のサブルーチン（sub2）を呼び出す場合には注意が必要です。sub1 が sub2 の呼び出しのために continue を設定する前に、continue の内容を別のレジスタに退避しておかなければ、sub1 は自身の処理が終わった後にどこへ戻ればよいかわからなくなります。次の節で再帰を扱うために開発するメカニズムは、このネストされたサブルーチン呼び出しの問題に対するより良い解決策も提供します。
