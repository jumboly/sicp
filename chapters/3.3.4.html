3.3.4  
A Simulator for Digital Circuits
デジタル回路のシミュレータ

Designing complex digital systems, such as computers, is an important engineering activity. Digital systems are constructed by interconnecting simple elements. Although the behavior of these individual elements is simple, networks of them can have very complex behavior. Computer simulation of proposed circuit designs is an important tool used by digital systems engineers. In this section we design a system for performing digital logic simulations. This system typifies a kind of program called an event-driven simulation, in which actions (events) trigger further events that happen at a later time, which in turn trigger more events, and so on.
コンピュータのような複雑なデジタルシステムの設計は、重要な工学的活動です。デジタルシステムは、単純な要素を相互に接続することで構築されます。個々の要素の振る舞いは単純ですが、それらのネットワークは非常に複雑な振る舞いを示すことがあります。提案された回路設計のコンピュータシミュレーションは、デジタルシステムエンジニアにとって重要なツールです。この節では、デジタル論理シミュレーションを行うシステムを設計します。このシステムは、 イベント駆動シミュレーションと呼ばれるプログラムの典型的な例です。イベント駆動シミュレーションでは、アクション（イベント）がさらなるイベントを引き起こし、それが後の時点で発生し、さらにそれがまた別のイベントを引き起こす、というように続きます。

Our computational model of a circuit will be composed of objects that correspond to the elementary components from which the circuit is constructed. There are wires, which carry digital signals. A digital signal may at any moment have only one of two possible values, 0 and 1. There are also various types of digital function boxes, which connect wires carrying input signals to other output wires. Such boxes produce output signals computed from their input signals. The output signal is delayed by a time that depends on the type of the function box. For example, an inverter is a primitive function box that inverts its input. If the input signal to an inverter changes to 0, then one inverter-delay later the inverter will change its output signal to 1. If the input signal to an inverter changes to 1, then one inverter-delay later the inverter will change its output signal to 0. We draw an inverter symbolically as in figure 3.47. An and-gate, also shown in figure 3.47, is a primitive function box with two inputs and one output. It drives its output signal to a value that is the logical and of the inputs. That is, if both of its input signals become 1, then one and-gate-delay time later the and-gate will force its output signal to be 1; otherwise the output will be 0. An or-gate is a similar two-input primitive function box that drives its output signal to a value that is the logical or of the inputs. That is, the output will become 1 if at least one of the input signals is 1; otherwise the output will become 0.
回路の計算モデルは、回路を構成する基本的な部品に対応するオブジェクトで構成されます。まず ワイヤがあり、これは デジタル信号を伝えます。デジタル信号は、どの瞬間においても 0 と 1 の二つの値のうちいずれか一方のみを取ります。また、さまざまな種類のデジタル ファンクションボックスがあり、入力信号を伝えるワイヤを別の出力ワイヤに接続します。このようなボックスは、入力信号から計算された出力信号を生成します。出力信号には、ファンクションボックスの種類に応じた時間の 遅延があります。例えば、 インバータは入力を反転するプリミティブなファンクションボックスです。インバータへの入力信号が 0 に変化すると、inverter-delay 後にインバータは出力信号を 1 に変更します。入力信号が 1 に変化すると、inverter-delay 後に出力信号を 0 に変更します。インバータは図 3.47のように記号的に描きます。 ANDゲートも図 3.47に示されていますが、二つの入力と一つの出力を持つプリミティブなファンクションボックスです。その出力信号を、入力の 論理積の値にします。つまり、両方の入力信号が 1 になると、and-gate-delay 時間後に ANDゲートは出力信号を 1 にします。それ以外の場合、出力は 0 になります。 ORゲートも同様に二つの入力を持つプリミティブなファンクションボックスで、出力信号を入力の 論理和の値にします。つまり、入力信号のうち少なくとも一つが 1 であれば出力は 1 になり、それ以外の場合は出力は 0 になります。

We can connect primitive functions together to construct more complex functions. To accomplish this we wire the outputs of some function boxes to the inputs of other function boxes. For example, the half-adder circuit shown in figure 3.48 consists of an or-gate, two and-gates, and an inverter. It takes two input signals, $A$ and $B$, and has two output signals, $S$ and $C$. $S$ will become 1 whenever precisely one of $A$ and $B$ is 1, and $C$ will become 1 whenever $A$ and $B$ are both 1. We can see from the figure that, because of the delays involved, the outputs may be generated at different times. Many of the difficulties in the design of digital circuits arise from this fact.
プリミティブ関数を接続することで、より複雑な関数を構築できます。これを実現するために、あるファンクションボックスの出力を別のファンクションボックスの入力に配線します。例えば、図 3.48に示す 半加算器回路は、一つの ORゲート、二つの ANDゲート、一つのインバータで構成されています。二つの入力信号 $A$ と $B$ を受け取り、二つの出力信号 $S$ と $C$ を持ちます。$S$ は $A$ と $B$ のうちちょうど一方が 1 のときに 1 になり、$C$ は $A$ と $B$ の両方が 1 のときに 1 になります。図からわかるように、遅延が関係するため、出力は異なるタイミングで生成される可能性があります。デジタル回路設計の難しさの多くは、この事実から生じます。

We will now build a program for modeling the digital logic circuits we wish to study. The program will construct computational objects modeling the wires, which will hold the signals. Function boxes will be modeled by functions that enforce the correct relationships among the signals.
これから、研究対象のデジタル論理回路をモデル化するプログラムを構築します。このプログラムは、信号を保持するワイヤをモデル化する計算オブジェクトを構築します。ファンクションボックスは、信号間の正しい関係を強制する 関数 によってモデル化されます。

One basic element of our simulation will be a function make_wire, which constructs wires. For example, we can construct six wires as follows:
シミュレーションの基本要素の一つは、ワイヤを構築する 関数 make_wire です。例えば、次のように六つのワイヤを構築できます。 
const a = make_wire();
const b = make_wire();
const c = make_wire();
const d = make_wire();
const e = make_wire();
const s = make_wire();
We attach a function box to a set of wires by calling a function that constructs that kind of box. The arguments to the constructor function are the wires to be attached to the box. For example, given that we can construct and-gates, or-gates, and inverters, we can wire together the half-adder shown in figure 3.48:
ファンクションボックスをワイヤのセットに接続するには、そのボックスを構築する 関数 を呼び出します。コンストラクタ 関数 への引数は、ボックスに接続するワイヤです。例えば、ANDゲート、ORゲート、インバータを構築できるとすると、図 3.48に示す半加算器を次のように配線できます。 
or_gate(a, b, d);

"ok"
and_gate(a, b, c);

"ok"
inverter(c, e);

"ok"
and_gate(d, e, s);

"ok"

Better yet, we can explicitly name this operation by defining a function half_adder that constructs this circuit, given the four external wires to be attached to the half-adder:
さらに良いことに、この操作に明示的に名前を付けることができます。半加算器に接続する四つの外部ワイヤを受け取り、この回路を構築する 関数 half_adder を定義すればよいのです。 
function half_adder(a, b, s, c) {
    const d = make_wire();
    const e = make_wire();
    or_gate(a, b, d);
    and_gate(a, b, c);
    inverter(c, e);
    and_gate(d, e, s);
    return "ok";
}
The advantage of making this definition is that we can use half_adder itself as a building block in creating more complex circuits. Figure 3.49, for example, shows a full-adder composed of two half-adders and an or-gate.
この定義の利点は、 half_adder 自体をより複雑な回路を作るためのビルディングブロックとして使えることです。例えば、図 3.49は、二つの半加算器と一つの ORゲートで構成される 全加算器を示しています。
[1]
We can construct a full-adder as follows:
全加算器は次のように構築できます。
function full_adder(a, b, c_in, sum, c_out) {
    const s = make_wire();
    const c1 = make_wire();
    const c2 = make_wire();
    half_adder(b, c_in, s, c1);
    half_adder(a, s, sum, c2);
    or_gate(c1, c2, c_out);
    return "ok";
}
Having defined full_adder as a function, we can now use it as a building block for creating still more complex circuits. (For example, see exercise 3.30.)
full_adder を 関数 として定義したので、さらに複雑な回路を作るためのビルディングブロックとして使えます。（例えば、練習問題 3.30を参照してください。）

In essence, our simulator provides us with the tools to construct a language of circuits. If we adopt the general perspective on languages with which we approached the study of JavaScript in section 1.1, we can say that the primitive function boxes form the primitive elements of the language, that wiring boxes together provides a means of combination, and that specifying wiring patterns as functions serves as a means of abstraction.
本質的に、このシミュレータは回路の言語を構築するためのツールを提供しています。 1.1節で JavaScript を学んだときと同じ、言語に対する一般的な視点を採用すると、プリミティブなファンクションボックスが言語のプリミティブな要素を形成し、ボックスを配線でつなぐことが組み合わせの手段を提供し、配線パターンを 関数 として定義することが抽象化の手段として機能する、と言えます。

Primitive function boxes
プリミティブなファンクションボックス

The primitive function boxes implement the forces by which a change in the signal on one wire influences the signals on other wires. To build function boxes, we use the following operations on wires:
  • get_signal($wire$)
    returns the current value of the signal on the wire.
  • set_signal($wire$, $new$-$value$):
    changes the value of the signal on the wire to the new value.
  • add_action($wire$, $function$-$of$-$no$-$arguments$):
    asserts that the designated function should be run whenever the signal on the wire changes value. Such functions are the vehicles by which changes in the signal value on the wire are communicated to other wires.
In addition, we will make use of a function after_delay that takes a time delay and a function to be run and executes the given function after the given delay.
プリミティブなファンクションボックスは、 あるワイヤの信号の変化が他のワイヤの信号に影響を及ぼす力を実装します。ファンクションボックスを構築するために、ワイヤに対する以下の操作を使います。
  • get_signal($wire$)
    ワイヤ上の信号の現在の値を返します。
  • set_signal($wire$, $new$-$value$):
    ワイヤ上の信号の値を新しい値に変更します。
  • add_action($wire$, $function$-$of$-$no$-$arguments$):
    ワイヤ上の信号の値が変化したときに、指定された 関数 が実行されるべきことを宣言します。このような 関数 は、ワイヤ上の信号値の変化を他のワイヤに伝える手段です。
さらに、時間遅延と実行する 関数 を受け取り、指定された遅延の後にその 関数 を実行する 関数 after_delay も使います。

Using these functions, we can define the primitive digital logic functions. To connect an input to an output through an inverter, we use add_action to associate with the input wire a function that will be run whenever the signal on the input wire changes value. The function computes the logical_not of the input signal, and then, after one inverter_delay, sets the output signal to be this new value:
これらの 関数 を使って、プリミティブなデジタル論理関数を定義できます。インバータを通じて入力を出力に接続するには、 add_action を使って、入力ワイヤに、信号の値が変化するたびに実行される 関数 を関連付けます。この 関数 は入力信号の logical_not を計算し、 inverter_delay 後に出力信号をこの新しい値に設定します。 
function inverter(input, output) {
    function invert_input() {
        const new_value = logical_not(get_signal(input));
        after_delay(inverter_delay, 
                    () => set_signal(output, new_value));
    }
    add_action(input, invert_input);
    return "ok";
}
function logical_not(s) {
    return s === 0
           ? 1
           : s === 1
           ? 0
           : error(s, "invalid signal");
}

An and-gate is a little more complex. The action function must be run if either of the inputs to the gate changes. It computes the logical_and (using a function analogous to logical_not) of the values of the signals on the input wires and sets up a change to the new value to occur on the output wire after one and_gate_delay.
ANDゲートはもう少し複雑です。アクション 関数 は、ゲートへのいずれかの入力が変化した場合に実行されなければなりません。入力ワイヤ上の信号値の logical_and （logical_not に類似した関数を使用） を計算し、 and_gate_delay 後に出力ワイヤの値が新しい値に変化するよう設定します。 
function and_gate(a1, a2, output) {
    function and_action_function() {
        const new_value = logical_and(get_signal(a1),
                                      get_signal(a2));
        after_delay(and_gate_delay, 
                    () => set_signal(output, new_value));
    }
    add_action(a1, and_action_function);
    add_action(a2, and_action_function);
    return "ok";
}

Representing wires
ワイヤの表現

A wire in our simulation will be a computational object with two local state variables: a signal_value (initially taken to be 0) and a collection of action_functions to be run when the signal changes value. We implement the wire, using message-passing style, as a collection of local functions together with a dispatch function that selects the appropriate local operation, just as we did with the simple bank-account object in section  3.1.1:
シミュレーションにおけるワイヤは、2つの局所状態変数を持つ計算オブジェクトです。 signal_value （初期値は0）と、信号の値が変化したときに実行される action_functions のコレクションです。ワイヤの実装には、 メッセージパッシングスタイルを用い、局所 関数 のコレクションと、適切な局所操作を選択する dispatch 関数 を組み合わせます。これは3.1.1節の単純な銀行口座オブジェクトで行ったのと同じ方法です。 
function make_wire() {
    let signal_value = 0;
    let action_functions = null;
    function set_my_signal(new_value) {
        if (signal_value !== new_value) {
            signal_value = new_value;
            return call_each(action_functions);
        } else {
            return "done";
        }
    }
    function accept_action_function(fun) {
        action_functions = pair(fun, action_functions);
        fun();
    }
    function dispatch(m) {
        return m === "get_signal"
               ? signal_value
               : m === "set_signal"
               ? set_my_signal
               : m === "add_action"
               ? accept_action_function
               : error(m, "unknown operation -- wire");
    }
    return dispatch;
}
The local function set_my_signal tests whether the new signal value changes the signal on the wire. If so, it runs each of the action functions, using the following function call_each, which calls each of the items in a list of no-argument functions:
局所 関数 set_my_signal は、新しい信号値がワイヤの信号を変化させるかどうかをテストします。変化する場合は、以下の 関数 call_each を使って各アクション 関数 を実行します。 call_each は、引数なし 関数 のリストの各要素を呼び出します。 
function call_each(functions) {
    if (is_null(functions)) {
        return "done";
    } else {
        head(functions)();
        return call_each(tail(functions));
    }
}
The local function accept_action_function adds the given function to the list of functions to be run, and then runs the new function once. (See exercise 3.31.)
局所 関数 accept_action_function は、与えられた 関数 を実行対象の 関数 のリストに追加し、その新しい 関数 を1回実行します（練習問題 3.31を参照）。

With the local dispatch function set up as specified, we can provide the following functions to access the local operations on wires:
上記のように局所 dispatch 関数 を設定すれば、ワイヤの局所操作にアクセスする以下の 関数 を提供できます。
[2] 
function get_signal(wire) {
    return wire("get_signal");
}
function set_signal(wire, new_value) {
    return wire("set_signal")(new_value);
}
function add_action(wire, action_function) {
    return wire("add_action")(action_function);
}

Wires, which have time-varying signals and may be incrementally attached to devices, are typical of mutable objects. We have modeled them as functions with local state variables that are modified by assignment. When a new wire is created, a new set of state variables is allocated (by the let statements in make_wire) and a new dispatch function is constructed and returned, capturing the environment with the new state variables.
ワイヤは、時間とともに変化する信号を持ち、デバイスに段階的に接続できるという点で、ミュータブルなオブジェクトの典型例です。ワイヤは、代入によって変更される局所状態変数を持つ 関数 としてモデル化しました。新しいワイヤが作成されると、新しい状態変数のセットが（ make_wire の let 文 によって）割り当てられ、新しい dispatch 関数 が構築されて返されます。この関数は新しい状態変数を含む環境を捕捉しています。

The wires are shared among the various devices that have been connected to them. Thus, a change made by an interaction with one device will affect all the other devices attached to the wire. The wire communicates the change to its neighbors by calling the action functions provided to it when the connections were established.
ワイヤは、接続されたさまざまなデバイス間で共有されます。したがって、あるデバイスとのインタラクションによって行われた変更は、そのワイヤに接続された他のすべてのデバイスに影響を与えます。ワイヤは、接続が確立されたときに提供されたアクション 関数 を呼び出すことで、変更を隣接するデバイスに伝達します。

The agenda
アジェンダ

The only thing needed to complete the simulator is after_delay. The idea here is that we maintain a data structure, called an agenda, that contains a schedule of things to do. The following operations are defined for agendas:
シミュレータを完成させるために残っているのは after_delay だけです。ここでの考え方は、実行すべきことのスケジュールを含むアジェンダと呼ばれるデータ構造を維持するということです。アジェンダに対して以下の操作が定義されています。
  • make_agenda():
    returns a new empty agenda.
  • make_agenda():
    新しい空のアジェンダを返します。
  • is_empty_agenda($agenda$)
    is true if the specified agenda is empty.
  • first_agenda_item($agenda$)
    returns the first item on the agenda.
  • remove_first_agenda_item($agenda$)
    modifies the agenda by removing the first item.
  • add_to_agenda($time$, $action$, $agenda$)
    modifies the agenda by adding the given action function to be run at the specified time.
  • current_time($agenda$)
    returns the current simulation time.
  • is_empty_agenda($agenda$)
    指定されたアジェンダが空の場合に真を返します。
  • first_agenda_item($agenda$)
    アジェンダの最初の項目を返します。
  • remove_first_agenda_item($agenda$)
    最初の項目を削除してアジェンダを変更します。
  • add_to_agenda($time$, $action$, $agenda$)
    指定された時刻に実行するアクション 関数 を追加してアジェンダを変更します。

    現在のシミュレーション時刻を返します。

The particular agenda that we use is denoted by the_agenda. The function after_delay adds new elements to the_agenda:
使用する特定のアジェンダは the_agenda で表されます。 関数 after_delay は the_agenda に新しい要素を追加します。 
function after_delay(delay, action) {
    add_to_agenda(delay + current_time(the_agenda),
                  action,
                  the_agenda);
}

The simulation is driven by the function propagate, which executes each function on the_agenda in sequence. In general, as the simulation runs, new items will be added to the agenda, and propagate will continue the simulation as long as there are items on the agenda:
シミュレーションは関数 propagate によって駆動されます。この関数は the_agenda 上の各関数を順番に実行します。 一般に、シミュレーションの実行中に新しい項目がアジェンダに追加され、propagate はアジェンダに項目がある限りシミュレーションを続行します。 
function propagate() {
    if (is_empty_agenda(the_agenda)) {
        return "done";
    } else {
        const first_item = first_agenda_item(the_agenda);
        first_item();
        remove_first_agenda_item(the_agenda);
        return propagate();
    }
}

Implementing the agenda
アジェンダの実装

Finally, we give details of the agenda data structure, which holds the functions that are scheduled for future execution.
最後に、将来の実行がスケジュールされた 関数 を保持するアジェンダデータ構造の詳細を示します。

The agenda is made up of time segments. Each time segment is a pair consisting of a number (the time) and a queue (see exercise 3.32) that holds the functions that are scheduled to be run during that time segment.
アジェンダは タイムセグメントで構成されています。各タイムセグメントは、数値（時刻）と、そのタイムセグメント中に実行がスケジュールされた 関数 を保持する キュー（練習問題 3.32を参照）からなるペアです。 
function make_time_segment(time, queue) {
   return pair(time, queue);
}
function segment_time(s) { return head(s); }

function segment_queue(s) { return tail(s); }
We will operate on the time-segment queues using the queue operations described in section 3.3.2.
タイムセグメントのキューは、3.3.2節で説明したキュー操作を使って操作します。

The agenda itself is a one-dimensional table of time segments. It differs from the tables described in section 3.3.3 in that the segments will be sorted in order of increasing time. In addition, we store the current time (i.e., the time of the last action that was processed) at the head of the agenda. A newly constructed agenda has no time segments and has a current time of 0:
アジェンダ自体は、タイムセグメントの1次元の テーブルです。3.3.3節で説明したテーブルと異なるのは、セグメントが時刻の昇順でソートされる点です。さらに、アジェンダの先頭に 現在の時刻（つまり、最後に処理されたアクションの時刻）を格納します。新しく構築されたアジェンダにはタイムセグメントがなく、現在の時刻は0です。
[3] 
function make_agenda() { return list(0); }

function current_time(agenda) { return head(agenda); }

function set_current_time(agenda, time) {
   set_head(agenda, time);
}
function segments(agenda) { return tail(agenda); }

function set_segments(agenda, segs) {
   set_tail(agenda, segs);
}
function first_segment(agenda) { return head(segments(agenda)); }

function rest_segments(agenda) { return tail(segments(agenda)); }

An agenda is empty if it has no time segments:
アジェンダは、タイムセグメントがない場合に空です。 
function is_empty_agenda(agenda) {
   return is_null(segments(agenda));
}

To add an action to an agenda, we first check if the agenda is empty. If so, we create a time segment for the action and install this in the agenda. Otherwise, we scan the agenda, examining the time of each segment. If we find a segment for our appointed time, we add the action to the associated queue. If we reach a time later than the one to which we are appointed, we insert a new time segment into the agenda just before it. If we reach the end of the agenda, we must create a new time segment at the end.
アジェンダにアクションを追加するには、まずアジェンダが空かどうかを確認します。空であれば、そのアクション用のタイムセグメントを作成し、アジェンダにインストールします。そうでなければ、アジェンダをスキャンして各セグメントの時刻を調べます。指定された時刻のセグメントが見つかれば、関連するキューにアクションを追加します。指定された時刻よりも後の時刻に達した場合は、その直前に新しいタイムセグメントを挿入します。アジェンダの末尾に達した場合は、末尾に新しいタイムセグメントを作成する必要があります。 
function add_to_agenda(time, action, agenda) {
   function belongs_before(segs) {
      return is_null(segs) || time < segment_time(head(segs));
   }
   function make_new_time_segment(time, action) {
      const q = make_queue();
      insert_queue(q, action);
      return make_time_segment(time, q);
   }
   function add_to_segments(segs) {
      if (segment_time(head(segs)) === time) {
          insert_queue(segment_queue(head(segs)), action);
      } else {
          const rest = tail(segs);
          if (belongs_before(rest)) {
              set_tail(segs, pair(make_new_time_segment(time, action),
                                  tail(segs)));
          } else {
              add_to_segments(rest);
          }
      }
   }
   const segs = segments(agenda);
   if (belongs_before(segs)) {
       set_segments(agenda,
                    pair(make_new_time_segment(time, action), segs));
   } else {
       add_to_segments(segs);
   }
}

The function that removes the first item from the agenda deletes the item at the front of the queue in the first time segment. If this deletion makes the time segment empty, we remove it from the list of segments:
アジェンダから最初の項目を削除する 関数 は、最初のタイムセグメントのキューの先頭にある項目を削除します。この削除によってタイムセグメントが空になった場合は、セグメントのリストからそれを削除します。
[4] 
function remove_first_agenda_item(agenda) {
   const q = segment_queue(first_segment(agenda));
   delete_queue(q);
   if (is_empty_queue(q)) {
       set_segments(agenda, rest_segments(agenda));
   } else {}
}

The first agenda item is found at the head of the queue in the first time segment. Whenever we extract an item, we also update the current time:
アジェンダの最初の項目は、最初のタイムセグメントのキューの先頭にあります。項目を取り出すたびに、現在の時刻も更新します。
[5] 
function first_agenda_item(agenda) {
    if (is_empty_agenda(agenda)) {
        error("agenda is empty -- first_agenda_item");
    } else {
        const first_seg = first_segment(agenda);
        set_current_time(agenda, segment_time(first_seg));
        return front_queue(segment_queue(first_seg));
    }
}

These functions are simply syntactic sugar that allow us to use ordinary functional syntax to access the local functions of objects. It is striking that we can interchange the role of functions and data in such a simple way. For example, if we write wire("get_signal") we think of wire as a function that is called with the message "get_signal" as input. Alternatively, writing get_signal(wire) encourages us to think of wire as a data object that is the input to a function get_signal. The truth of the matter is that, in a language in which we can deal with functions as objects, there is no fundamental difference between functions and data, and we can choose our syntactic sugar to allow us to program in whatever style we choose.
これらの 関数 は単なる糖衣構文であり、 通常の 関数的な 構文でオブジェクトの局所 関数 にアクセスできるようにするものです。 関数 とデータの役割をこれほど簡単に交換できるのは注目に値します。例えば、 wire("get_signal") と書くと、wire はメッセージ "get_signal" を入力として呼び出される 関数 だと考えます。一方、 get_signal(wire) と書くと、wire は 関数 get_signal への入力であるデータオブジェクトだと考えるようになります。実際のところ、 関数 をオブジェクトとして扱える言語では、関数とデータの間に根本的な違いはなく、好みのスタイルでプログラミングできるように糖衣構文を選べるのです。
