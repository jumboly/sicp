5.3.1  
Memory as Vectors
ベクトルとしてのメモリ

A conventional computer memory can be thought of as an array of cubbyholes, each of which can contain a piece of information. Each cubbyhole has a unique name, called its address or location. Typical memory systems provide two primitive operations: one that fetches the data stored in a specified location and one that assigns new data to a specified location. Memory addresses can be incremented to support sequential access to some set of the cubbyholes. More generally, many important data operations require that memory addresses be treated as data, which can be stored in memory locations and manipulated in machine registers. The representation of list structure is one application of such address arithmetic.
一般的なコンピュータメモリは、それぞれが情報の断片を格納できる仕切り付きの棚の配列と考えることができます。各仕切りには、 アドレスまたは ロケーションと呼ばれる一意の名前が付いています。典型的なメモリシステムは2つのプリミティブ演算を提供します。1つは指定されたロケーションに格納されたデータを取り出す演算、もう1つは指定されたロケーションに新しいデータを割り当てる演算です。メモリアドレスをインクリメントすることで、仕切りの集合への逐次アクセスが可能になります。より一般的には、多くの重要なデータ操作では、メモリアドレスをデータとして扱い、メモリのロケーションに格納したりマシンレジスタで操作したりする必要があります。リスト構造の表現は、そのような アドレス算術の一つの応用です。

To model computer memory, we use a new kind of data structure called a vector. Abstractly, a vector is a compound data object whose individual elements can be accessed by means of an integer index in an amount of time that is independent of the index.
コンピュータメモリをモデル化するために、 ベクトルと呼ばれる新しい種類のデータ構造を使用します。抽象的には、ベクトルは複合データオブジェクトであり、その個々の要素には整数のインデックスを使ってアクセスでき、アクセスに要する時間はインデックスに依存しません。
[1]
In order to describe memory operations, we use two functions for manipulating vectors:
メモリ操作を記述するために、ベクトルを操作する2つの 関数 を使用します。
[2]
  • vector_ref($vector$, $n$)
    returns the $n$th element of the vector.
    はベクトルの$n$番目の要素を返します。
  • vector_set($vector$, $n$, $value$)
    sets the $n$th element of the vector to the designated value.
    はベクトルの$n$番目の要素を指定された値に設定します。
For example, if v is a vector, then vector_ref(v, 5) gets the fifth entry in the vector v and vector_set(v, 5, 7) changes the value of the fifth entry of the vector v to 7.
たとえば、v がベクトルであるとすると、 vector_ref(v, 5) はベクトル v の5番目のエントリを取得し、 vector_set(v, 5, 7) はベクトル v の5番目のエントリの値を7に変更します。
[3]
For computer memory, this access can be implemented through the use of address arithmetic to combine a base address that specifies the beginning location of a vector in memory with an index that specifies the offset of a particular element of the vector.
コンピュータメモリの場合、このアクセスはアドレス算術を使って実装できます。メモリ内のベクトルの開始ロケーションを指定するベースアドレスと、ベクトルの特定の要素のオフセットを指定するインデックスを組み合わせるのです。

Representing data
データの表現

We can use vectors to implement the basic pair structures required for a list-structured memory. Let us imagine that computer memory is divided into two vectors: the_heads and the_tails. We will represent list structure as follows: A pointer to a pair is an index into the two vectors. The head of the pair is the entry in the_heads with the designated index, and the tail of the pair is the entry in the_tails with the designated index. We also need a representation for objects other than pairs (such as numbers and strings) and a way to distinguish one kind of data from another. There are many methods of accomplishing this, but they all reduce to using typed pointers, that is, to extending the notion of pointer to include information on data type.
ベクトルを使って、リスト構造メモリに必要な基本的なペア構造を実装できます。コンピュータメモリが2つのベクトル、すなわち the_heads と the_tails に分割されていると想像してみましょう。リスト構造は次のように表現します。ペアへのポインタは、2つのベクトルへのインデックスです。ペアの head は、指定されたインデックスでの the_heads のエントリであり、ペアの tail は、指定されたインデックスでの the_tails のエントリです。ペア以外のオブジェクト（数値や 文字列） の表現と、データの種類を区別する方法も必要です。これを実現する方法は多数ありますが、いずれも結局は 型付きポインタを使うことに帰着します。つまり、ポインタの概念を拡張して、データ型の情報を含めるのです。
[4]
The data type enables the system to distinguish a pointer to a pair (which consists of the pair data type and an index into the memory vectors) from pointers to other kinds of data (which consist of some other data type and whatever is being used to represent data of that type). Two data objects are considered to be the same (===) if their pointers are identical. Figure 5.18 illustrates the use of this method to represent list(list(1, 2), 3, 4), whose box-and-pointer diagram is also shown. We use letter prefixes to denote the data-type information. Thus, a pointer to the pair with index 5 is denoted p5, the empty list is denoted by the pointer e0, and a pointer to the number 4 is denoted n4. In the box-and-pointer diagram, we have indicated at the lower left of each pair the vector index that specifies where the head and tail of the pair are stored. The blank locations in the_heads and the_tails may contain parts of other list structures (not of interest here).
データ型により、システムはペアへのポインタ（pairデータ型とメモリベクトルへのインデックスで構成される）を、他の種類のデータへのポインタ（他のデータ型とそのデータ型の表現に使われるものとで構成される）と区別できます。2つのデータオブジェクトは、そのポインタが同一であれば 同じ （===） であるとみなされます。 図 5.18 は、この方法を使って list(list(1, 2), 3, 4) を表現する様子を示しています。ボックスとポインタの図も合わせて示しています。データ型情報を表すために文字の接頭辞を使用します。したがって、インデックス 5のペアへのポインタは p5 と表記され、空リストはポインタ e0 で表記され、数値 4へのポインタは n4 と表記されます。ボックスとポインタの図では、各ペアの左下に、そのペアの head と tail が格納されている場所を指定するベクトルのインデックスを示しています。 the_heads と the_tails の空白のロケーションには、他のリスト構造の部品が入っている可能性があります（ここでは関係ありません）。

A pointer to a number, such as n4, might consist of a type indicating numeric data together with the actual representation of the number 4.
n4 のような数値へのポインタは、数値データであることを示す型と、数値4の実際の表現を組み合わせたものになるかもしれません。
[5]
To deal with numbers that are too large to be represented in the fixed amount of space allocated for a single pointer, we could use a distinct bignum data type, for which the pointer designates a list in which the parts of the number are stored.
1つのポインタに割り当てられた固定量の空間では表現できないほど大きな数値を扱うには、別の bignum データ型を使用できます。この場合、ポインタは数値の各部分が格納されたリストを指します。
[6]

A string might be represented as a typed pointer that designates a sequence of the characters that form the string's printed representation. The parser constructs such a sequence when it encounters a string literal, and the string-concatenation operator + and string-producing primitive functions such as stringify construct such a sequence. Since we want two instances of a string to be recognized as the same string by === and we want === to be a simple test for equality of pointers, we must ensure that if the system sees the same string twice, it will use the same pointer (to the same sequence of characters) to represent both occurrences. To accomplish this, the system maintains a table, called the string pool, of all the strings it has ever encountered. When the system is about to construct a string, it checks the string pool to see if it has ever before seen the same string. If it has not, it constructs a new string (a typed pointer to a new character sequence) and enters this pointer in the string pool. If the system has seen the string before, it returns the string pointer stored in the string pool. This process of replacing strings by unique pointers is called string interning.
文字列は、その文字列の印字表現を構成する文字の列を指す型付きポインタとして表現されるかもしれません。 パーサは文字列リテラルに出会うとこのような列を構築し、文字列連結演算子 + や、stringify のような文字列を生成するプリミティブ関数もこのような列を構築します。2つの文字列のインスタンスが === によって同じ文字列として認識されるようにしたいのであり、また === がポインタの等価性の単純なテストであるようにしたいのですから、システムが同じ文字列を2回見た場合に、両方の出現を表現するために同じポインタ（同じ文字列への）を使うようにしなければなりません。これを実現するために、システムはこれまでに出会ったすべての文字列の 文字列プールと呼ばれるテーブルを保持しています。システムが文字列を構築しようとするとき、文字列プールをチェックして、以前に同じ文字列を見たことがあるかどうか調べます。見たことがなければ、新しい文字列（新しい文字列への型付きポインタ）を構築し、このポインタを文字列プールに登録します。以前にその文字列を見たことがあれば、文字列プールに格納されている文字列ポインタを返します。文字列を一意のポインタに置き換えるこのプロセスは、 文字列インターニングと呼ばれます。

Implementing the primitive list operations
プリミティブなリスト操作の実装

Given the above representation scheme, we can replace each primitive list operation of a register machine with one or more primitive vector operations. We will use two registers, the_heads and the_tails, to identify the memory vectors, and will assume that vector_ref and vector_set are available as primitive operations. We also assume that numeric operations on pointers (such as incrementing a pointer, using a pair pointer to index a vector, or adding two numbers) use only the index portion of the typed pointer.
上記の表現方式が与えられれば、レジスタマシンの各プリミティブリスト操作を、1つ以上のプリミティブなベクトル操作に置き換えることができます。2つのレジスタ、 the_heads と the_tails をメモリベクトルの識別に使用し、 vector_ref と vector_set がプリミティブ演算として利用可能であると仮定します。また、ポインタに対する数値演算（ポインタのインクリメント、ペアポインタを使ったベクトルのインデックス指定、2つの数値の加算など）は、型付きポインタのインデックス部分のみを使用すると仮定します。

For example, we can make a register machine support the instructions
たとえば、レジスタマシンに次の命令をサポートさせることができます。
assign($reg$$_1$, list(op("head"), reg($reg$$_2$))) assign($reg$$_1$, list(op("tail"), reg($reg$$_2$)))
if we implement these, respectively, as
これらをそれぞれ次のように実装すればよいのです。
assign($reg$$_1$, list(op("vector_ref"), reg("the_heads"), reg($reg$$_2$))) assign($reg$$_1$, list(op("vector_ref"), reg("the_tails"), reg($reg$$_2$)))
The instructions
次の命令は
perform(list(op("set_head"), reg($reg$$_1$), reg($reg$$_2$))) perform(list(op("set_tail"), reg($reg$$_1$), reg($reg$$_2$)))
are implemented as
次のように実装されます。
perform(list(op("vector_set"), reg("the_heads"), reg($reg$$_1$), reg($reg$$_2$))) perform(list(op("vector_set"), reg("the_tails"), reg($reg$$_1$), reg($reg$$_2$)))

The operation pair is performed by allocating an unused index and storing the arguments to pair in the_heads and the_tails at that indexed vector position. We presume that there is a special register, free, that always holds a pair pointer containing the next available index, and that we can increment the index part of that pointer to find the next free location.
pair 操作 は、未使用のインデックスを割り当て、 pair への引数をそのインデックス位置の the_heads と the_tails に格納することで実行されます。次に利用可能なインデックスを含むペアポインタを常に保持する特別なレジスタ free があり、そのポインタのインデックス部分をインクリメントすることで次の空きロケーションを見つけられると仮定します。
[7]
For example, the instruction
たとえば、次の命令は
assign($reg$$_1$, list(op("pair"), reg($reg$$_2$), reg($reg$$_3$)))
is implemented as the following sequence of vector operations:
以下のベクトル操作の列として実装されます。
[8] perform(list(op("vector_set"), reg("the_heads"), reg("free"), reg($reg$$_2$))), perform(list(op("vector_set"), reg("the_tails"), reg("free"), reg($reg$$_3$))), assign($reg$$_1$, reg("free")), assign("free", list(op("+"), reg("free"), constant(1)))

The === operation
=== 操作
list(op("==="), reg($reg$$_1$), reg($reg$$_2$))
simply tests the equality of all fields in the registers, and predicates such as is_pair, is_null, is_string, and is_number need only check the type field.

Implementing stacks
スタックの実装

Although our register machines use stacks, we need do nothing special here, since stacks can be modeled in terms of lists. The stack can be a list of the saved values, pointed to by a special register the_stack. Thus, save($reg$) can be implemented as
レジスタマシンはスタックを使用しますが、スタックはリストを使ってモデル化できるので、ここでは特別なことをする必要はありません。スタックは、 特別なレジスタ the_stack が指す、保存された値のリストとすることができます。したがって、 save($reg$) は次のように実装できます。
assign("the_stack", list(op("pair"), reg($reg$), reg("the_stack")))
Similarly, restore($reg$) can be implemented as
同様に、 restore($reg$) は次のように実装できます。
assign($reg$, list(op("head"), reg("the_stack"))) assign("the_stack", list(op("tail"), reg("the_stack")))
and perform(list(op("initialize_stack"))) can be implemented as
そして、 perform(list(op("initialize_stack"))) は次のように実装できます。
assign("the_stack", constant(null))
These operations can be further expanded in terms of the vector operations given above. In conventional computer architectures, however, it is usually advantageous to allocate the stack as a separate vector. Then pushing and popping the stack can be accomplished by incrementing or decrementing an index into that vector.
これらの操作は、上記で与えたベクトル操作を使ってさらに展開できます。しかし、一般的なコンピュータアーキテクチャでは、通常、スタックを別のベクトルとして割り当てる方が有利です。そうすれば、スタックへのプッシュとポップは、そのベクトルへのインデックスをインクリメントまたはデクリメントすることで実現できます。

Type information may be encoded in a variety of ways, depending on the details of the machine on which the JavaScript system is to be implemented. The execution efficiency of JavaScript programs will be strongly dependent on how cleverly this choice is made, but it is difficult to formulate general design rules for good choices. The most straightforward way to implement typed pointers is to allocate a fixed set of bits in each pointer to be a type field that encodes the data type. Important questions to be addressed in designing such a representation include the following: How many type bits are required? How large must the vector indices be? How efficiently can the primitive machine instructions be used to manipulate the type fields of pointers? Machines that include special hardware for the efficient handling of type fields are said to have tagged architectures.
