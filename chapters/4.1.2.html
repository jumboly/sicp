4.1.2  
Representing Components
コンポーネント の表現

Programmers write programs as text, i.e. sequences of characters, entered in a programming environment or a text editor. To run our evaluator, we need to start with a representation of this program text as a JavaScript value. In section 2.3.1 we introduced strings to represent text. We would like to evaluate programs such as "const size = 2; 5 * size;" from section 1.1.2. Unfortunately, such program text does not provide enough structure to the evaluator. In this example, the program parts "size = 2" and "5 * size" look similar, but carry very different meanings. Abstract syntax functions such as declaration_value_expression would be difficult and error-prone to implement by examining the program text. In this section, we therefore introduce a function parse that translates program text to a tagged-list representation, reminiscent of the tagged data of section 2.4.2. For example, the application of parse to the program string above produces a data structure that reflects the structure of the program: a sequence consisting of a constant declaration associating the name size with the value 2 and a multiplication.
プログラマはプログラムをテキスト、すなわち文字の列として書き、プログラミング環境やテキストエディタに入力します。評価器を実行するには、このプログラムテキストを JavaScript の値として表現するところから始める必要があります。2.3.1節では、テキストを表現するために文字列を導入しました。1.1.2節の "const size = 2; 5 * size;" のようなプログラムを評価したいと考えています。しかし残念ながら、このようなプログラムテキストは評価器にとって十分な構造を提供しません。この例では、プログラムの部分 "size = 2" と "5 * size" は見た目が似ていますが、まったく異なる意味を持っています。 declaration_value_expression のような抽象構文関数を、プログラムテキストを調べて実装するのは困難でエラーが起きやすいでしょう。そこでこのセクションでは、プログラムテキストをタグ付きリスト表現に変換する関数 parse を導入します。これは2.4.2節のタグ付きデータを彷彿とさせるものです。たとえば、上のプログラム文字列に parse を適用すると、プログラムの構造を反映したデータ構造が生成されます。すなわち、名前 size を値 2 に関連付ける定数宣言と、乗算からなるシーケンスです。 
parse("const size = 2; 5 * size;");

list("sequence",
     list(list("constant_declaration",
               list("name", "size"), list("literal", 2)),
          list("binary_operator_combination", "*",
               list("literal", 5), list("name", "size"))))
The syntax functions used by the evaluator access the tagged-list representation produced by parse.
評価器が使用する構文関数は、 parse が生成するタグ付きリスト表現にアクセスします。

The evaluator is reminiscent of the symbolic differentiation program discussed in section 2.3.2. Both programs operate on symbolic data. In both programs, the result of operating on an object is determined by operating recursively on the pieces of the object and combining the results in a way that depends on the type of the object. In both programs we used data abstraction to decouple the general rules of operation from the details of how the objects are represented. In the differentiation program this meant that the same differentiation function could deal with algebraic expressions in prefix form, in infix form, or in some other form. For the evaluator, this means that the syntax of the language being evaluated is determined solely by parse and the functions that classify and extract pieces of the tagged lists produced by parse.
この評価器は、2.3.2節で議論した シンボリック微分プログラムを彷彿とさせます。どちらのプログラムもシンボリックな データ を操作します。どちらのプログラムでも、 オブジェクト に対する操作の結果は、その オブジェクト の構成要素に対して再帰的に操作を行い、 オブジェクト の型に応じた方法で結果を組み合わせることによって決まります。どちらのプログラムでも、操作の一般的な規則と、 オブジェクト がどのように表現されるかの詳細を切り離すために データ抽象を使いました。微分プログラムでは、同じ微分 関数が前置記法、中置記法、その他の形式の代数式を扱えることを意味しました。評価器においては、 評価される言語の構文は、parse と、parse が生成するタグ付きリストを分類し構成要素を取り出す関数によってのみ決定される ことを意味します。

Figure 4.3 depicts the abstraction barrier formed by the syntax predicates and selectors, which interface the evaluator to the tagged-list representation of programs, which in turn is separated from the string representation by parse. Below we describe the parsing of program components and list the corresponding syntax predicates and selectors, as well as constructors if they are needed.
図 4.3は、構文述語とセレクタによって形成される 抽象バリアを示しています。これらは評価器とプログラムのタグ付きリスト表現の間のインターフェースとなり、タグ付きリスト表現はさらに parse によって文字列表現から分離されています。以下では、プログラムコンポーネントの解析について説明し、対応する構文述語とセレクタ、そして必要な場合はコンストラクタを列挙します。

Literal expression

Literal expressions are parsed into tagged lists with tag "literal" and the actual value.
リテラル式は、タグ "literal" と実際の値を持つタグ付きリストに解析されます。
\[ \begin{align*} \ll\ \mathit{literal}\textit{-}\mathit{expression}\ \gg & = \texttt{list("literal", }\mathit{value}\texttt{)} \end{align*} \] where $value$ is the JavaScript value represented by the $literal$-$expression$ string. Here $\ll\ $$literal$-$expression$$\ \gg$ denotes the result of parsing the string $literal$-$expression$. 
parse("1;");

list("literal", 1)
parse("'hello world';");

list("literal", "hello world")
parse("null;");

list("literal", null)
The syntax predicate for literal expressions is is_literal.
リテラル式の構文述語は is_literal です。 
function is_literal(component) {
    return is_tagged_list(component, "literal");
}
It is defined in terms of the function is_tagged_list, which identifies lists that begin with a designated string:
これは関数 is_tagged_list を使って定義されており、指定された文字列で始まるリストを識別します。 
function is_tagged_list(component, the_tag) {
    return is_pair(component) && head(component) === the_tag;
}
The second element of the list that results from parsing a literal expression is its actual JavaScript value. The selector for retrieving the value is literal_value.
リテラル式を解析して得られるリストの2番目の要素は、実際の JavaScript の値です。値を取り出すセレクタは literal_value です。 
function literal_value(component) {    
    return head(tail(component));
}

literal_value(parse("null;"));

null
In the rest of this section, we just list the syntax predicates and selectors, and omit their declarations if they just access the obvious list elements.
このセクションの残りでは、構文述語とセレクタを列挙するだけにとどめ、単に明白なリスト要素にアクセスするだけの宣言は省略します。

We provide a constructor for literals, which will come in handy:
リテラルのコンストラクタも用意しておきます。後で役に立ちます。 
function make_literal(value) {
    return list("literal", value);
}

Names

The tagged-list representation for names includes the tag "name" as first element and the string representing the name as second element.
名前のタグ付きリスト表現は、最初の要素としてタグ "name" を、2番目の要素として名前を表す文字列を含みます。
\[ \begin{align*} \ll\ \mathit{name}\ \gg & = \texttt{list("name", }\mathit{symbol}\texttt{)} \end{align*} \] where $symbol$ is a string that contains the characters that make up the $name$ as written in the program.
The syntax predicate for names is is_name.
名前の構文述語は is_name です。
The symbol is accessed using the selector symbol_of_name.
シンボルにアクセスするためのセレクタは symbol_of_name です。
We provide a constructor for names, to be used by operator_combination_to_application:
名前のコンストラクタも用意しておきます。 operator_combination_to_application で使用します。 
function make_name(symbol) {
    return list("name", symbol);
}

Expression statements

We do not need to distinguish between expressions and expression statements. Consequently, parse can ignore the difference between the two kinds of components:
式と式文を区別する必要はありません。したがって、parse はこの2種類のコンポーネントの違いを無視できます。
\[ \ll\ \mathit{expression}\texttt{;}\ \gg {=} \ll\ \mathit{expression}\ \gg \]

Function applications

Function applications are parsed as follows:
関数適用は次のように解析されます。
\[ \ll\ \mathit{fun}\textit{-}\mathit{expr}\texttt{(}\mathit{arg}\textit{-}\mathit{expr}_1\texttt{, }\ldots\texttt{, } \mathit{arg}\textit{-}\mathit{expr}_n \texttt{)}\ \gg \\ = \\ \texttt{list("application",} \ll\ \mathit{fun}\textit{-}\mathit{expr}\gg\texttt{, list(} \ll\ \mathit{arg}\textit{-}\mathit{expr}_1\;\gg \texttt{, }\ldots\texttt{, } \ll\ \mathit{arg}\textit{-}\mathit{expr}_n\;\gg \texttt{))} \]
We declare is_application as the syntax predicate and function_expression and arg_expressions as the selectors.
構文述語として is_application を、セレクタとして function_expression と arg_expressions を宣言します。
We add a constructor for function applications, to be used by operator_combination_to_application:
関数適用のコンストラクタも追加します。 operator_combination_to_application で使用します。 
function make_application(function_expression, argument_expressions) {
    return list("application",
                function_expression, argument_expressions);
}

Conditionals

Conditional expressions are parsed as follows:
条件式は次のように解析されます。
$\ll\ \mathit{predicate}\ \texttt{?}\ \mathit{consequent}\textit{-}\mathit{expression}\ \texttt{:}\ \mathit{alternative}\textit{-}\mathit{expression}\ \gg\ \ = $ list("conditional_expression", $\ll\ $$predicate$$\ \gg$, $\ll\ $$consequent$-$expression$$\ \gg$, $\ll\ $$alternative$-$expression$$\ \gg$)
Similarly, conditional statements are parsed as follows:
同様に、条件文は次のように解析されます。
$\ll\ \textbf{if}\ \texttt{(} \mathit{predicate} \texttt{)}\ \mathit{consequent}\textit{-}\mathit{block}\ \textbf{else}\ \mathit{alternative}\textit{-}\mathit{block}\ \gg\ \ =$ list("conditional_statement", $\ll\ $$predicate$$\ \gg$, $\ll\ $$consequent$-$block$$\ \gg$, $\ll\ $$alternative$-$block$$\ \gg$)
The syntax predicate is_conditional returns true for both kinds of conditionals, and the selectors conditional_predicate, conditional_consequent, and conditional_alternative can be applied to both kinds.
構文述語 is_conditional はどちらの種類の条件にも true を返し、セレクタ conditional_predicate、 conditional_consequent、 conditional_alternative はどちらの種類にも適用できます。

Lambda expressions

A lambda expression whose body is an expression is parsed as if the body consisted of a block containing a single return statement whose return expression is the body of the lambda expression.
本体が式であるラムダ式は、その本体が、ラムダ式の本体を return 式とする単一の return 文を含むブロックであるかのように解析されます。
\[ \ll\ \texttt{(}\mathit{name}_1\texttt{, }\ldots\texttt{, } \mathit{name}_n \texttt{) =>}\ \mathit{expression}\ \gg \\ = \\ \ll\ \texttt{(}\mathit{name}_1\texttt{, }\ldots\texttt{, } \mathit{name}_n \texttt{) => \{}\ \textbf{return} \ \mathit{expression}\texttt{;}\ \texttt{\}}\ \gg \]
A lambda expression whose body is a block is parsed as follows:
本体がブロックであるラムダ式は次のように解析されます。
$\ll\ \texttt{(}\mathit{name}_1\texttt{, }\ldots\texttt{, } \mathit{name}_n \texttt{) =>}\ \mathit{block}\ \gg\ \ =$ list("lambda_expression", list($\ll\ name_1\;\gg$, $\ldots$, $\ll\ name_n\;\gg$), $\ll\ block\ \gg$)
The syntax predicate is is_lambda_expression and the selector for the body of the lambda expression is lambda_body. The selector for the parameters, called lambda_parameter_symbols, additionally extracts the symbols from the names.
構文述語は is_lambda_expression で、ラムダ式の本体のセレクタは lambda_body です。 パラメータのセレクタ lambda_parameter_symbols は、名前からシンボルを取り出す処理も行います。 
function lambda_parameter_symbols(component) {
    return map(symbol_of_name, head(tail(component)));
}
The function function_decl_to_constant_decl needs a constructor for lambda expressions:
関数 function_decl_to_constant_decl にはラムダ式のコンストラクタが必要です。 
function make_lambda_expression(parameters, body) {
    return list("lambda_expression", parameters, body);
}

Sequences

A sequence statement packages a sequence of statements into a single statement. A sequence of statements is parsed as follows:
シーケンス文は、文のシーケンスを単一の文にまとめます。文のシーケンスは次のように解析されます。
\[ \ll\ \mathit{statement}_1 \cdots \mathit{statement}_n\;\gg \\ = \\ \texttt{list("sequence", list(} \ll\ \mathit{statement}_1\;\gg \texttt{, } \ldots \texttt{, } \ll\ \mathit{statement}_n\;\gg \texttt{))} \]
The syntax predicate is is_sequence and the selector is sequence_statements. We retrieve the first of a list of statements using first_statement and the remaining statements using rest_statements. We test whether the list is empty using the predicate is_empty_sequence and whether it contains only one element using the predicate is_last_statement.
構文述語は is_sequence で、セレクタは sequence_statements です。 文のリストの最初の要素を取得するには first_statement を、残りの文を取得するには rest_statements を使います。リストが空かどうかは述語 is_empty_sequence で、要素が1つだけかどうかは述語 is_last_statement でテストします。
[1] 
function first_statement(stmts) { return head(stmts); }

function rest_statements(stmts) { return tail(stmts); }

function is_empty_sequence(stmts) { return is_null(stmts); }

Exercise 4.8
The result of evaluating the body of a function is determined by its return statements. Following up on footnote 6 and the evaluation of declarations in section 4.1.1, this exercise addresses the question of what should be the result of evaluating a JavaScript program that consists of a sequence of statements (declarations, blocks, expression statements, and conditional statements) outside of any function body.
関数の本体を評価した結果は、その return 文によって決まります。脚注 6および4.1.1節の宣言の評価に続き、この練習問題では、文のシーケンス（宣言、ブロック、式文、条件文）からなる JavaScript プログラムを、関数の本体の外で評価した場合、その結果はどうあるべきかという問題を扱います。

For such a program, JavaScript statically distinguishes between value-producing and non-value-producing statements. (Here statically means that we can make the distinction by inspecting the program rather than by running it.) All declarations are non-value-producing, and all expression statements and conditional statements are value-producing. The value of an expression statement is the value of the expression. The value of a conditional statement is the value of the branch that gets executed, or the value undefined if that branch is not value-producing. A block is value-producing if its body (sequence of statements) is value-producing, and then its value is the value of its body. A sequence is value-producing if any of its component statements is value-producing, and then its value is the value of its last value-producing component statement. Finally, if the whole program is not value-producing, its value is the value undefined.

    1; 2; 3;

1; { if (true) {} else { 2; } }

1; const x = 2;

1; { let x = 2; { x = x + 3; } }
  2. Modify the evaluator to adhere to this specification.
このようなプログラムに対して、JavaScript は値を生成する文と値を生成しない文を静的に区別します（ここで「静的に」とは、プログラムを実行するのではなく検査することで区別できるという意味です）。すべての宣言は値を生成せず、すべての式文と条件文は値を生成します。式文の値はその式の値です。条件文の値は実行された分岐の値、またはその分岐が値を生成しない場合は undefined です。ブロックは、その本体（文のシーケンス）が値を生成する場合に値を生成し、その値は本体の値です。シーケンスは、構成する文のいずれかが値を生成する場合に値を生成し、その値は最後の値を生成する構成文の値です。最後に、プログラム全体が値を生成しない場合、その値は undefined です。
  1. この仕様に従うと、次の4つのプログラムの値は何ですか？ 
    1; 2; 3;

1; { if (true) {} else { 2; } }

1; const x = 2;

1; { let x = 2; { x = x + 3; } }
  2. この仕様に準拠するよう評価器を修正してください。
