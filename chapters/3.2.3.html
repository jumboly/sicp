3.2.3  
Frames as the Repository of Local State
ローカル状態の保管場所としてのフレーム

We can turn to the environment model to see how functions and assignment can be used to represent objects with local state. As an example, consider the withdrawal processor from section 3.1.1 created by calling the function
環境モデルを使って、 関数 と代入がどのようにローカル状態を持つオブジェクトを表現するかを見ていきましょう。例として、 節 3.1.1で次の 関数 を呼び出して作った引き出しプロセッサを考えます。 
function make_withdraw(balance) {
    return amount => {
               if (balance >= amount) {
                   balance = balance - amount;
                   return balance;
               } else {
                   return "insufficient funds";
               }
           };
}
Let us describe the evaluation of
次の式の評価を説明しましょう。
const W1 = make_withdraw(100);
followed by
続いて
W1(50);

50
Figure 3.12 shows the result of declaring the make_withdraw function in the program environment. This produces a function object that contains a pointer to the program environment. So far, this is no different from the examples we have already seen, except that the return expression in the body of the function is itself a lambda expression.
図 3.12 は、 プログラム 環境で make_withdraw 関数を宣言 した結果を示しています。これにより、 プログラム 環境へのポインタを含む 関数 オブジェクトが生成されます。ここまでは、これまで見てきた例と変わりません。ただし、 関数の本体にある return 式自体がラムダ式である点が異なります。

The interesting part of the computation happens when we apply the function make_withdraw to an argument:
計算の興味深い部分は、 関数 make_withdraw を引数に適用するときに起こります。 
const W1 = make_withdraw(100);
We begin, as usual, by setting up an environment E1 in which the parameter balance is bound to the argument 100. Within this environment, we evaluate the body of make_withdraw, namely the return statement whose return expression is a lambda expression. The evaluation of this lambda expression constructs a new function object, whose code is as specified by the lambda expression and whose environment is E1, the environment in which the lambda expression was evaluated to produce the function. The resulting function object is the value returned by the call to make_withdraw. This is bound to W1 in the program environment, since the constant declaration itself is being evaluated in the program environment. Figure 3.14 shows the resulting environment structure.
まず通常通り、パラメータ balance が引数 100 に束縛される環境 E1 を作ります。この環境の中で、 make_withdraw の本体、すなわち return 式がラムダ式である return 文を評価します。このラムダ式の評価により 、新しい 関数 オブジェクトが生成されます。そのコードは ラムダ式 で指定されたもので、環境は E1、つまり ラムダ式 が評価されて 関数 を生成した環境です。この 関数 オブジェクトが、 make_withdraw の呼び出しが返す値です。 定数宣言 自体が プログラム 環境で評価されているため、この値は プログラム 環境で W1 に束縛されます。 図 3.14 に、結果の環境構造を示します。

Now we can analyze what happens when W1 is applied to an argument:
次に、W1 を引数に適用したときに何が起こるかを分析しましょう。 
W1(50);
50
We begin by constructing a frame in which amount, the parameter of W1, is bound to the argument 50. The crucial point to observe is that this frame has as its enclosing environment not the program environment, but rather the environment E1, because this is the environment that is specified by the W1 function object. Within this new environment, we evaluate the body of the function:
まず、W1 のパラメータ amount が引数 50 に束縛されるフレームを構築します。ここで注目すべき重要な点は、このフレームの外側の環境が プログラム 環境ではなく環境 E1 であるということです。これは、W1 の 関数 オブジェクトが指定している環境が E1 だからです。この新しい環境の中で、 関数 の本体を評価します。 
if (balance >= amount) {
    balance = balance - amount;
    return balance;
} else {
    return "insufficient funds";
}
The resulting environment structure is shown in figure 3.16. The expression being evaluated references both amount and balance. The variable amount will be found in the first frame in the environment, and balance will be found by following the enclosing-environment pointer to E1.
結果の環境構造を 図 3.16 に示します。評価される式は amount と balance の両方を参照しています。 変数 amount は環境の最初のフレームで見つかり、balance は外側の環境へのポインタをたどって E1 で見つかります。

When the assignment is executed, the binding of balance in E1 is changed. At the completion of the call to W1, balance is 50, and the frame that contains balance is still pointed to by the function object W1. The frame that binds amount (in which we executed the code that changed balance) is no longer relevant, since the function call that constructed it has terminated, and there are no pointers to that frame from other parts of the environment. The next time W1 is called, this will build a new frame that binds amount and whose enclosing environment is E1. We see that E1 serves as the place that holds the local state variable for the function object W1. Figure 3.18 shows the situation after the call to W1.
代入 が実行されると、E1 における balance の束縛が変更されます。W1 の呼び出しが完了した時点で、balance は 50 になっており、balance を含むフレームは依然として 関数 オブジェクト W1 から指されています。amount を束縛するフレーム（balance を変更したコードを実行したフレーム）は、それを構築した 関数 呼び出しが終了し、環境の他の部分からそのフレームへのポインタもないため、もはや関係ありません。次に W1 が呼び出されるときには、amount を束縛する新しいフレームが構築され、その外側の環境は E1 になります。E1 が 関数 オブジェクト W1 のローカル状態変数を保持する場所として機能していることがわかります。 図 3.18 に、W1 の呼び出し後の状況を示します。

Observe what happens when we create a second withdraw object by making another call to make_withdraw:
make_withdraw をもう一度呼び出して、2番目の引き出しオブジェクトを作るとどうなるか見てみましょう。 
const W2 = make_withdraw(100);
This produces the environment structure of figure 3.20, which shows that W2 is a function object, that is, a pair with some code and an environment. The environment E2 for W2 was created by the call to make_withdraw. It contains a frame with its own local binding for balance. On the other hand, W1 and W2 have the same code: the code specified by the lambda expression in the body of make_withdraw.
これにより、 図 3.20 の環境構造が生成されます。この図は、W2 が 関数 オブジェクト、つまりコードと環境のペアであることを示しています。W2 の環境 E2 は、 make_withdraw の呼び出しによって作られたものです。この環境には、balance に対する独自のローカルな束縛を持つフレームが含まれています。一方、W1 と W2 は同じコードを持っています。それは make_withdraw の本体にある ラムダ 式で指定されたコードです。
[1]
We see here why W1 and W2 behave as independent objects. Calls to W1 reference the state variable balance stored in E1, whereas calls to W2 reference the balance stored in E2. Thus, changes to the local state of one object do not affect the other object.
ここで、W1 と W2 が独立したオブジェクトとして振る舞う理由がわかります。W1 の呼び出しは E1 に格納された状態変数 balance を参照し、W2 の呼び出しは E2 に格納された balance を参照します。したがって、一方のオブジェクトのローカル状態を変更しても、もう一方のオブジェクトには影響しません。

Exercise 3.10
In the make_withdraw function the local variable balance is created as a parameter of make_withdraw. We could also create the local state variable separately, using what we might call an immediately invoked lambda expression as follows:
make_withdraw 関数では、 ローカル変数 balance は make_withdraw のパラメータとして作られています。ローカル状態変数は、 いわゆる即時呼び出しラムダ式を使って別の方法でも 作ることができます。次のようにします。 
function make_withdraw(initial_amount) {
    return (balance => 
              amount => {
                  if (balance >= amount) {
                      balance = balance - amount;
                      return balance;
                   } else {
                      return "insufficient funds";
                   }
              })(initial_amount);
}
The outer lambda expression is invoked immediately after it is evaluated. Its only purpose is to create a local variable balance and initialize it to initial_amount.
外側のラムダ式は、評価された直後に呼び出されます。その唯一の目的は、ローカル変数 balance を作成し、 initial_amount で初期化することです。
Use the environment model to analyze this alternate version of make_withdraw, drawing figures like the ones above to illustrate the interactions
環境モデルを使って、この別バージョンの make_withdraw を分析してください。上の図のような図を描いて、次のやりとりを説明してください。 
const W1 = make_withdraw(100);

W1(50);
	
const W2 = make_withdraw(100);
Show that the two versions of make_withdraw create objects with the same behavior. How do the environment structures differ for the two versions?
2つのバージョンの make_withdraw が同じ振る舞いのオブジェクトを生成することを示してください。2つのバージョンで環境構造はどのように異なりますか？
  • Black shows the environment structure of function in exercise 3.10
  • Green shows differences in environment structure of original (where make_withdraw is replaced with the figure 3.9 version)
  • 黒は練習問題 3.10 の関数の環境構造を示しています
  • 緑はオリジナルの環境構造との違いを示しています （make_withdraw を図 3.9 のバージョンに置き換えた場合）
[1]
Whether W1 and W2 share the same physical code stored in the computer, or whether they each keep a copy of the code, is a detail of the implementation. For the interpreter we implement in chapter 4, the code is in fact shared.
W1 と W2 がコンピュータに格納された同じ物理的なコードを共有しているのか、それぞれがコードのコピーを保持しているのかは、実装の詳細です。第 4章で実装するインタプリタでは、実際にコードは共有されます。
